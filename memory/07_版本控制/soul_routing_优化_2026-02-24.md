# SOUL.md 路由规则优化 — 2026-02-24

**版本**: v2.0 → v2.1  
**执行者**: deep（subagent）  
**审核**: 待厂长确认

---

## 变更摘要

### 1. 快速决策流程重写
**之前**：「是否简单任务？」→ 主观判断，边界模糊  
**之后**：5 条量化条件全部满足才算「自己搞定」，否则按优先级匹配派发（命中即停）

具体变化：
- 「简单任务」从模糊描述改为 5 条可检查条件
- 派发逻辑从并列选择改为优先级瀑布（① main → ② logic → ③ kitt → ④ deep）
- 去掉「不确定 → 自己先处理」的模糊兜底，改为明确的 deep 兜底

### 2. 意图桶映射精确化
**之前**：只有「桶 → 场景 → 派给」三列，无触发关键词，无升级条件  
**之后**：四列表格「桶 | 触发关键词 | 默认派给 | 升级条件」

新增内容：
- 每个桶的触发关键词组合（如 S1 = 客户+靠谱/资质/ABC/分级/背调）
- 升级条件（什么情况下从默认 agent 升级到更强 agent）
- DEV1 新增双向升级：架构级 → kitt，性能优化 → logic
- SC2 新增降级：简单查询 → deep（不必每次都用 kitt）

### 3. 边界 case 处理（新增）
之前完全没有，现在明确了 4 种边界情况：
- 分不清桶 → 默认 deep
- 跨桶任务 → 拆子任务分别派发
- 厂长指定 agent → 无条件服从
- agent 失败 → 换 agent 重试一次

### 4. 外部碰撞规则细化
**之前**：三行笼统描述  
**之后**：按工具分类，每个工具明确使用场景

| 工具 | 之前 | 之后 |
|------|------|------|
| web_search | 「搜索 → web_search」 | 明确 3 类场景：查事实、查时效、快速验证 |
| web_fetch | 未提及 | 新增：已知 URL 内容提取 + Scout 规则 |
| Perplexity | 「告诉厂长用哪个 Tab」 | 明确 Tab 1/2/3 各自用途 + 调用话术模板 |
| 豆包 | 未提及 | 新增：仅用于中文润色，不用于生成/分析/推理 |
| 内部碰撞 | 未提及 | 新增：main/kitt/flash 的 spawn 场景 |

### 5. Scout 派发模板精简
**之前**：5 条派发规则（含冗余的「不需要轮询」「必要时润色」等）  
**之后**：3 行模板 + 1 句原则

模板：
```
sessions_spawn(agentId="<agent>", task="
任务：<一句话>
背景：<不超过3句>
输出要求：<格式/长度/语言>
")
```

### 6. Agent 编制表精简
**之前**：4 列（Agent/模型/擅长/spawn方式），spawn 方式是冗余信息  
**之后**：3 列（Agent/模型/一句话定位），用口语化描述
