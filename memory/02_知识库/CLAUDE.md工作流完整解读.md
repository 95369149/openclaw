## 核心理念

这是一个**复利系统**：
- 每次纠正都会被捕获为规则
- 随着时间推移，Claude 的错误率下降
- 因为它从你的反馈中学习

---

## 六大核心模块

### 1. Workflow Orchestration（工作流编排）

#### Plan Node Default（规划节点默认）
- **触发条件：** 任何非平凡任务（3+ 步骤或架构决策）
- **核心原则：**
  - 出问题立即停止并重新规划，不要硬推
  - 用规划模式做验证步骤，不只是构建
  - 提前写详细规范减少歧义

### 2. Subagent Strategy（子代理策略）

#### 核心思想
- **大量使用子代理**保持主上下文窗口干净
- **卸载任务：** 研究、探索、并行分析

#### 应用场景
- 复杂项目的模块化开发
- 并行处理多个独立任务
- 保持主会话专注于核心逻辑

### 3. Self-Improvement Loop（自我改进循环）

#### 机制
- 每次错误都记录为规则
- 规则存储在项目文件中
- 下次遇到类似情况自动应用规则

#### 实施方式
- 告诉 Claude："把这个规则存到你的文件里"
- 建立规则库（类似 Kitt 的 memory/01_强制规则/）
- 定期回顾和优化规则

### 4. Verification Before Done（完成前验证）

#### 核心原则
- 不只是构建，验证也需要规划
- 完成任务前必须验证

#### 验证清单
- 功能是否符合需求
- 代码是否通过测试
- 是否有潜在的边界情况
- 是否符合最佳实践

### 5. Autonomous Bug Fixing（自主修复 Bug）

#### 机制
- 遇到错误时自动分析原因
- 尝试修复并验证
- 如果无法修复，报告详细信息

#### 实施方式
- 建立错误分类系统
- 常见错误自动修复
- 复杂错误提供详细诊断

### 6. Core Principles（核心原则）

#### 1. 规划优先
- 复杂任务先规划，简单任务直接执行
- 规划包括验证步骤

#### 2. 上下文管理
- 保持主上下文干净
- 使用子代理处理独立任务

#### 3. 持续学习
- 从错误中学习
- 建立规则库
- 定期优化

#### 4. 验证驱动
- 完成前必须验证
- 建立验证清单

#### 5. 自主修复
- 遇到错误自动尝试修复
- 无法修复时提供详细信息

**当前问题：**

**优化方案：**
```markdown
## 规划节点触发条件
1. 任务包含 3+ 步骤
2. 涉及架构决策
3. 需要修改多个文件
4. 涉及外部系统集成
5. 用户明确要求规划

## 规划模板
1. 任务目标
2. 执行步骤（详细）
3. 验证清单
4. 潜在风险
5. 回滚方案

#### 2. 自我改进循环
**当前问题：**
- 规则更新依赖手动操作

**优化方案：**
- 自动捕获错误和纠正

- 定期回顾和优化

#### 3. 验证清单
**当前问题：**
- 缺少系统化的验证流程

**优化方案：**

- [ ] 功能符合需求
- [ ] 边界情况处理
- [ ] 错误处理完善

### 代码质量
- [ ] 代码格式正确
- [ ] 无语法错误
- [ ] 符合最佳实践

### 测试验证
- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 手动测试通过

### 文档验证
- [ ] 代码注释完整
- [ ] 文档更新
- [ ] 变更日志记录
```

#### 4. 自主修复机制
**当前问题：**
- 遇到错误时缺少自动修复机制

**优化方案：**
- 建立错误分类系统

- 复杂错误提供详细诊断

## 总结

**CLAUDE.md 的核心价值：**
1. **复利系统：** 越用越聪明
2. **系统化：** 不依赖记忆，依赖规则
3. **可扩展：** 规则库持续增长
4. **可验证：** 每个步骤都有验证

**对 Kitt 的意义：**
- 从"被动执行"到"主动优化"
- 从"依赖记忆"到"依赖规则"
- 从"单次任务"到"持续进化"
