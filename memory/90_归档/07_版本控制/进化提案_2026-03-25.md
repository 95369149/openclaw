# 进化提案｜2026-03-25

## 厂长周报摘要

本周外部侦察里，真正有价值的不是“新模型又多强”，而是三条更落地的趋势：

1. **Context engineering 已从 prompt 技巧升级为系统工程**。最新实践普遍收敛到“最近上下文保留原文 + 更早历史做摘要压缩 + 按需激活技能/资料”的混合路线，核心目标是只把高信号 token 放进窗口，减少 lost-in-the-middle。
2. **多 Agent 记忆问题正在被当成“计算机体系结构问题”来解决**。外部最新文章明确提出：Agent 系统需要区分 I/O 层、Cache 层、Memory 层，还要补上版本控制、访问协议、冲突处理，否则共享记忆一多，系统就会出现脏读、覆盖、重复计算和语义冲突。
3. **OpenClaw 生态讨论重点正转向可治理性**。外部文章把 smart pruning、sandbox 多后端、secrets workflow、人类在环、插件/能力模块化当成升级重点，说明社区关注点已从“能不能跑”转为“能不能长期稳定跑”。

对我们自己的启发很直接：Kitt/Lyra 这套系统当前优势在“记忆外置、规则明确、人工守门”，短板在“Scout 自动侦察质量不稳定、共享记忆缺少版本语义、上下文卫生规则虽有但未完全产品化”。所以本周最值得做的不是继续堆 Agent，而是先补三件基础设施：**修复 Scout 真搜索、建立结构化 facts/skills 记忆提炼、给 shared/ops 记忆加版本与冲突治理**。这样后面再去 Perplexity 做高级模型深碰撞，输入材料才值得花钱。

## 进化提案

### P0（本周必须做）

1. **修复 evolution_scout.py 真实侦察输出**
   - 问题：当前脚本仍返回“示例发现 / 待实现：真实搜索结果”，导致 weekly evolution 失真。
   - 动作：接入真实 web_search 结果解析；输出统一 schema（title/url/source/why_it_matters/suggested_action）；失败时明确降级说明，而不是写假结果。
   - 验收：下周报告中至少有 3 条真实来源、可点击 URL、非示例内容。

2. **建立记忆三层治理：I/O → Cache → Memory**
   - I/O：外链原文、工具结果、临时观察。
   - Cache：本轮摘要、活跃任务上下文、最近错误轨迹。
   - Memory：长期 facts、决策、SOP、已验证经验。
   - 动作：明确哪些内容只能短存，哪些必须提炼后入库；shared/ 不再默认等于长期记忆。

3. **给 shared/ops 记忆加版本和冲突规则**
   - 动作：新增最小元数据：`source_agent`、`created_at`、`supersedes`、`confidence`、`status`。
   - 场景：多个 agent 同时写同一主题时，必须能知道哪个版本最新、哪个只是草稿、哪个已被覆盖。

### P1（下周推进）

1. **做 context hygiene 规则产品化**
   - 保留最近 N 轮原文；更早历史摘要压缩；错误轨迹不压掉；低价值工具输出自动裁剪。
   - 目标：减少长会话退化、降低 token 成本。

2. **做 facts/skills 双层提炼**
   - facts：稳定事实、偏好、组织规则。
   - skills：可复用流程、脚本、动作模板。
   - 目标：把“做过一次”变成“下次自动更稳”。

3. **建立 weekly evolution 的 Perplexity 预碰撞包**
   - 每周自动产出：top findings + open questions + suggested prompts。
   - 让 jimmy 手动去做高价值多轮碰撞，而不是从零开始。

### P2（观察项）

1. 技能/能力模块的激活治理：避免 skill 数量增长后误触发。
2. Sandbox/执行环境分级：本地镜像、远端、只读模式按风险切换。
3. Secrets 与配置治理继续收口：减少明文、减少散落配置。

## 本周最值得关注的 5 条外部内容

1. OpenClaw 2026.3 advanced practices：强调 smart pruning、sandbox 多后端、secrets workflow、人类在环与模块化能力拆分。
2. State of Context Engineering in 2026：行业主流已收敛到 progressive disclosure + sliding window + summarisation hybrid。
3. Multi-agent memory as computer architecture：共享记忆不是“加个向量库”就完，需要层级、协议、版本与一致性。
4. MachineLearningMastery 关于 agent memory 的系统化讨论：记忆已被视为可靠性设计问题，而非单纯大上下文问题。
5. 外部 OpenClaw 讨论逐步把重点转向安全、迁移、运维可控性，而非炫技 demo。
