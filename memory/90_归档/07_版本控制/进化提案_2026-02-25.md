## 发现的问题

### 问题 1：派任务后不跟进
**描述**：
- 昨晚 23:18-23:39 派了 3 个任务给 deep
- 之后完全没跟进，任务显示 "running" 7 小时无人管
- 直到厂长问"都干了啥"才去检查

**影响**：
- 任务 001 完成了但状态没更新（浪费资源重复检查）
- 任务 002/003 可能早就挂了，无人知晓（浪费时间）
- 厂长无法掌握进度，信任度下降

**证据**：
- `task-board.json` 显示 3 个任务 startedAt 昨晚，status 仍为 "running"
- `subagents list` 显示 0 个活跃 agent（早就跑完或崩了）
- 任务 001 的输出文件时间戳是 23:20，但任务板未更新

### 问题 2：心跳流于形式
**描述**：
- HEARTBEAT.md 写了"检查任务是否超过 30 分钟"
- 但我只会读文件、报警，从不主动处理
- 报了 3 次"任务卡住告警"，但没有任何行动

**影响**：
- 心跳变成"读文件 → 报警 → HEARTBEAT_OK"的机械循环
- 异常发现了但不解决，等于没发现
- 厂长还得手动介入，失去了自动化的意义

**证据**：
- 4:03、4:58、5:44、6:39 四次心跳都报了同样的警告
- 但任务板状态没变、agent 没被终止、也没重启任务

### 问题 3：缺少任务验收机制
**描述**：
- 派任务时没有设置验收标准
- 任务完成后不检查输出质量
- 不更新任务板状态

**影响**：
- 任务 001 完成了，但我不知道
- 任务 002/003 可能有部分产物，但我没去找
- 任务板成了"只写不读"的摆设

**证据**：
- 任务 001 的 `completionCriteria` 全是 false，但实际已完成
- 我是通过手动 `ls` 才发现输出文件的

## 优化建议

### 建议 1：建立任务生命周期管理
**方案**：
1. **派任务时**：
   - 记录预期完成时间（默认 30 分钟）
   - 设置检查点（10 分钟、20 分钟、30 分钟）
   - 明确验收标准（输出文件路径、关键指标）

2. **运行中**：
   - 每次心跳检查任务是否超时
   - 超时 → 检查 agent 是否还活着（`subagents list`）
   - 如果 agent 已消失 → 检查输出文件，判断是完成还是崩溃

3. **完成后**：
   - 验收输出文件（存在性、大小、内容关键词）
   - 更新任务板状态（done/failed）
   - 记录到日志

**预期收益**：
- 任务完成率可追踪
- 异常任务自动发现并处理
- 厂长随时知道进度

**实施难度**：中  
**风险等级**：低

### 建议 2：心跳增加执行力
**方案**：
修改 HEARTBEAT.md，从"检查 + 报警"改为"检查 + 处理"：

```markdown
### 4. 子 Agent 任务监控
检查 `memory/task-board.json` 中的活跃任务：
- 读取 `activeTasks` 数组
- 检查是否有任务运行超过 30 分钟
  - 是 → 检查 agent 是否还活着（subagents list）
  - agent 已消失 → 检查输出文件，更新任务状态
  - agent 还在但无进展 → 通知厂长，建议终止
- 检查是否有任务需要重试（retries < maxRetries）
  - 是 → 自动重启任务
```

**预期收益**：
- 心跳从"传声筒"变成"执行者"
- 异常自动处理，减少人工介入
- 任务板状态实时准确

**实施难度**：低  
**风险等级**：低

### 建议 3：任务板增加时间戳字段
**方案**：
在 `task-board.json` 的任务对象中增加：
- `expectedDuration`: 预期耗时（分钟）
- `lastCheckedAt`: 最后检查时间
- `checkpoints`: 检查点列表（10min、20min、30min）

**预期收益**：
- 更精确的超时判断
- 避免重复检查
- 可追溯任务历史

**实施难度**：低  
**风险等级**：低

### 建议 4：建立任务模板
**方案**：
创建 `memory/templates/task-template.json`：
```json
{
  "id": "自动生成",
  "title": "任务标题",
  "agent": "deep/main/logic/kitt",
  "sessionKey": "派发后填写",
  "status": "pending",
  "startedAt": "派发时填写",
  "expectedDuration": 30,
  "description": "任务描述",
  "subtasks": [],
  "completionCriteria": {
    "outputFiles": ["必须产出的文件路径"],
    "keywords": ["输出文件中必须包含的关键词"],
    "minSize": 1024
  },
  "retries": 0,
  "maxRetries": 3
}
```

**预期收益**：
- 派任务时不会漏填字段
- 验收标准明确
- 任务板结构统一

**实施难度**：低  
**风险等级**：低
