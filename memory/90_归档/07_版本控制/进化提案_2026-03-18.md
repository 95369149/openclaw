# 进化提案｜2026-03-18

## 厂长周报摘要
本周 Scout 结果偏少，侦察脚本当前仍停留在示例输出阶段，只返回 1 条占位发现，说明自动外部侦察链路本身就是当前第一优先级问题。补充外链学习后，有三条真正有价值的新信号：
1. **Microsoft PlugMem**：提出把原始交互日志转成“事实+技能”的结构化知识，而不是继续往上下文里塞长文本；重点是“按决策相关性供给知识”，还能降低 token 消耗。
2. **Context Engineering 最佳实践**：近期文章普遍强调，问题往往不在模型本身，而在“给了什么上下文、何时给、以什么形态给”；高频建议包括工具瘦身、上下文裁剪、阶段性摘要、外置记忆与老化清理。
3. **OpenClaw 安全与治理讨论升温**：外部内容大量聚焦 skill 供应链风险、默认暴露面、权限治理，说明 OpenClaw 生态正在从“能跑”转向“可控、可审计、可长期运维”。

对我们系统的启发很直接：
- **OpenClaw**：该补的是“自动侦察质量”和“安全治理可视化”，不是继续堆新功能。
- **Lyra/提示词层**：要进一步从 prompt engineering 升级到 context engineering，把摘要、裁剪、记忆注入做成标准流水线。
- **记忆系统**：QMD 已有基础，但还缺一层“从日志提炼为可复用知识单元”的结构化记忆层；否则 memory 会越积越多、越搜越吵。

结论：本周最值得做的不是再碰高级模型，而是先把 Scout 输出质量、记忆提炼机制、上下文治理规则补齐。等这三块稳住，再去 Perplexity 做多轮深度碰撞，投入产出比才高。

## 进化提案

### P0（立即做）
1. **修复 evolution_scout.py，从示例发现升级为真实发现**
   - 目标：输出至少 3 条真实链接 + 摘要 + 来源 + 时间。
   - 做法：把当前占位 `example.com` 结果替换为真实搜索/抓取流程，并增加“无结果/超时/重复链接”处理。
   - 价值：没有真实 Scout，后续所有碰撞都建立在空气上。

2. **给记忆系统增加“事实/技能”双层提炼机制**
   - 目标：不再只存原文摘要，而是拆成 `事实（facts）`、`策略（skills）`、`适用场景（when to use）`。
   - 做法：在 daily/weekly 学习流水线后新增一步，将高价值发现转写为结构化块，供后续检索优先命中。
   - 价值：降低长上下文噪声，贴近 PlugMem 思路。

3. **建立上下文卫生规则（Context Hygiene）**
   - 目标：让摘要、裁剪、注入、淘汰有统一标准。
   - 做法：明确哪些内容进 system memory，哪些只留 shared，哪些 7 天后降级归档；为 weeklyEvolution 增加“recency + reuse”字段。
   - 价值：防止 memory 越用越脏、任务越做越飘。

3. **做一个“待深度碰撞队列”**：把值得后续 Perplexity 深挖的话题单独列出，避免下次从零开始。
