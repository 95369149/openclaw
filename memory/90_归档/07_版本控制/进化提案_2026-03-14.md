## 🎯 进化提案（P0/P1/P2 分级）

### P0（立即执行，影响核心稳定性）

#### P0-1：Manifest 落地确定性执行器
**问题**：子 Agent 写文件成功率 <30%，JSON 解析失败频繁
**方案**：
1. 创建 Python 脚本 `bin/apply_manifest.py`
2. 输入：manifest JSON 文件路径
3. 输出：`{"ok": true/false, "files": [...], "errors": [...]}`
4. Jimmy 收到子 Agent 返回后：
   - 保存原样输出到 `memory/tmp/agent_manifest.json`
   - 调用 `apply_manifest.py` 执行落地
   - 成功 → 汇报摘要；失败 → 一次修复重试
5. 防污染：Jimmy 上下文只保留摘要，不复述完整内容

**预期收益**：
- 文件落地成功率 >95%
- 减少 Jimmy 上下文污染
- 可追溯的执行日志

**工作量**：2 小时（含测试）

---

#### P0-2：上下文压缩后强制读记忆
**问题**：2026-02-26 教训，Kitt 压缩后没读记忆，用旧数据改坏配置
**方案**：
1. 在 `SOUL.md` 第零号铁律中明确：
   ```
   每次醒来/压缩后，先读记忆再说话。不读完不许回复任何消息。
   1. read memory/.abstract
   2. read memory/task-board.json
   3. read memory/2026-MM-DD.md（不存在读昨天）
   4. session_status
   ```
2. 违反后果：厂长会杀了你（不是比喻）

**预期收益**：
- 杜绝"用过时信息操作"的灾难
- 保证每次醒来都是最新状态

**工作量**：已完成（本次更新 SOUL.md）

### P1（本月内完成，提升效率）

#### P1-1：Context Quality Score（上下文质量评分）
**灵感来源**：Context Engineering 最佳实践
**方案**：
1. 为每次子 Agent 派发任务打分（0-100）
2. 评分维度：
   - 任务描述清晰度（30 分）
   - 背景信息完整度（20 分）
   - 输出要求明确度（30 分）
   - 前置读取是否执行（20 分）
3. 低于 60 分 → 自动补充上下文后再派发
4. 记录到 `memory/logs/context_quality.jsonl`

**预期收益**：
- 子 Agent 成功率提升 20-30%
- 减少"理解偏差"导致的重做

**工作量**：4 小时

---

#### P1-2：热数据/冷数据分层（Letta 启发）
**灵感来源**：AI Agent Memory 分层架构
**方案**：
1. `memory/hot/`：最近 7 天的高频访问文件（自动迁移）
2. `memory/cold/`：30 天以上未访问的归档文件
3. QMD 搜索优先查 `hot/`，未命中再查 `cold/`
4. 每周日凌晨 3 点自动整理（cron）

**预期收益**：
- 搜索速度提升 40-60%
- 减少无效上下文加载

**工作量**：6 小时

---

#### P1-3：业务流程自动化模板库
**灵感来源**：OpenClaw 21 个实战自动化
