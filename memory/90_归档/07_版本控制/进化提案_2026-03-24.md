### 1. 单 Agent 长时任务比多 Agent 协同更可靠（Anthropic 研究）

来源：@AnthropicAI 今日推文（Claude Opus 4.5 早期宇宙物理建模）

核心发现：Anthropic 发现"把工作拆给多个 Agent 并不适合所有问题"——特别是**错误会累积的任务**，单个 Agent 顺序执行反而更稳。这与我们当前的"多 Agent 协同"架构形成对比。

**对红太阳的启示**：
- 振动刀参数推荐、询盘回复、报价生成这类**有明确对错的任务**，不要强行走多 Agent 流水线——一个 deep/kitt 处理到底更可靠
- 多 Agent 适合**并行且独立**的任务（如同时做内容+拓客）
- 当前 T-146（微信ClawBot询盘自动回复）应设计成**单 Agent 闭环**，不要引入过多 Agent 跳转导致错误累积

### 2. Obsidian 多 Agent 系统：8 个 Agent 精细分工（@qingq77）

来源：[My Brain Is Full - Crew](https://github.com/gnekt/My-Brain-Is-Full-Crew)，8 个 Agent 分工：记笔记、清 inbox、搜知识、找连接、转录会议、盯邮件和日历

**对红太阳的启示**：
- 我们的 4 员编制中，"知识管理"这个角色是缺失的——`学习摄取 cron` 在做，但没有专门负责"知识连接"的角色
- 厂长的销售知识库（T-124）可以借鉴这个模式：记录案例（deep）→ 找连接（kitt）→ 形成可查询知识资产
- 关键洞察：`记笔记 ≠ 建知识库`，缺的是**找连接**这一步

### 3. Seedance 2.0 适合国风/短平快素材（@msjiaozhu 实测）

核心：Seedance 2.0 当做"素材生成器"用（不触发审核），而不是"完整视频生成器"用
