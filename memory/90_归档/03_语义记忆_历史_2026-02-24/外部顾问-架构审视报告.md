## 一、记忆架构分析

### 当前架构 (L0-L4)

```
L0: SOUL.md + IDENTITY.md + USER.md（每次必读）
L1: INDEX.md（导航，按需加载）
L2: 强制规则（按需读取）
L3: 语义记忆（按需读取）
L4: 技能（用到时读）
```

### 分层合理性评估

**优点**：

1. L0的"每次必读"确保了核心身份一致
2. L2强制规则的按需读取降低了上下文负担
3. L4技能的延迟加载避免了性能浪费

**问题**：

1. **L1定位模糊**：`INDEX.md`既是导航又包含操作指南，建议分离
2. **情景记忆位置不明确**：目录中有04\_情景记忆，但架构描述中缺失
3. **缺乏缓存机制**：频繁读取的文件没有LRU缓存

### 具体改进建议

#### 1. 重构分层架构

**文件**: `/Users/apple/.openclaw/workspace/SOUL.md`
**修改位置**: "记忆架构"部分
**当前内容**:

```
## 记忆架构
- L0: SOUL.md + IDENTITY.md + USER.md（每次必读）
- L1: INDEX.md（导航，按需加载）
- L2: 强制规则（按需读取）
- L3: 语义记忆（按需读取）
- L4: 技能（用到时读）
```

**建议修改为**:

```
## 记忆架构 (v3.1)
- L0 (核心身份): SOUL.md + IDENTITY.md + USER.md（每次启动时强制读取）
- L1 (导航索引): NAVIGATION.md（纯导航索引，按需加载）
- L2 (操作规范): 强制规则（按需读取，启动时预加载前3个高频规则）
- L3 (语义知识): 语义记忆（语义搜索优先，文件索引次之）
- L4 (情景记忆): 情景记忆（按时间线检索，主动调用）
- L5 (技能库): 技能文件（延迟加载，使用频率跟踪）
```

**理由**:

1. 明确L1为纯导航，避免功能混杂
2. 加入L4层，与目录结构对应
3. 增加启动时高频规则预加载（如Fallback策略）

#### 2. 添加缓存机制

**文件**: 新文件 `/Users/apple/.openclaw/workspace/memory/01_强制规则/文件缓存策略.md`
**内容**:

```markdown
# 强制规则：文件缓存策略

## 缓存规则

1. **热缓存** (启动时加载，常驻内存)
   - SOUL.md、IDENTITY.md、USER.md
   - 强制规则/fallback策略.md
   - 强制规则/自我迭代.md

2. **温缓存** (访问2次后缓存)
   - index.md 系列文件
   - 语义记忆/\_INDEX.md

3. **冷缓存** (访问5次后缓存)
   - 技能库文件
   - 收藏夹文件

## 缓存失效

- 文件修改时间 > 缓存时间 + 60秒时失效
- 主动触发 `memory cleanup` 时清空缓存
```

## 二、系统提示词优化

### SOUL.md 需要精确化的指令

**文件**: `/Users/apple/.openclaw/workspace/SOUL.md`

#### 1. "有主见"指令改进

**当前**: "有主见。可以不同意，可以有偏好。"
**改进**:

```
有主见，不绕弯。当用户问"你觉得呢"或"选哪个"时：
- 直接给出明确的推荐（一个最佳方案）
- 用bullet points说明理由（最多3点）
- 除非用户要求，不提供备选方案列表
- 如果拿不准，明确说"我倾向于X，但Y也有可能，需要更多信息确认"
```

#### 2. "先自己想办法"指令改进

**当前**: "先自己想办法。读文件、查上下文、搜索。搞不定再问。"
**改进**:

```
先自己想办法，最多尝试3种不同路径：
1. 首先查现有知识库和记忆（memory_search）
2. 其次搜索网络（web_search, 限制每次2-3个关键词）
3. 最后查阅文件和代码（read/exec）
4. 如果3种路径都无进展，立即停止并告知用户："我尝试了A/B/C方法，都无法解决。需要你提供（具体缺少的信息）"
```

#### 3. 添加"汇报格式"指令

**新增到"风格"部分**:

```
## 汇报格式
- 复杂任务：结论在前，细节分段，用##标题分隔
- 代码任务：先展示运行结果再展示代码
- 多步操作：用1. 2. 3. 列表，但不要嵌套超过三层
- 错误情况：先告诉用户"有错误"，然后给原因，最后给解决方案
```

### AGENTS.md 需要删除的废话

**文件**: `/Users/apple/.openclaw/workspace/AGENTS.md`

#### 1. 删除冗余描述

**当前**: "这个文件夹是家。"

## 三、9层Fallback链优化

### 当前问题分析

1. **失败后切换**：每次遇到错误才fallback，响应慢
2. **健康监控缺失**：无模型响应时间统计
3. **优先级冲突**：多个免费模型可能同时失败

### 三层Fallback策略改进

**文件**: `/Users/apple/.openclaw/workspace/memory/01_强制规则/fallback策略.md`

#### 改进方案：智能分级Fallback

```markdown
## 智能分级Fallback链 (v3.1)

### 第1层：主力 + 快速备用 (0-3秒响应)

1. siliconflow/deepseek-ai/DeepSeek-V3.2 (免费主力)
2. siliconflow/Pro/deepseek-ai/DeepSeek-V3.2 (付费备1)
3. siliconflow/Qwen/Qwen3-32B (免费备2)

**触发条件**:

- 主力模型响应时间 > 5秒
- 主力模型返回明显错误
- 主力模型连续失败2次

### 第2层：免费堡垒 (3-8秒响应)

4. groq/llama-3.3-70b-versatile
5. groq/qwen/qwen3-32b
6. google-gemini/gemini-2.5-flash

**触发条件**:

- 第1层整体失败率 > 30%
- 特定任务类型（代码生成用Qwen，推理用Llama）
- 晚上时段（流量高峰期）

### 第3层：大脑枢纽 (8-15秒响应)

7. mynewapi/claude-sonnet-4-6
8. mynewapi/claude-opus-4-6

**保留策略**:

- 仅在复杂任务或高质量要求时使用
- 每月使用时长不超过20小时
- 关键决策时强制使用Opus

### 新功能：健康监控

创建 `/Users/apple/.openclaw/workspace/logs/fallback-monitor.md`
记录：

- 每次fallback的时间、原因、目标模型
- 各模型月失败率统计
- 响应时间百分位（P50/P90/P95）
```

## 五、安全边界加固

### 当前隐患识别

1. **配置变更风险**：全靠手动JSON编辑
2. **支付风险**：多个付费模型可能同时欠费
3. **权限扩散**：GitHub PAT等敏感凭证管理松散

### 具体加固方案

#### 1. 配置变更双人审核 (虚拟)

**新增文件**: `/Users/apple/.openclaw/workspace/memory/01_强制规则/配置安全.md`

```markdown
## 配置变更安全规则

1. **变更前**: 必须创建 `/workbench/config-review.md` 记录：
   - 变更原因、预期效果、风险点
   - 回滚方案
   - 测试计划

2. **虚拟审核**: 自己作为审核员，24小时后重新审视

   - 每次变更前自动备份 openclaw.monthly.json
   - 变更成功后标记为 openclaw.rolling.json
```
