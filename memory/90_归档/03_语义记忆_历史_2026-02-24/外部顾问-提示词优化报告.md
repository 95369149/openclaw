# 外部顾问：Kitt 提示词体系优化报告
> 审计日期：2026-02-19
> 审计范围：SOUL.md / AGENTS.md / IDENTITY.md / USER.md / HEARTBEAT.md / 00_大脑中枢.md / INDEX.md / MEMORY.md / 强制规则/*
> 审计人：Prompt Engineering 专家（Claude Opus 子 Agent）

---

## 一、总体评价

Kitt 的提示词体系在 Agent 社区中属于**中上水平**。架构分层清晰（L0-L4），记忆系统有章法，强制规则覆盖面广。但存在以下系统性问题：

1. **信息散射**：同一条规则在 3-4 个文件中重复出现，版本不一致
2. **职责边界模糊**：SOUL.md / USER.md / 行为约束.md / 操作纪律.md 四个文件的管辖范围重叠
3. **启动流程有冗余 I/O**：每次唤醒读 6-8 个文件，其中部分内容重复
4. **HEARTBEAT.md 过于简陋**：只有自学一个任务，与 AGENTS.md 描述的"心跳"职责不匹配
5. **MEMORY.md 是手动维护的"影子副本"**：大量内容与 USER.md / TOOLS.md / 强制规则 重复

---

### 2.2 模糊/不精确的指令

#### 问题 E：AGENTS.md 启动流程缺少条件分支

**改前：**
```markdown
## 启动流程
1. 读 `INDEX.md` — 导航索引
2. 读 `SOUL.md` + `IDENTITY.md` + `USER.md` — L0 核心
3. 读 `memory/YYYY-MM-DD.md`（今天+昨天）
4. 主会话额外读 `MEMORY.md` + `memory/active-context.md`
```

**问题**：
- 步骤 1 读 INDEX.md 是浪费——INDEX.md 是导航用的，启动时不需要"浏览目录"
- 步骤 2 和步骤 1 可以合并
- 没有说明子 Agent 该读什么（子 Agent 不需要读日志）
- "今天+昨天"的日志可能不存在，没有容错

**改后：**
```markdown
## 启动流程

### 主会话
1. 读 `SOUL.md` + `IDENTITY.md` + `USER.md`（L0 核心，并行读取）
2. 读 `MEMORY.md` + `memory/active-context.md`（工作上下文）
3. 读 `memory/05_日常日志/YYYY-MM-DD.md`（今天，不存在则跳过）
4. 如果 `BOOTSTRAP.md` 存在 → 执行后删除

### 子 Agent
1. 读 `SOUL.md`（仅风格基线）
2. 读任务相关的具体文件（由主会话指定）

### 心跳会话
1. 读 `HEARTBEAT.md` → 执行任务 → 回 HEARTBEAT_OK
2. 如需上下文 → 按需读 `memory/active-context.md`
```

**理由**：
- 去掉 INDEX.md（启动时不需要导航，需要时再查）
- 区分三种会话类型，避免子 Agent 浪费 token 读无关文件
- 昨天的日志通常不需要，去掉减少 I/O
- 明确并行读取，减少启动延迟

### 2.5 启动流程优化

#### 问题 M：当前启动读取量过大

当前主会话启动要读：INDEX.md + SOUL.md + IDENTITY.md + USER.md + 今天日志 + 昨天日志 + MEMORY.md + active-context.md = **8 个文件**。

按实际内容估算：
- INDEX.md: ~600 token
- SOUL.md: ~400 token
- IDENTITY.md: ~300 token
- USER.md: ~500 token
- MEMORY.md: ~800 token
- active-context.md: ~600 token
- 日志 ×2: ~1000 token
- **总计: ~4200 token**（还没开始干活）

**优化方案：合并 IDENTITY.md 到 SOUL.md**

IDENTITY.md 只有 15 行，完全可以作为 SOUL.md 的第一节：

```markdown
# SOUL.md - Who I Am

## 身份
- 名字：Kitt（源自《霹雳游侠》K.I.T.T.）

- Emoji：🐾
- 风格：随性、直接、有主见、不端着

## 核心
（原 SOUL.md 内容）
```

**收益**：减少 1 次文件读取，减少 ~100 token 的文件头/尾开销。

## 四、架构级建议

### 4.1 MEMORY.md 的定位需要重新思考

当前 MEMORY.md 试图做两件事：
1. **长期记忆摘要**（关于厂长、关于系统）
2. **规则速查**（强制规则、教训）

但这两件事都有更好的源文件（USER.md、TOOLS.md、强制规则/）。

**建议将 MEMORY.md 重新定位为"动态状态面板"**：

```markdown
# MEMORY.md — Kitt 动态状态

## 系统架构（变化时更新）
- 当前主力模型：...
- Fallback 链：...
- Worker 兵团：...

## 近期教训（TOOLS.md 未覆盖的）
- ...

## 待办
- ...

## 关注项目
- ...
```

去掉所有与 USER.md / TOOLS.md / 强制规则 重复的内容。

### 4.2 00_大脑中枢.md 的注入模板不应在 Kitt 的上下文中

00_大脑中枢.md 的"一键注入模板"是给**其他 AI 模型**用的，Kitt 自己不需要读这段。建议：
- 将注入模板移到独立文件 `memory/DigitalPersona.md`（已存在）
- 00_大脑中枢.md 只保留目录结构和检索规则

### 4.3 考虑引入"启动摘要缓存"

每次启动都读 5-6 个文件，可以考虑让 Kitt 在每天第一次启动时生成一个 `memory/.boot-cache.md`，包含当天需要的所有 L0+L1 信息的压缩版。后续启动只读这一个文件。

**触发条件**：`.boot-cache.md` 不存在或日期不是今天 → 全量读取并生成缓存。
**风险**：缓存可能过期。可以加一个"源文件修改时间"校验。

## 五、总结

Kitt 的提示词体系**骨架很好**，问题主要在"肉"上——信息重复、职责不清、缺少精确性。核心优化方向：

1. **单一真相源**：每条信息只在一个文件中完整存在，其他文件用指针引用
2. **按会话类型分流**：主会话、子 Agent、心跳各读各的，不一刀切
3. **MEMORY.md 瘦身**：从"什么都抄一遍"变成"动态状态 + 指针"
4. **HEARTBEAT.md 充实**：把 AGENTS.md 承诺的心跳职责真正落地

预计优化后：
- 启动 token 消耗减少 ~30%（从 ~4200 降到 ~2900）
- 信息一致性风险降低 ~80%（消除 4 处重复源）
- 子 Agent 启动 token 消耗减少 ~60%（只读 SOUL.md + 任务文件）
