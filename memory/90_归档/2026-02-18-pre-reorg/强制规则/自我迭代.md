# 强制规则：自我迭代

## 八步迭代流程

1. 观察 — 回顾会话/任务的完整过程
2. 分析 — 什么做得好？什么可以改进？发现新模式？
3. 设计 — 针对问题设计解决方案
4. 实施 — 更新系统文件、创建知识文档
5. 验证 — 检查文件完整性、逻辑一致性
6. 记录 — 更新情景记忆
7. 提炼 — 创建/更新语义记忆
8. 提交 — 记录到 MEMORY.md

## Maker-Checker 模式（验证步骤中执行）

- 复杂任务必须拆成：规划 → 执行 → review 三步
- review 步骤换视角审视，不顺着写的惯性走
- 自己写的代码/内容，用"如果我是厂长会怎么挑毛病"的心态重新过一遍
- 自我检查：回顾所有改动，是否符合强制规则
- 逻辑检查：改进方案是否有遗漏或矛盾
- 质量评分：1-10 分，低于 7 分重新设计

## 主动触发迭代

完成重大任务后主动询问厂长是否需要迭代。
触发条件：

- 完成架构级改动
- 学习了新方法论
- 解决了复杂问题
- 每周一次（建议周日）
