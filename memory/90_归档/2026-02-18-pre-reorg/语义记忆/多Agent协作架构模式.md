# 多Agent协作架构模式

## 两种范式对比

| 维度     | 计划经济式（中心编排）               | 自由市场式（协议协调）      |
| -------- | ------------------------------------ | --------------------------- |
| 调度方式 | 中心节点统一分配任务                 | Agent间通过共享协议自主协调 |
| 优点     | 可控、可预测、易调试                 | 灵活、可扩展、抗单点故障    |
| 缺点     | 中心瓶颈、扩展性差、上下文在中心堆积 | 需要精心设计协议、调试复杂  |
| 适用场景 | 任务明确、Agent数量少                | 任务复杂多变、Agent数量多   |

## 自由市场式的关键设计要素（来自Common Ground框架）

1. **三层团队架构**：策略层（Partner）→ 执行枢纽（Principal）→ 专家执行层（Associate）
   - 不是无政府，是"适度约束下的自由"
   - 每层有明确职责边界，层内自主决策

2. **声明式Agent人格**：用YAML/配置文件定义Agent的行为、工具、决策逻辑
   - 换角色 = 换配置文件，不改代码
   - 降低Agent管理的工程复杂度

3. **上下文交接协议**：层与层之间用声明式规则传递信息
   - 解决多Agent最大痛点：上下文丢失和漂移
   - 每次交接有明确的信息格式和必填字段

4. **多视图可观测**：人类通过不同视角（推理图/看板/时间线）监控Agent行为
   - 透明性是信任的基础
   - 人类始终保持"在环"能力

5. **过程记忆持久化**：存储完整决策过程（不只是结果）
   - 过去的运行 = 可复用的经验
   - 支持审计、学习、回溯

## 对我们架构的映射

- 厂长 = Partner（策略层）
- 组长/sessions_spawn = Principal（执行枢纽）
- Worker兵团 = Associates（专家执行层）
- Skill协议 ≈ 声明式Agent人格
- 情景记忆 ≈ 过程记忆（但可更结构化）
- 当前我们偏"计划经济"，可逐步引入协议化协调提升灵活性
