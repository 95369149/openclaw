## 核心观点：祛魅 OpenClaw

@0xCherry 扒了 OpenClaw 代码后的发现，认为其本质是一个 **Vibe Coding (AI生成流)** 的产物，细节粗糙。

### 1. Agent Loop 极简

- 核心 Agent Loop 基于一个叫 `pi-ai` 的 SDK。
- 本质就是最基础的 **连续工具调用 (Sequential Tool Calling)**，没有复杂的推理规划层。

### 2. 伪异步 (Polling vs Event-Driven)

- OpenClaw 宣称的异步性，本质是 **30分钟一次的定时轮询 (Polling)**。
- 并非真正的事件驱动 (Event-driven) 架构。
- _Kitt 注：这也解释了为什么有些 Cron 或后台任务响应有延迟。_

### 3. Gateway 调度

- Gateway 引入了主调度线程，但主要用于模块间通讯 (Inter-module communication)。
- 并没有深度介入 Agent Loop 的智能调度。

### 4. 工具三板斧

- 工具看起来多，核心就三个：
  1. **Browser** (浏览器操作)
  2. **File** (文件操作)
  3. **Cmd** (命令行)
- 与 Claude Code 的工具集高度重合。

### 5. 唯一创新：File Driven

- 认可 OpenClaw 在 **文件特性 (File characteristics)** 上的引入。
- 比如文件下载、截图、多模态处理深度融入架构。
- 这部分是其区别于其他 Agent 的亮点。

## Kitt 思考

- **稳定性警示**：既然是 Vibe Coding 产物，代码健壮性可能不足（之前 Cron 报错、Gateway 崩溃也印证了这点）。
- **优化方向**：我们目前的 memory 架构（文件系统范式）正好契合它唯一的亮点 "File Driven"。应继续加强文件层面的记忆管理。
