## 二、核心优化策略

### 1. Fallback 链重构（成本优先）

#### 当前配置

```
主力: mynewapi/claude-sonnet-4-6-thinking (付费)
Fallback: 9 个模型（免费+付费混合）
```

#### 优化方案

```
主力: siliconflow/deepseek-ai/DeepSeek-V3.2 (免费)
Fallback:
1. groq/llama-3.3-70b-versatile (免费)
2. google-gemini/gemini-2.5-pro (免费，20次/天)
3. groq/qwen/qwen3-32b (免费)
4. siliconflow/deepseek-ai/DeepSeek-R1 (免费推理)
5. mynewapi/claude-sonnet-4-6 (付费，精调用)
6. mynewapi/claude-opus-4-6 (付费，复杂任务)
7. google-gemini-cli/gemini-3-pro-preview (付费会员)
```

**理由：**

- 免费模型足够应对 80% 的日常任务
- 付费模型留给真正需要的场景
- 符合 Annie 所长的"别拿高射炮打蚊子"原则

### 2. 任务分级机制（智能选择模型）

#### 简单任务（免费模型）

- 例行检查、基础搜索
- 文件读写、简单编辑
- 日志记录、状态查询
- **模型：** DeepSeek-V3.2, Groq Llama

#### 中等任务（免费高级模型）

- 代码生成、逻辑推理
- 多文件操作、配置修改
- 数据分析、内容总结
- **模型：** Gemini 2.5 Pro, DeepSeek-R1

#### 复杂任务（付费模型）

- 架构设计、系统优化
- 复杂调试、深度分析
- 关键决策、精细润色
- **模型：** Claude Sonnet 4.6, Opus 4.6

**实施方式：**

- 不需要明确分类，让 Fallback 链自动处理
- 免费模型失败后自动升级到付费模型
- 记录每个任务使用的模型，优化选择策略

### 3. 规划节点机制（适合 Kitt）

#### 触发条件（不照搬 3+ 步骤）

**Kitt 的实际情况：**

- 大部分任务是单步或两步
- 真正需要规划的是"多文件操作"和"配置变更"

**优化后的触发条件：**

1. **配置变更：** 修改 openclaw.json 或 cron 任务
2. **多文件操作：** 需要修改 3+ 个文件
3. **外部集成：** 调用外部 API 或服务
4. **用户明确要求：** "先规划"、"列出步骤"
5. **高风险操作：** 删除、重启、发布

**规划模板（简化版）：**

```markdown
## 任务：[任务名称]

### 目标

[一句话描述]

### 步骤

1. [步骤1]
2. [步骤2]
3. [步骤3]

### 验证

- [ ] [验证项1]
- [ ] [验证项2]

### 风险

- [风险1及应对]
```

**不需要：**

- 每个任务都规划（太重）
- 复杂的规划模板（太繁琐）
- 等待用户确认（影响效率）

### 4. 验证清单（实用版）

#### 配置变更验证

```markdown
- [ ] JSON 格式正确
- [ ] 关键配置项存在
- [ ] Fallback 链不为空
- [ ] 备份已创建
```

#### 代码变更验证

```markdown
- [ ] 语法正确
- [ ] 逻辑完整
- [ ] 注释清晰
```

#### 文件操作验证

```markdown
- [ ] 文件路径正确
- [ ] 权限足够
- [ ] 备份已创建
```

**不需要：**

- 复杂的测试流程（没有测试环境）
- 过度的文档要求（影响效率）

### 5. 自我改进循环（轻量版）

#### 当前问题

- 规则更新依赖手动操作
- 错误记录不系统

#### 优化方案

**自动记录错误：**

- 工具调用失败时自动记录到 memory/05\_日常日志/
- 包含：错误类型、原因、解决方案

**定期回顾：**

- 每日迭代升级时回顾当天错误
- 提取通用规则更新到 memory/01\_强制规则/

**不需要：**

- 复杂的规则引擎（过度工程）
- 实时规则更新（影响性能）

## 四、不采纳的内容（及原因）

### 1. Discord 集成

**原因：**

- Kitt 主要用于个人助手，不需要团队协作
- Telegram/WhatsApp 已满足需求
- Discord 集成成本高，收益低

### 2. 复杂的规划模板

**原因：**

- Kitt 的任务大多简单直接
- 过度规划影响效率
- 简化版已足够

### 3. 实时规则更新

**原因：**

- 技术复杂度高
- 可能影响性能
- 定期回顾已足够

### 4. 完整的测试流程

**原因：**

- 没有测试环境
- 大部分任务是配置和文件操作
- 简单验证已足够

### 5. Obsidian + GitHub 集成

**原因：**

- 当前 memory/ 目录已足够
- 增加复杂度
- 收益不明显

## 六、总结

**核心思想：**

- **实用主义：** 只采纳真正有用的
- **成本优先：** 免费模型优先，付费模型精准使用
- **轻量化：** 避免过度工程
- **渐进式：** 逐步优化，不求一步到位

**Kitt 的特点：**

- 个人助手，不是团队工具
- 任务简单直接，不需要复杂规划
- 成本敏感，优先使用免费资源
- 效率优先，避免过度流程

**优化方向：**

- 成本控制 > 功能完整
- 实用性 > 理论完美
- 渐进式 > 一步到位
