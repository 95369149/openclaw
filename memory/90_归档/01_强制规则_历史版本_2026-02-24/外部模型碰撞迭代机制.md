# 强制规则：外部模型碰撞迭代机制

## 核心思路
当 Kitt 遇到迷茫、不确定的配置或决策时，打包发给外部高端模型（Perplexity GPT-5.2 或 Grok 4.2）碰撞，集大家所长提升自己。

## 适用场景
1. **配置不确定**：不知道某个参数该怎么设置
2. **架构迷茫**：不确定某个功能该怎么设计
3. **决策困难**：多个方案不知道选哪个
4. **性能优化**：不知道怎么提升效率
5. **错误反复**：同一个问题反复出现

## 操作流程

### 1. 打包当前状态（⚠️ 必须脱敏）
```markdown
# Kitt 迭代请求

## 背景
[简述当前问题]

## 当前配置
[贴上相关配置文件内容]
⚠️ **脱敏要求：**
- 删除所有 API key
- 删除所有密码
- 删除个人信息（姓名、电话、地址）
- 删除公司敏感信息
- 删除服务器地址和端口
- 用占位符替换：[API_KEY], [PASSWORD], [COMPANY_NAME]

## 困惑点
[具体说明不确定的地方]

## 已尝试方案
[列出已经试过的方法]

## 期望结果
[希望达到什么效果]
```

### 2. 派兵碰撞
- **Perplexity Pro + GPT-5.2**：架构设计、最佳实践
- **Grok 4.2**：创新思路、非常规方案
- **Gemini 3.0 Pro**：深度分析、多角度思考

### 3. 整合反馈
- 收集 3 个模型的建议
- 提取共识部分（大家都认同的）
- 标注分歧点（不同意见）
- 给厂长 2-3 个方案 + 推荐

### 4. 实施并记录
- 执行选定方案
- 写入 `memory/07_版本控制/迭代提案.md`
- 记录效果（好/坏/待观察）

## 定期碰撞机制

### 每周日晚 22:00
- 自动总结本周遇到的困惑点
- 打包发给外部模型碰撞
- 生成《Kitt 进化建议》
- 推送到 Discord #日报频道

### 触发条件
- 同一个错误出现 3 次
- 厂长说"你这个不对"
- 自己感觉某个设计不够优雅

## 外部模型选择

### Perplexity Pro + GPT-5.2
- **优势**：最新信息、最佳实践、社区共识
- **适用**：架构设计、配置优化、性能调优

### Grok 4.2
- **优势**：创新思路、X 平台洞察、非常规方案
- **适用**：突破性问题、创意需求

### Gemini 3.0 Pro
- **优势**：深度分析、多角度思考、逻辑严密
- **适用**：复杂决策、风险评估

## 示例：配置优化

### 问题
cron 任务模型配置不确定，不知道该用哪个模型。

### 打包
```markdown
# Kitt 配置优化请求

## 背景
我有 9 个 cron 定时任务，需要选择合适的模型。

## 当前配置
- 任务1：GitHub Trending（每天9:00）
- 任务2：AI 新闻汇总（每天9:30）
- ...

## 可用资源
- Perplexity Pro（付费）
- Gemini 3.0 Pro（付费）
- 硅基流动 DeepSeek-V3.2（免费）
- Gemini 2.5 Flash（20次/天限制）

## 困惑点
1. 哪些任务该用付费模型？
2. 哪些任务该用免费模型？
3. 如何平衡成本和质量？

## 期望结果
给出每个任务的最佳模型选择 + 理由
```

### 派兵
1. 发给 Perplexity Pro（搜索最佳实践）
2. 发给 Grok 4.2（创新方案）
3. 发给 Gemini 3.0 Pro（深度分析）

### 整合
- 提取共识：日常任务用免费，关键任务用付费
- 标注分歧：Grok 建议全用免费，Gemini 建议分级
- 给厂长方案：保守/平衡/激进 3 个选项
