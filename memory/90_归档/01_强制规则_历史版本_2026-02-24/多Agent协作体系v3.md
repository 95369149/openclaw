## 一、组织架构（4 类核心角色 + 插件化能力）

```
厂长（指挥官）
  │
  ▼
Kitt（编排 + 记忆中枢）── 本体：Opus 4.6 primary
  │
  ├── 🔍 侦察（信息获取）── 搜索/X/网页
  ├── ⚙️ 工兵（内容产出）── 中文/英文/多模态
  └── ⚖️ 质检（独立裁决）── L0规则/L1独立Agent/L2仲裁
```

### 角色定义

| 角色             | 职责                           | 原则                     |
| ---------------- | ------------------------------ | ------------------------ |
| **Kitt（编排）** | 调度、记忆、合成交付、厂长对话 | 不下场干活，只调度和决策 |
| **侦察**         | 信息获取、事实写入             | 唯一有权写事实库的角色   |
| **工兵**         | 内容生成、代码、翻译           | 只读事实库，不得写入事实 |
| **质检**         | 评分、缺陷定位、返工指令       | 只判不改，不碰正文       |

### 能力插件（挂载到4类角色上）

| 插件      | 挂载角色 | 主力模型           | 备选1              | 备选2          |
| --------- | -------- | ------------------ | ------------------ | -------------- |
| 搜索      | 侦察     | Perplexity Pro     | web_search (Brave) | Gemini Pro     |
| X 抓取    | 侦察     | Grok 4 (browser)   | x-reader skill     | web_fetch      |
| 中文生成  | 工兵     | DeepSeek V3.2 (SF) | Qwen3 32B (Groq)   | Qwen3 32B (SF) |
| 英文/代码 | 工兵     | Llama 70B (Groq)   | DeepSeek V3.2      | Flash          |
| 多模态    | 工兵     | Gemini Pro         | Flash              | Opus (仅关键)  |
| L1 质检   | 质检     | Flash              | Qwen3 32B          | DeepSeek V3.2  |

## 二、任务路由（两段式 Triage/Plan）

### 第一段：Triage（<1秒）

收到任务后立即分类，输出：

- `intent_bucket`：搜索/写作/分析/代码/多模态/配置/对话
- `risk_level`：low/medium/high
- `need_tools`：true/false
- `language`：zh/en

### 第二段：Plan（按需 5-20秒）

仅对 `risk_level=high` 或 `need_tools=true` 的任务做拆解：

1. 目标澄清（Kitt）：验收标准、输出格式、截止时间
2. 事实收集（侦察）：结构化摘录
3. 结论草拟（工兵）：先建议后证据
4. 风险审查（质检/第二工兵）：找反例、漏洞
5. 合成交付（Kitt）：统一格式，写入产出库

### 路由表

| intent_bucket | risk=low       | risk=medium        | risk=high                |
| ------------- | -------------- | ------------------ | ------------------------ |
| 对话          | Kitt 直接回    | Kitt 直接回        | Kitt 回 + 记录           |
| 搜索          | 侦察直出       | 侦察 → Kitt 审     | 侦察 → 质检 → Kitt       |
| 写作          | 工兵直出       | 工兵 → L1质检      | 工兵 → L1质检 → 厂长确认 |
| 分析          | 工兵 → Kitt 审 | 侦察+工兵 → L1质检 | 全链路 + L2仲裁          |
| 代码          | 工兵直出       | 工兵 → 测试验证    | 工兵 → 质检 → 厂长确认   |
| 配置          | Kitt（需确认） | Kitt（需确认）     | Kitt + L2仲裁 + 厂长确认 |

**路由原则：免费 > 付费，快 > 慢，风险越高质检越严**

## 三、三层质检（L0/L1/L2）

### L0 规则闸门（Kitt 本地，零成本，<1秒）

硬性红线自动拦截：

- ❌ 编造数据/无来源引用
- ❌ 答非所问
- ❌ 格式不合规
- ❌ "赋能""闭环""抓手"等废话
- ❌ 超出要求字数 50%
- ❌ 前三句全在说"我们"

### L1 独立质检 Agent（免费模型，3-10秒）

- 用与执行模型不同的模型审核
- 只做"评分 + 缺陷定位 + 返工指令"，不改正文
- 输出结构化 JSON：

```json
{
  "hit": 8,
  "accuracy": 7,
  "usability": 8,
  "style": 6,
  "efficiency": 9,
  "total": 7.5,
  "evidence": ["fact_001", "fact_003"],
  "fix_instructions": "风格偏正式，需要更口语化"
}
```

### L2 仲裁（付费模型，按需）

触发条件：L1 评分 <5.0，或 L1 与业务规则冲突

- 用 Opus/Sonnet 做最终裁决
- 输出：通过/重做/Kitt接管

### 评分阈值（修正版）

- ≥6.0 → ✅ 直接交付
- 5.0-5.9 → 🔧 轻量补救（只返工缺口段，不全部重做）
- <5.0 → ❌ 重做或 Kitt 接管，失败原因写入黄金修正库

## 四、激励/淘汰（Bandit 派单 + ELO）

### 分桶 Bandit 策略

每个 intent_bucket 独立维护各模型的：

- 移动平均分（最近 20 次）
- 置信区间（样本越少区间越宽）
- 新模型先 10% 流量试跑，表现好再提到主力

### ELO 动态评分

每个模型初始 ELO = 1000

| 事件             | ELO 变化 |
| ---------------- | -------- |
| 质检 ≥6.0        | +15      |
| 质检 5.0-5.9     | -5       |
| 质检 <5.0        | -20      |
| 报错（403/超时） | -30      |
| 厂长说"好"       | +25      |
| 厂长说"不行"     | -25      |
| 响应 <3秒        | +5       |
| 响应 >30秒       | -10      |

### 段位

| ELO       | 段位    | 派发策略         |
| --------- | ------- | ---------------- |
| ≥1200     | ⭐ 王牌 | 该桶首选         |
| 1000-1199 | 🟢 主力 | 正常轮换         |
| 800-999   | 🟡 替补 | 仅主力不可用时上 |
| <800      | 🔴 淘汰 | 暂停，观察30天   |

### 硬指标自动打点

每次交付记录：

- 成功率（一次交付可用？）
- 返工轮数
- 端到端时延
- 成本（tokens/付费调用数）
- 协作效率（跨Agent往返次数/有效信息量）
- 证据覆盖率（结论中可追溯到事实库的比例）

### Golden Set 月度 Benchmark

从厂长真实需求抽 30 条，按桶分类：

1. 市场情报（搜索+摘要）
2. 竞品对比（搜索+分析）
3. 中文文案（写作）
4. 英文翻译（翻译）
5. 数据提取（结构化）
6. 逻辑推理（分析）

每月 1 号跑一轮，生成《模型绩效月报》。

## 五、三库一表（共享记忆）

### 事实库（Fact Store）→ `memory/02_知识库/facts/`

- 写入权限：仅侦察兵
- 每条必须包含：来源URL、抓取时间、摘要、可信度标签
- 写入前去重（同URL+同主张+同时间窗口合并）

### 任务库（Task Memory）→ `memory/04_情景记忆/tasks/`

- 写入权限：Kitt
- 存：任务目标、约束、拆解子任务、验收点、最终结果

### 产出库（Artifacts）→ `memory/02_知识库/artifacts/`

- 写入权限：工兵（经 Kitt 审核）
- 存：交付物、可复用模板、代码片段、常用措辞

### 证据映射表（Evidence Map）→ `memory/02_知识库/evidence-map.md`

- 写入权限：质检
- 格式：`结论句子 → fact_ID`，方便追溯和复查

### 清理规则

- 每周自动清理：低置信度 + 从未被 Evidence Map 引用的事实 → 归档
- 工兵不得直接写事实库（防止幻觉污染共享记忆）

## 六、监督反馈闭环

```
厂长下令 → Kitt Triage(<1s) → 判断风险等级
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
                 low            medium           high
              直接派发        派发+L1质检     Plan分解+L1+L2
                    │               │               │
                    ▼               ▼               ▼
               工兵/侦察执行 ──────────────────────┘
                    │
                    ▼
              L0 规则闸门（自动拦截红线）
                    │
                    ▼
              L1 独立质检（结构化JSON评分）
                    │
              ┌─────┼─────┐
              ▼     ▼     ▼
           ≥6.0  5-5.9  <5.0
           交付  补救段  重做/L2仲裁
              │     │     │
              ▼     ▼     ▼
           厂长收到结果 ←──┘
              │
              ▼
        厂长反馈 → 更新 ELO + Bandit
```

### 实时反馈规则

- 任务预计 >30秒 → 立即告知厂长"已派发，预计X秒"
- 任务完成 → 立即汇报结果
- 任务失败 → 立即汇报 + 替代方案
- 厂长说"不满意" → ELO -25，记录原因，下次换模型

### 高风险 Human-in-the-Loop

以下任务必须厂长确认后才执行：

- 对外发布（公众号/抖音/社交媒体）
- 报价/合同相关
- 配置修改
- 投资/采购决策

## 七、Fallback 总链

**主链：** Opus → Flash → DeepSeek(SF) → Llama(Groq) → Qwen3(SF) → Qwen3(Groq) → Sonnet

**搜索链：** Perplexity → Brave API → Gemini Pro → web_fetch

**X内容链：** Grok(browser) → x-reader skill → web_fetch

### 外链等待策略

| 任务类型  | 预估字数    | 等待时间 | 轮询间隔 |
| --------- | ----------- | -------- | -------- |
| 简单问答  | <500字      | 15秒     | 5秒      |
| 摘要/分析 | 500-2000字  | 45秒     | 10秒     |
| 深度研究  | 2000-5000字 | 90秒     | 15秒     |
| 长文生成  | >5000字     | 180秒    | 20秒     |

**原则：宁可降级回复，绝不失联。**
