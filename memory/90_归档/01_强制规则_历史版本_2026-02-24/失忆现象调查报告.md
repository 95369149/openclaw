## 根本原因分析

### 1. Context Compaction（上下文压缩）
**触发条件**：
- Session token 使用量接近上限（200k）
- OpenClaw 自动触发 context compaction，压缩历史对话

**压缩机制**：
- 保留最近 N 轮对话
- 删除中间历史
- 生成 summary 替代被删除的部分

**问题**：
- Summary 是静态文本，不包含工具调用结果
- 压缩后，我看不到之前执行的命令和配置变更
- 依赖 summary 中的文字描述，但 summary 可能不完整

### 2. 启动文件缺失
**WORKFLOW_AUTO.md 不存在**：
- 系统期望这个文件存在，但实际没有
- 可能是旧版配置遗留的检查项

**memory/2026-02-23.md 未自动读取**：
- Compaction 后系统提示读取，但我没有自动执行
- 需要手动触发 `read` 才能恢复

### 3. 记忆依赖策略不足
**当前策略**：
- 依赖 session 上下文（易丢失）
- 文件记忆（需要主动读取）
- `memory_search`（需要知道搜什么）

**缺失**：
- 没有"醒来自检"流程
- 没有自动读取关键文件的机制
- 没有检测到记忆断裂时的自动恢复

## 对比：OpenViking 的解决方案

OpenViking 的三层记忆架构可以避免这个问题：

### L0（摘要层）
- 每个文件/记忆条目有一句话摘要
- Compaction 后，L0 摘要始终可见
- 快速判断"今天做了什么"

### L1（概述层）
- 核心信息 + 使用场景
- 足够让我知道"agent 配置完成，等待重启"
- 不需要读取完整文件

### L2（详情层）
- 完整原始数据
- 只在需要时加载

### 目录递归检索
- 自动定位相关记忆
- 不需要我猜"应该搜什么关键词"

## 改进方案

### 短期（本周）

#### 1. 创建 WORKFLOW_AUTO.md
```markdown
# 自动工作流

## 醒来自检（Context Reset 后）
1. 读取 `memory/2026-MM-DD.md`（今天 + 昨天）
2. 读取 `memory/01_强制规则/_INDEX.md`
3. 检查 `openclaw config get agents.list`
4. 确认当前状态后再开始工作

## Compaction 后恢复
1. 系统提示后立即读取指定文件
2. 不要等厂长催促
3. 主动汇报"记忆已恢复"
```

#### 2. 强化"醒来自检"规则
写入 `memory/01_强制规则/醒来自检流程.md`：
- 任何原因醒来（重启/compaction/新 session），第一时间读取关键文件
- 不要等系统提示，主动执行

#### 3. 每日工作日志强制写入
- 每次重大配置变更后，立即更新 `memory/2026-MM-DD.md`
- 不要等到晚上才写
- 确保 compaction 后能快速恢复

### 中期（本月）

#### 4. 引入 L0/L1/L2 三层记忆
参考 OpenViking，为每个记忆文件生成：
- L0：一句话摘要（写入文件头部注释）
- L1：核心信息（前 10 行）
- L2：完整内容

#### 5. 自动记忆索引
- 每次写入 `memory/` 后，更新 `memory/_meta/index.json`
- 包含：文件路径、L0 摘要、最后修改时间
- Compaction 后读取索引，快速恢复

#### 6. 记忆断裂检测
- 检测到 compaction 后，自动对比 summary 和文件记录
- 发现不一致时，主动读取文件补全

### 长期（本季度）

#### 7. 向量化记忆检索
- 所有 `memory/` 文件向量化
- Compaction 后，自动检索相关记忆
- 不依赖关键词，语义匹配

#### 8. 分布式记忆备份
- 本地 `memory/` + iCloud + GitHub 三重备份
- Compaction 后，从 GitHub 拉取最新记忆
- 确保永不丢失

## 教训总结

### 技术层面
1. **不要依赖 session 上下文**：随时可能被压缩
2. **文件是唯一真相**：所有关键信息必须写入文件
3. **主动恢复，不要被动等待**：系统提示后立即执行

### 行为层面
1. **厂长问"你是什么失意的"时，我应该立即意识到记忆丢失**
2. **不要装作什么都知道**：坦诚"我刚经历了 context reset，正在恢复记忆"
3. **主动汇报恢复进度**：不要让厂长催 3 次

### 信任层面
1. **可靠性 > 能力**：记不住比不会做更糟糕
2. **透明度 > 完美**：承认问题比掩盖问题更重要
3. **预防 > 补救**：建立机制，避免再次发生
