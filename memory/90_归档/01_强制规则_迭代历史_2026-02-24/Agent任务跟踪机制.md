# Agent 任务跟踪机制 v1.0

## 核心原则

**派出去不是结束，跟踪学习才是关键。**

## 派出 Agent 后必须做的事

### 1. 立即记录

```markdown
- Agent: [名字]
- 任务: [简述]
- 派出时间: [时间]
- 预计完成: [时间]
- 状态: 运行中
```

### 2. 定期检查（每 5 分钟）

```bash
subagents(action=list)
```

检查：

- 哪些在运行？
- 哪些完成了？
- 哪些失败了？
- 运行时间是否过长？

### 3. 完成后立即学习

- ✅ 读取成果
- ✅ 提取关键信息
- ✅ 更新知识库
- ✅ 应用到当前任务

### 4. 失败后立即处理

- ❌ 分析失败原因
- ❌ 换模型重试（最多 2 次）
- ❌ 如果还失败，换方法或向厂长汇报

## 学习成果的方法

### 方法 1：直接读取（如果有权限）

```bash
sessions_history(sessionKey="agent:xxx:subagent:xxx")
```

### 方法 2：等待自动回报

- Agent 完成后会自动发送结果
- 立即阅读并提取关键信息

### 方法 3：主动询问

```bash
sessions_send(sessionKey="agent:xxx:subagent:xxx", message="请总结你的成果")
```

## 超时处理

### 判断标准

- 简单任务：> 3 分钟 → 可能超时
- 复杂任务：> 5 分钟 → 可能超时
- 学习任务：> 10 分钟 → 可能超时

### 处理流程

1. 检查 agent 状态
2. 如果还在运行，继续等待
3. 如果超时，kill 并重试
4. 如果重试 2 次还失败，换方法

## 失败处理

### 常见失败原因

1. **模型问题**：gemini-cli 不稳定 → 换 deepseek-v3.2
2. **超时**：任务太复杂 → 拆分任务
3. **权限不足**：无法读取文件 → 换方法
4. **配置错误**：模型配置错误 → 修复配置

### 处理流程

1. 分析失败原因
2. 换模型/换方法重试
3. 最多重试 2 次
4. 如果还失败，向厂长汇报

## 成功标准

✅ **跟踪率 100%**：所有派出的 agent 都有跟踪记录  
✅ **学习率 100%**：所有完成的 agent 成果都已学习  
✅ **重试率 > 80%**：失败的 agent 80% 成功重试  
✅ **超时率 < 10%**：超时的 agent < 10%
