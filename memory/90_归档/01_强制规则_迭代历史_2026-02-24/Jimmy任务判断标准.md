# Jimmy 任务判断标准（简单 vs 需派发）

**制定时间**: 2026-02-23 17:39  
**制定人**: Kitt

---

## 判断原则

**简单任务**（jimmy 自己处理）：

- 单轮对话能完成
- 不需要专业领域知识
- 不需要复杂推理
- 不需要生成大量内容
- 成本可控（<1000 tokens 输出）

**复杂任务**（派发给专业 agent）：

- 需要多步推理
- 需要专业领域知识
- 需要生成大量内容
- 需要特殊能力（多模态/数学/架构设计）

---

## 具体判断标准

### ✅ Jimmy 自己处理（简单任务）

#### 1. 信息查询类

- 查记忆：`memory_search` + `memory_get`
- 查文件：`read` 单个文件
- 查配置：`openclaw config get`
- 查状态：`openclaw status`

**示例**：

- "今天做了什么？" → 查 memory/05\_日常日志/
- "兵团有哪些成员？" → 查 memory/01\_强制规则/兵团编制与调度.md
- "当前模型是什么？" → session_status

#### 2. 简单操作类

- 单文件编辑：`edit` 一处修改
- 简单脚本：`exec` 单行命令
- 配置修改：`openclaw config set` 单个值
- 文件创建：`write` 小文件（<2KB）

**示例**：

- "把这个配置改成 true" → config set
- "运行一下这个命令" → exec
- "创建一个 TODO 文件" → write

#### 3. 日常对话类

- 闲聊
- 确认指令
- 简单解释
- 状态汇报

**示例**：

- "收到"
- "好的，马上处理"
- "这个配置的意思是..."
- "当前进度：已完成 3/5"

#### 4. 简单决策类

- 二选一决策（有明确规则）
- 流程确认
- 下一步建议

**示例**：

- "要重启 Gateway 吗？" → 根据配置变更判断
- "接下来干啥？" → 查待办清单
- "用哪个模型？" → 根据成本和任务类型

---

### ❌ 需要派发（复杂任务）

#### 1. 内容生成类 → deep/main

- 中文文章（>500字）
- 技术文档
- 代码文件（>50行）
- 图片/视频生成

**判断标准**：

- 输出预计 >1000 tokens
- 需要专业写作能力
- 需要多模态能力

**示例**：

- "写一篇关于 AI Agent 的文章" → deep
- "生成一张产品宣传图" → main
- "写一个完整的 Python 脚本" → deep

#### 2. 深度分析类 → logic/kitt

- 数学证明
- 算法设计
- 架构设计
- 复杂推理

**判断标准**：

- 需要多步推理（>3步）
- 需要专业领域知识
- 需要深度思考

**示例**：

- "设计一个分布式系统架构" → kitt
- "证明这个数学定理" → logic
- "优化这个算法的时间复杂度" → logic

#### 3. 多模态任务 → main

- 图片/视频分析
- 图片/视频生成
- 超长文档分析（>100KB）

**判断标准**：

- 涉及图片/视频
- 文档超过 jimmy 的舒适处理范围

**示例**：

- "分析这张图片" → main
- "生成一个视频" → main
- "总结这个 200 页的 PDF" → main

#### 4. 关键决策类 → kitt

- 系统架构选型
- 重大技术决策
- 战略规划
- 风险评估

**判断标准**：

- 影响重大（成本/时间/风险）
- 需要深度权衡
- 需要长期视角

**示例**：

- "选择哪个数据库方案？" → kitt
- "要不要重构整个系统？" → kitt
- "未来 3 个月的技术规划" → kitt

## 边界案例处理

### 案例 1: 中等长度代码（50-200行）

**判断**：

- 如果是简单脚本（逻辑简单）→ jimmy 自己写
- 如果需要复杂逻辑 → deep

### 案例 2: 中等复杂度推理（2-3步）

**判断**：

- 如果有明确规则可循 → jimmy 自己推
- 如果需要创造性思考 → logic

### 案例 3: 配置变更（多个相关配置）

**判断**：

- 如果是简单的值修改 → jimmy 自己改
- 如果涉及架构调整 → kitt 审查

### 案例 4: 文档生成（500-2000字）

**判断**：

- 如果是简单总结/汇报 → jimmy 自己写
- 如果需要专业写作 → deep

## 成本考量

### Jimmy 自己处理的成本优势

- **速度快**：sonnet 响应快，无派发开销
- **成本低**：单次调用，无额外 token
- **简单高效**：不需要任务拆解和结果汇总

### 派发的成本

- **时间成本**：派发 + 等待 + 汇总
- **Token 成本**：任务描述 + 结果传递
- **复杂度**：需要任务拆解和质检

### 原则

- **能自己处理的不派发**
- **派发必须有明确收益**（质量提升 or 专业能力）
- **成本敏感任务优先自己处理**
