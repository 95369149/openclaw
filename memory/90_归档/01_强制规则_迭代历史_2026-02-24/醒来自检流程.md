# 醒来自检流程

**适用场景**：

- Gateway 重启
- Context compaction（上下文压缩）
- 新 session 启动
- 任何原因导致的记忆断裂

---

## 强制执行（5 步）

### 1. 读取今日工作日志

```
read memory/2026-MM-DD.md
```

如果今天的不存在，读昨天的。

**目的**：快速恢复"今天做了什么"。

---

### 2. 读取强制规则索引

```
read memory/01_强制规则/_INDEX.md
```

**目的**：恢复行为约束和核心规则。

---

### 3. 检查 agent 配置

```
openclaw config get agents.list
openclaw config get bindings
```

**目的**：确认当前 agent 编制和渠道路由。

---

### 4. 确认当前模型

```
session_status
```

**目的**：确认当前使用的模型和 fallback 链。

---

### 5. 主动汇报

向厂长汇报：

- "记忆已恢复"
- "当前状态：[agent/模型/渠道]"
- "今天已完成：[关键事项]"
- "待办：[未完成事项]"

**目的**：让厂长知道我已经恢复，可以继续工作。

---

## 触发时机

### 自动触发

- 系统提示 "Post-Compaction Audit"
- 检测到 session 上下文为空
- 检测到最后一条消息时间超过 1 小时

### 手动触发

- 厂长说"把以前的记忆全部找回"
- 厂长问"你是什么失意的"
- 厂长问"你怎么不记得了"

---

## 不要做的事

❌ **等系统提示才读取**  
→ 主动检测，主动恢复

❌ **等厂长催促才恢复**  
→ 发现记忆断裂立即执行

❌ **装作什么都知道**  
→ 坦诚承认，快速恢复

❌ **只读取不汇报**  
→ 恢复后主动告知厂长

❌ **依赖 session 上下文**  
→ 文件是唯一真相

---

## 恢复后验证

**自检清单**：

- [ ] 知道今天做了什么
- [ ] 知道当前 agent 配置
- [ ] 知道当前模型和 fallback
- [ ] 知道待办事项
- [ ] 已向厂长汇报

**全部勾选后**，才能继续工作。

---

**状态**: 强制执行  
**优先级**: P0（最高）  
**违反后果**: 失去厂长信任
