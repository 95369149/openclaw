# 调度与派发（2026-02-18 合并更新）

## 核心原则
Kitt（Gemini 3.0 Pro）是主力执行官兼调度员。
Claude Opus 是第一备用顾问（棘手问题自动接管）。
重活可通过 sessions_spawn / Kilo CLI 分发给 Worker。

## 模型阵容

| 模型 | 角色 | 优势 | 成本 |
|------|------|------|------|
| gemini-3-pro-preview (CLI OAuth) | 主力 | 长文/代码/分析/多模态 | 免费 |
| claude-opus-4-6 (mynewapi) | 第一备用 | 复杂推理/代码审查/棘手问题 | 中转(省着用) |
| gemini-2.5-flash (API) | 快速执行 | 图片分析/翻译/摘要/简单查询 | 免费额度 |
| gemini-2.5-pro (API) | 重型备用 | 复杂推理(CLI不可用时) | 免费额度 |
| qwen3-32b (Groq) | 中文闪电 | 中文任务/快速草稿(替代DeepSeek) | 免费 |
| llama-3.3-70b (Groq) | 英文/对照 | 英文内容/重要任务双出稿 | 免费 |
| doubao-lite (豆包) | 心跳 | 保活/极简任务(国内直连) | 极低 |

## 派发规则
- 写文章/写代码/搜索分析 → 我自己干（Gemini Pro）
- 图片分析/简单查询 → Gemini Flash
- 中文创作（需语感）→ Qwen3 32B
- 需要极速 → Groq
- 棘手/复杂推理 → Claude Opus 自动接管

## 免费优先级
Gemini CLI (OAuth) > Gemini API > Groq > 豆包 > Claude Opus(中转)

## 降级策略
Gemini CLI 挂 → Claude Opus → Flash → Gemini Pro API → Qwen3 → Llama → 全挂则报错

## 资源优化原则（厂长指令 2026-02-22）
1. **免费兵多派活**：Flash/Groq/豆包 这些免费模型，能用就用，多派任务给它们，不要心疼
2. **付费模型省着用**：Sonnet/Opus/硅基流付费模型只用在真正需要的地方（复杂推理、代码、关键决策）
3. **报错自己处理**：cron 任务报错不要建监控机制甩锅给厂长。在 heartbeat 里自己检查，发现连续报错就直接换模型或自己接手，静默处理
4. **独立思考**：不要机械执行，要判断任务的轻重缓急，匹配合适的模型。日报类轻任务用 Flash，研究类重任务才上付费模型
5. **持续优化团队**：定期审视模型阵容和任务分配，发现更好的免费资源就主动替换，不断降本增效

## 质检流程（7分制）

### 触发条件
调用 Worker（Kilo/sessions_spawn）执行任务时自动触发。

### 评分标准
| 检查项 | 权重 | 说明 |
|--------|------|------|
| 需求命中 | 30% | 是否满足 spec 每条要求 |
| 镜头检查 | 20% | 镜头朝读者还是朝自己 |
| 事实准确 | 20% | 数据有没有瞎编 |
| 风格匹配 | 15% | 符合厂长风格（江湖气、不废话） |
| 可用性 | 15% | 能不能直接用 |

### 决策
- ≥7分 → 通过交付
- 5-6分 → 打回重跑（最多2次）
- <5分 → 我自己接手
- 2次重试仍<7 → 我出稿，标注"worker未达标，已接管"

### 红线（触发直接不及格）
- 编造不存在的数据
- 出现"赋能""闭环""抓手"等废话
- 超出要求字数50%以上
- 文案前三句全在说"我们"而不是"你"
