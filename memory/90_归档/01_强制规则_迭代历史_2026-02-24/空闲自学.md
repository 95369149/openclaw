# 空闲自学系统

## 触发机制
- 用户无互动超过 **1 小时** → 进入学习模式
- 用户发消息 → 立即暂停学习，响应用户
- 用户再次沉默 1 小时 → 继续学习（从断点续）
- 通过 heartbeat 检测空闲状态

## 节奏控制（重要！）
- 每次只读 **2-3 篇**，然后停下来
- 停 **30 分钟** 后再继续下一批
- 严禁一口气读完所有资料 — API 调用频率受不了
- 宁可慢慢消化，不要集中爆发

## 原则
- 我只做调度：定主题 → 搜索 → 抓取 → 审核 → 存记忆
- 单次学习 1 个小主题，<3 轮工具调用
- 每个知识点存语义记忆 <3KB
- 不打扰用户，学完静默存储

## 两条学习线（交替进行）

### 线1：消化已有资料（优先）
已存但未消化的资料 = 浪费。每次空闲优先从以下位置挑一篇深读：
1. `memory/inbox/` — 未处理的外部反馈（最高优先）
2. `memory/80_收藏/` — 抓回来的文章，提取可执行方法论 → 写入语义记忆
3. `memory/02_知识库/` — 模板类资料，提炼核心要点 → 写入语义记忆
4. iCloud `OpenClaw_Memory/` — 云端同步过来的资料
5. NotebookLM 里的知识（无法直接读取，但可以根据已有摘要做关联学习）

消化标准：
- 读完一篇 → 提取 3-5 条可执行知识点 → 写入 `memory/03_semantic-memory/`
- 原文标记已消化（在文件末尾加 `<!-- digested: YYYY-MM-DD -->`）
- 如果原文价值不大 → 直接归档到 `memory/90_归档/`

### 线2：外出找新知识
优先攻克 `memory/语义记忆/Kitt进化路线图.md` 中的未完成项。

#### 优先级队列
1. **基础设施**：OpenViking 架构落地、OpenClaw 故障自愈
2. **能力扩展**：Reveal.js Skill 移植、RF-DETR 本地视觉部署
3. **技术前沿**：监控 Codexbot、Agent Swarm 等竞品动态

### 交替规则
- 奇数次空闲 → 线1（消化已有）
- 偶数次空闲 → 线2（找新知识）
- inbox 有未处理项时 → 强制线1，直到 inbox 清空
