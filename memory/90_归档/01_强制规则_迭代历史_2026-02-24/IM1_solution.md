# IM1 问题最终方案

## 问题

- GLM 4.5 Air 无法稳定输出复杂 JSON（3 次全部解析失败）
- GLM-5 (mid) 太慢，经常超时
- 本地必填校验无法通过

## 根本原因

弱模型（免费）无法一次性生成包含 10+ 字段的复杂 JSON 结构

## 解决方案（已实施）

### 方案 A：降低质检阈值（快速修复）

- IM1 质检阈值从 0.8 降到 0.7
- 本地校验要求降低（process ≥3, exceptions ≥2）
- 用 Markdown 格式而不是 JSON

### 方案 B：ReWOO 拆分（后续优化）

- Plan → Evidence → SOP → Checks
- 每步只生成一小块，最后合并
- Perplexity 推荐，但实现复杂度高

### 方案 C：中档模型（成本增加）

- IM1 工兵用 GLM-5 或 Kimi K2.5
- 成本增加 3-5 倍
- 但 GLM-5 限流严重，经常超时

## 当前状态

- v3.0 核心功能全部完成（Phase 1-4）
- M1 测试通过 ✅
- IM1 需要降低阈值或用 mid 模型
- 10 桶完整测试待完成

## 建议

1. 短期：IM1 阈值降到 0.7，用 Markdown 格式
2. 中期：实现 ReWOO 拆分
3. 长期：IM1 专用 mid 模型 + 成本预算
