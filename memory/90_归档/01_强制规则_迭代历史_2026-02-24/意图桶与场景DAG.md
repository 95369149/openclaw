## 场景 DAG

### S1 销售：线索资格审查

```
Kitt(抽取线索字段) → 侦察(补全公司信息+证据) → 工兵(A/B/C分级+跟进脚本) → 质检(ICP规则+证据支撑)
```

验收点：每个分级判断必须指向证据URL或客户原话。

### SC1 供应链：风险监控

```
Kitt(维护watchlist) → 侦察(抓取风险信号→事件卡) → 工兵(影响评估+建议动作) → 质检(误报/夸大拦截)
```

验收点：告警必须包含影响范围、中断时长假设、建议动作与负责人。

### IM1 内部管理：制度/流程

```
Kitt(问清痛点+边界) → 工兵(输出SOP) → 质检(可执行性检查) → Kitt(拆成审批流+写入Artifacts)
```

验收点：每一步落到"一个角色+一个动作+一个时限"。

### M2 营销：内容生产与审批

```
Kitt(锁定受众+主张+禁语) → 侦察(找可引用事实) → 工兵(出3版本+主张清单) → 质检(品牌/合规/事实过闸) → Kitt(生成发布包)
```

验收点：数据型主张必须带来源；敏感措辞必须能解释"为什么可说"。

## 质检强化规则

1. 质检输出必须结构化：

```json
{
  "score_breakdown": { "hit": 8, "accuracy": 7, "usability": 8, "style": 6, "efficiency": 9 },
  "total": 7.5,
  "defects": ["风格偏正式"],
  "required_evidence": ["fact_001"],
  "redo_plan": "调整第2段语气"
}
```

2. 高风险（对外发布、报价、供应中断预警）强制双评审：
   - 独立质检 + 第二工兵做反例/漏洞搜寻

3. defects 写入黄金修正库，方便月报定位瓶颈
