## 反思洞察

### 2026-02-28

**1. 路由模式是核心，不是可选项**
- **模式**：今天大部分任务 jimmy 自己做了，没有充分派发子 agent
- **根因**：系统不稳定（kitt 没 exec 权限）+ 惯性思维（觉得自己做更快）
- **教训**：调度中枢不是万能执行者。复杂任务（>500 tokens 输出）必须派发
- **改进**：严格执行快速决策流程，收到任务先过滤"自己能搞定吗？"
- **状态**：已写入 memory/2026-02-28.md，需连续观察3天

**2. 配置变更需要"慢就是快"**
- **模式**：今天改配置搞砸了3次（jimmy/kitt 互换、xjrouter 乱码、系统无响应）
- **根因**：没完全理解需求就动手、一次改多个东西、没有验证就继续改
- **教训**：改配置前先完全理解需求，一次只改一个东西，改完验证再继续
- **改进**：建立配置变更 checklist（理解需求 → 备份 → 单点修改 → 验证 → 下一步）
- **状态**：已写入急救手册 v3.5

**3. 外链碰撞要"充分利用资源"**
- **模式**：视频工厂方案一开始只靠自己想，厂长提醒"用所有资源来完善"
- **根因**：忘记了 SOUL.md 的核心规则："不是只靠你一个去想"
- **教训**：复杂方案必须调动所有资源（web_search 5+篇、派子 agent、外部模型碰撞）
- **改进**：收到复杂任务时，第一反应是"我能调动哪些资源"而不是"我怎么做"
- **状态**：已执行（搜了5篇文章+更新模板），需持续强化

**4. 提示词质量决定输出质量**
- **模式**：谷歌一条龙碰撞发现，官方 Nano Banana 提示词平均 150-300 词，极其详细
- **洞察**：AI 生成质量的天花板不是模型能力，是提示词质量
- **应用**：video-factory 模板从 50 词升级到 150-300 词，加入摄影术语+情绪+色彩+材质
- **改进方向**：建立提示词质量标准（长度、结构、术语密度），定期迭代模板库
- **状态**：已落地到 video-factory skill

**5. 免费模型优先，但要知道边界**
- **模式**：gemini 经常限流，xjrouter 不稳定（乱码），但都是免费的
- **洞察**：免费模型有边界（限流、稳定性），关键路径必须用付费稳定线路
- **应用**：jimmy（调度中枢）用 mynewapi，cron 定时任务用 sonnet，学习任务用 gemini-cli
- **改进**：建立"关键路径识别"机制，自动判断哪些任务不能用免费模型
- **状态**：已落地到 agent 配置和 cron 任务
