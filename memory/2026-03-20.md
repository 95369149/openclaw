## 经验教训

1. **Apollo API 协议**：Key 必须放 Header `X-Api-Key`，放 body 返回 422；免费版 `mixed_people/search` 返回 403，需用 `organizations/search` 做 health check
2. **chrome-relay CDP 超时**：端口 18792 未监听，根因是扩展未正确 attach，需用户重新点击龙虾图标；重启 gateway 无效，需重载扩展
3. **cron job ID 不能猜**：必须先 list 拿到真实 ID 再 update，猜 ID 浪费工具调用
4. **env.vars 不支持对象引用**：`openclaw.json` 的 `env.vars` 只能是字符串或 `${VAR}` 格式，不能写成 `{ "source": "env", ... }` 对象，否则配置解析失败导致 gateway 无法启动

## 20:44 - 21:02 Gemini 3.1 Pro High 配置修正

### 问题
厂长测试 `g31` 模型时报错：
```
400 INVALID_ARGUMENT
Request contains an invalid argument.
```

### 根因
1. **API 协议错误**：配置为 `google-generative-ai`，但代理 `https://api.penguinsaichat.dpdns.org` 是 OpenRouter，要求 `openai-completions`
2. **baseUrl 路径错误**：配置为 `/v1beta`，应为 `/v1`
3. **模型 ID 缺少前缀**：配置为 `gemini-3.1-pro-high`，OpenRouter 要求 `google/gemini-3.1-pro-high`

### 修正过程
1. 第一次修正（20:47）：
   - `api`: `google-generative-ai` → `openai-completions`
   - `baseUrl`: `/v1beta` → `/v1`
   - 备份：`~/.openclaw/openclaw.json.bak.20260320-204711`
   - 结果：仍报 400

2. 第二次修正（20:58）：
   - 模型 ID：`gemini-3.1-pro-high` → `google/gemini-3.1-pro-high`
   - 备份：`~/.openclaw/openclaw.json.bak.20260320-205825`
   - 依据：厂长提供 OpenRouter 模型页面截图

### 最终配置
```json
"google-gemini-high": {
  "baseUrl": "https://api.penguinsaichat.dpdns.org/v1",
  "apiKey": { "source": "env", "provider": "default", "id": "GOOGLE_GEMINI_HIGH_API_KEY" },
  "api": "openai-completions",
  "models": [
    {
      "id": "google/gemini-3.1-pro-high",
      "name": "Gemini 3.1 Pro High",
      ...
    }
  ]
}
```

### 教训
- OpenRouter 模型 ID 必须带 provider 前缀（如 `google/`、`anthropic/`）
- 代理平台的 API 协议不能假设，必须查文档或看截图确认
- 第三方代理（OpenRouter/OpenAI-compatible）统一用 `openai-completions` + `/v1` 端点
