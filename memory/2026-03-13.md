## Lyra V5.5 → V6.0 架构升级（07:00-10:30）

### 外部碰撞（Perplexity GPT-5.4 Thinking）
- 3 轮深度问询，吸收 2026 年 Context Engineering 最佳实践
- 核心洞察：
  1. 从 Prompt Engineering 到 Context Engineering（Karpathy：LLM=CPU，Context=RAM）
  2. 推理模型禁用显式 CoT（"think step by step" 有害）
  3. 长提示词降低性能（3000 tokens 后退化，最佳 150-300 词）
  4. Lost in the Middle：关键信息放开头或结尾
  5. 结构化输出三步法：建立理解 → 提供上下文 → 输出前再次提醒
  6. 模型特异性策略：openai_reasoning / claude / gemini / xai 分开适配

### V6.0 架构设计
- **核心定位**：从"prompt 润色器"升级为"白话转标准 JSON 的跨模型上下文装配引擎"
- **5 个核心模块**：
  - `schemas/`：TaskSpec v1 + AppResponse v1 + business schemas
  - `assembler/`：三层上下文装配（L0/L1/L2）
  - `policies/`：模型家族策略（reasoning / gpt / claude / gemini / xai）
  - `adapters/`：API 对接层（openai / gemini / grok）
  - `validators/`：结果治理 + repair retry
- **主链路**：`intent parse → context assemble → vendor policy select → prompt render → structured output → local validate → repair retry`

## 教训与模式

1. **Provider 兼容性不能只看简单请求**：geminiflash 简单请求 200，复杂请求（长 prompt + 多 tools）稳定 422
2. **配置漂移是慢性毒药**：多个文件（排兵布阵、大脑中枢、.abstract）互相矛盾，必须以 `openclaw.json` 为唯一真相源
3. **外部碰撞价值巨大**：Perplexity GPT-5.4 Thinking 3 轮问询，产出的架构洞察远超闭门造车
4. **三层加载是共识**：OpenViking、我们的 memory、Lyra V6.0 都在用 L0/L1/L2，说明这是正确方向
5. **可观测性是工程化关键**：检索轨迹、loadTrace、状态日志，debug 时能看到"为什么"比"是什么"更重要
