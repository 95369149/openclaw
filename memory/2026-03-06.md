## 3. 经验教训
- 子Agent在执行任务时，直接在主进程推送（push）结果会导致严重的视觉污染和上下文干扰。所有涉及IO落地的任务都应放入后台静默执行，主节点仅反馈人类可读的“摘要”。
- 对厂长的交互节奏必须从“确认流”切换为“闭环流”：同一条线上、低风险、已明确授权的动作应默认直接做到底，不要把一件事切成很多步确认。
- 汇报节奏要极简：默认只在“开始”和“结尾”两次汇报，中间不实时播报；任务没完成前不要停，除非卡住、失败、需拍板或存在风险变更。
- 派工透明度仍然重要：开始时至少说明“任务 / 执行者 / 状态”，既让厂长知道谁在干活，又不打断执行闭环。
