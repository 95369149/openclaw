## 1. 调用方式

### 设计原则
厂长一句自然语言就能触发，不需要记命令格式。jimmy 负责理解意图。

### 调用入口
厂长 → jimmy（唯一入口，任何频道：webchat / 微信 / Discord）

### 自然语言示例（直接说就行）

| 厂长说的话 | 系统理解 |
|-----------|---------|
| "写个通报，表扬销售部这周业绩" | 通报 → 表扬类 |
| "帮我发个朋友圈，今天发了15台货" | 朋友圈 → 工厂日常 |
| "给河北王总回个报价" | 销售文案 → 报价回复 |
| "写个月报，这个月产了90台" | 报告 → 月报 |
| "发个朋友圈，聊聊今年自动化产线的趋势" | 朋友圈 → 行业洞察 |
| "给老客户发个春节问候" | 销售文案 → 节日问候 |
| "写个晨会发言稿，今天要冲刺" | 管理文书 → 晨会发言 |

### 补充信息机制
如果厂长给的信息不够，jimmy 追问一次（最多一次），问最关键的缺失项：

```
厂长："写个通报"
jimmy："好的，表扬还是批评？谁？什么事？"
厂长："表扬，张伟，上周发现主轴异响避免了事故"
jimmy：→ 生成通报
```

### 快捷触发词（可选，加速识别）

| 触发词 | 映射 |
|--------|------|
| 通报 / 考核 | B1 考核通报 |
| 月报 / 周报 / 报告 | B2 工作报告 |
| 评语 / 转正 / 考核评语 | B3 员工评语 |
| 会议纪要 / 晨会纪要 | B4 会议纪要 |
| 朋友圈 / 发圈 | A1-A4（根据内容细分） |
| 报价 / 回复客户 | C1 报价回复 |
| 售后 / 投诉 / 回访 | C2 售后回复 |
| 问候 / 节日 | C3 节日问候 |
| 抖音 / 短视频 | D1-D3（根据内容细分） |
| 晨会 / 发言 | E1 晨会发言稿 |

## 2. 路由规则

### 两级路由：大类 → 子场景

```
厂长输入
  │
  ▼
jimmy 意图识别（第一级：大类）
  │
  ├─ 关键词命中 → 直接路由
  │   "通报" → 管理文书
  │   "朋友圈" → 朋友圈文案
  │   "报价" → 客户沟通
  │
  └─ 关键词未命中 → 语义理解
      分析上下文判断大类
  │
  ▼
子场景识别（第二级：具体模板）
  │
  ├─ 朋友圈文案
  │   ├─ 提到设备/产品/卖点 → A1 产品推广
  │   ├─ 提到客户/交付/验收 → A2 客户案例
  │   ├─ 提到车间/团队/日常 → A3 工厂日常
  │   └─ 提到趋势/观点/行业 → A4 行业洞察
  │
  ├─ 管理文书
  │   ├─ 提到表扬/批评/事故 → B1 考核通报
  │   ├─ 提到周报/月报/数据 → B2 工作报告
  │   ├─ 提到评语/转正/晋升 → B3 员工评语
  │   └─ 提到会议/纪要/决议 → B4 会议纪要
  │
  ├─ 客户沟通
  │   ├─ 提到报价/价格/询价 → C1 报价回复
  │   ├─ 提到投诉/维修/售后 → C2 售后回复
  │   └─ 提到节日/问候/生日 → C3 节日问候
  │
  ├─ 短视频脚本
  │   ├─ 提到抖音/15秒/短 → D1 抖音15秒
  │   ├─ 提到案例视频/1分钟 → D2 客户案例视频
  │   └─ 提到YouTube/讲解/教程 → D3 YouTube技术讲解
  │
  └─ 管理能力
      └─ 提到晨会/发言/激励 → E1 晨会发言稿
```

### 路由优先级
1. 显式关键词 > 语义推断
2. 有歧义时，jimmy 追问一次确认
3. 完全无法判断时，默认当"朋友圈文案 → 工厂日常"处理（厂长最常用的场景）

## 3. Agent 分工

### 核心架构

```
厂长
  │
  ▼
jimmy（总调度 · claude-sonnet）
  │  ① 接收请求
  │  ② 意图识别 + 路由
  │  ③ 提取变量（从厂长的话里抽出模板需要的参数）
  │  ④ 派发给执行 agent
  │  ⑤ 接收结果，质检，交付厂长
  │
  ├──→ deep（中文内容专家 · DeepSeek-V3.2）【主力执行】
  │     负责：所有文稿的初稿生成
  │     - 朋友圈文案（A1-A4）
  │     - 管理文书（B1-B4）
  │     - 客户沟通（C1-C3）
  │     - 晨会发言稿（E1）
  │     优势：中文语感好、速度快、免费
  │
  ├──→ main（多模态专家 · Gemini Pro）【视频脚本】
  │     负责：短视频脚本（D1-D3）
  │     原因：视频脚本需要画面思维，Gemini 多模态理解强
  │     附加：如果需要配图建议的可视化，也走 main
  │
  ├──→ kitt（架构师 · claude-opus）【仅重大场景】
  │     负责：年度报告、重大通报、战略性文稿
  │     触发条件：厂长明确说"这个很重要"或涉及对外发布的正式文件
  │     原因：opus 级别的深度思考，确保重大文稿零失误
  │
  └──→ logic（推理引擎 · DeepSeek-R1）【数据密集型】
        负责：经营分析报告中的数据计算和趋势分析
        触发条件：报告中涉及复杂数据对比、同比环比计算
        原因：R1 的推理能力处理数据分析更准确
```

### 分工矩阵

| 文稿类型 | 主执行 Agent | 备选 Agent | 说明 |
|----------|-------------|-----------|------|
| A1 产品推广 | deep | jimmy | 简单的 jimmy 自己写 |
| A2 客户案例 | deep | jimmy | |
| A3 工厂日常 | deep | jimmy | 最短最简单，jimmy 也能写 |
| A4 行业洞察 | deep | kitt | 深度观点可能需要 kitt |
| B1 考核通报 | deep | kitt | 重大事故通报走 kitt |
| B2 工作报告 | deep + logic | kitt | logic 算数据，deep 写文字 |
| B3 员工评语 | deep | jimmy | |
| B4 会议纪要 | deep | jimmy | |
| C1 报价回复 | deep | jimmy | |
| C2 售后回复 | deep | jimmy | |
| C3 节日问候 | jimmy | - | 太短了，jimmy 直接写 |
| D1 抖音15秒 | main | deep | |
| D2 案例视频 | main | deep | |
| D3 YouTube讲解 | main | deep | |
| E1 晨会发言 | deep | kitt | 重要场合走 kitt |

### 成本控制
- 日常文稿 90% 走 deep（免费）
- 视频脚本走 main（Gemini CLI 免费）
- jimmy 只做调度 + 简单文稿（付费但便宜）
- kitt 仅重大场合（控制调用频次）

## 4. 质量保证流程

### 三层质检机制

```
第一层：模板约束（写之前）
  │  deep/main 收到的不是裸指令，而是完整的提示词模板 + 变量
  │  模板已经内置了厂长风格要求、字数限制、格式规范
  │  → 从源头保证方向不跑偏
  │
第二层：jimmy 审稿（写完后）
  │  jimmy 收到 deep/main 的初稿后，用以下清单快速检查：
  │  □ 风格检查：有没有"赋能""闭环""抓手"等禁忌词？
  │  □ 字数检查：是否在模板要求的字数范围内？
  │  □ 格式检查：落款、日期、标题格式是否正确？
  │  □ 数据检查：厂长提供的数据是否准确引用？
  │  □ 脱敏检查：客户真名是否已替换？（朋友圈/对外文稿）
  │  → 不合格则打回 deep 重写，附修改意见
  │
第三层：厂长终审（交付后）
  │  jimmy 把文稿交给厂长，附一句话说明：
  │  "通报写好了，表扬张伟发现主轴异响，奖励500+积分20。看看有没有要改的？"
  │  → 厂长说"行"就发，说"改XX"就改
```

### 风格守护规则（内置到所有文稿提示词中）

```
## 厂长风格红线（所有文稿必须遵守）

### 必须有的：
- 数据说话：能用数字的不用形容词
- 场景切入：用具体的人、事、时间开头，不用空话
- 一针见血：每句话都有信息量，删掉不影响意思的字就删
- 江湖气：说人话，像老板跟人聊天，不像秘书写公文

### 绝对不能有的：
- 企业咨询废话：赋能、闭环、抓手、颗粒度、对齐、拉通
- 官腔套话：在领导的正确指导下、高度重视、深入贯彻
- 鸡汤废话：不忘初心、砥砺前行、携手共进
- 学术腔：综上所述、由此可见、不难发现
- 过度修饰：震撼、重磅、史诗级、颠覆性
```

### 持续优化机制
1. 厂长每次修改文稿，jimmy 记录修改内容到 `memory/03_语义记忆/厂长文稿修改记录.md`
2. 每积累 10 次修改，kitt 分析修改模式，更新风格规则
3. 提示词模板每月迭代一次，基于实际使用反馈

## 5. 实施步骤

### 第一步：基础设施（今天就能做）

**目标**：让 jimmy 能识别文稿请求并路由

**具体动作**：
1. 在 jimmy 的系统提示词中加入文稿路由规则（第2节的路由树）
2. 在 jimmy 的系统提示词中加入风格守护规则（第4节的红线）
3. 确认 deep agent 可正常调用（`sessions_spawn(agentId="deep")`）

**验证**：厂长说"写个通报"，jimmy 能正确识别并派发给 deep

---

### 第二步：模板注入（1-2天）

**目标**：deep/main 收到任务时，自动加载对应的提示词模板

**具体动作**：
1. 将 `实战提示词系统v2.md` 的 17 个模板拆分为独立文件：
   ```
   memory/02_知识库/文稿模板/
   ├── A1_产品推广.md
   ├── A2_客户案例.md
   ├── A3_工厂日常.md
   ├── A4_行业洞察.md
   ├── B1_考核通报.md
   ├── B2_工作报告.md
   ├── B3_员工评语.md
   ├── B4_会议纪要.md
   ├── C1_报价回复.md
   ├── C2_售后回复.md
   ├── C3_节日问候.md
   ├── D1_抖音15秒.md
   ├── D2_案例视频.md
   ├── D3_YouTube讲解.md
   ├── E1_晨会发言.md
   └── _INDEX.md          ← 模板索引，jimmy 用来查找
   ```
2. jimmy 路由时，读取对应模板文件，拼接厂长提供的变量，发给执行 agent
3. 每个模板文件包含：场景说明 + 输入变量 + 提示词 + 输出格式

**验证**：厂长说"写个朋友圈推广新设备1325"，deep 收到的是完整的 A1 模板 + 变量

---

### 第三步：质检闭环（第3-4天）

**目标**：jimmy 能自动审稿，不合格打回重写

**具体动作**：
1. 在 jimmy 的系统提示词中加入质检清单（第4节的三层质检）
2. 建立 `memory/03_语义记忆/厂长文稿修改记录.md`，记录每次厂长的修改
3. 测试 5 种常见文稿类型，确保质检流程跑通

**验证**：生成一篇带"赋能"的通报 → jimmy 自动识别并要求 deep 重写

---

### 第四步：优化迭代（第5-7天）

**目标**：根据实际使用反馈优化

**具体动作**：
1. 厂长实际使用 3-5 天，积累修改记录
2. kitt 分析修改模式，输出优化建议
3. 更新提示词模板和风格规则
4. 新增厂长常用但模板未覆盖的文稿类型

**验证**：文稿一次通过率从 ~60% 提升到 ~85%

---

### 第五步：扩展新类型（持续）

**目标**：未来加新文稿类型零成本

**扩展流程**：
1. 厂长说"我需要一种新的文稿类型，比如招聘启事"
2. kitt 设计提示词模板（参考现有模板结构）
3. 新建 `memory/02_知识库/文稿模板/F1_招聘启事.md`
4. 在 `_INDEX.md` 中注册新模板
5. 在 jimmy 路由规则中加入新的触发词
6. 完成，下次厂长说"写个招聘启事"就能用

## 6. 示例

```

  ① 意图识别：通报 → B1 考核通报 → 表扬类

     - 通报类型：表扬
     - 当事人：销售部（重点表扬张磊）
     - 事件描述：本周签约8单，回款120万，张磊个人签约3单
     - 处理决定：（未提供，jimmy 不追问，deep 按惯例拟定）
```
