# 外部碰撞规则 v2.0

> 核心：PinchTab 大幅降低 token 成本，可以放心大胆碰撞迭代，充分使用 Perplexity 高级模型（除 Max 外全开放）

---

## 一、什么时候需要碰撞

### 必须碰撞（不碰撞会出错）
- 需要**实时信息**：价格、政策、新闻、竞品动态（内部模型没有最新数据）
- 需要**多源交叉验证**：重大决策前，一个模型说的不够，要第二个视角
- 需要**超出内部能力**的推理：数学证明失败、架构方案拿不准、中文表达不地道

### 建议碰撞（碰撞效果更好）
- 厂长说"帮我查一下"/"最新的"/"现在市场上"
- 方案设计完成后需要**找漏洞**
- 写完内容需要**独立视角审查**
- 涉及**行业数据/市场分析**（内部模型数据过时）

### 不需要碰撞（浪费额度）
- 简单问答、记忆查询、文件操作
- 内部模型能搞定的代码/文案
- 已有明确答案的事实性问题
- 日常对话、配置变更

## 二、谁去碰撞

### 碰撞执行者：jimmy 用 PinchTab 直接碰撞（v2.0 重大升级）

**2026-03-13 更新**：安装 PinchTab 后，浏览器操作从截图模式（10000 tokens/页）降到 Accessibility Tree 模式（800 tokens/页），**省 13 倍成本**。

**新策略**：
- jimmy 自己用 PinchTab 操作 Perplexity，不再派发子 agent
- Token 成本大幅下降，可以放心多次迭代、深度碰撞
- 思考模式默认开启，不再心疼 token

**流程**：
```bash
~/bin/pinchtab nav https://www.perplexity.ai
sleep 3
~/bin/pinchtab snap -i -c  # 获取可交互元素
~/bin/pinchtab click <模型按钮ref>
~/bin/pinchtab type <输入框ref> "<问题>"
~/bin/pinchtab click <提交按钮ref>
sleep 30  # 等待思考模式回复
~/bin/pinchtab text  # 提取回复（~800 tokens）
```

### 串行规则（防限流）
- Perplexity 碰撞任务一次只派一个，完成后再派下一个
- 不需要碰撞的任务可以并行派发
- 同一模型连续碰撞间隔 ≥30 秒

### 小马拉大车原则
- 子 agent（main/deep）是搬运工+整理者，Perplexity 上的顶级模型是大脑
- 子 agent 负责：开浏览器、提交问题、提取结果、整理格式、写入文件
- Perplexity 模型负责：写核心内容（文案、代码、方案、分析）
- 这样用最便宜的 agent 调用最强的模型，成本最低质量最高

### 模型 × 任务匹配
| 任务类型 | 推荐 Perplexity 模型 |
|----------|---------------------|
| 中文内容/国内市场 | Kimi K2.5 |
| 创意文案/多语言 | GPT-5.3 |
| 商业分析/反向验证 | Grok 4.2 |
| 架构设计/代码 | Claude 4.6 |
| 快速查证 | Sonar |
| 长文档/多模态 | Gemini 3.1 Pro |

## 四、防限流策略

### Perplexity Pro 限制
- Pro 会员有每日查询额度（非无限）
- 思考模式消耗更多额度
- 高频调用可能触发速率限制

### 防限流策略（v2.0 放宽）

**Token 成本大幅下降后的新策略**：

1. **合并查询**：仍然推荐，但不再强制
   - 可以分步碰撞、多次迭代，不用担心 token 成本

2. **每日碰撞预算（已放开）**：
   - Sonar：不限
   - 思考模式模型（GPT-5.4/Grok/Claude/Kimi/Gemini）：**按需使用，不再限制次数**
   - 唯一限制：避免触发 Perplexity 的速率限制（同模型间隔 ≥30s）

3. **间隔控制**（防限流）：
   - 同一模型连续碰撞间隔 ≥30 秒
   - 不同模型切换间隔 ≥10 秒

4. **缓存意识**：
   - 同一个问题 24 小时内不重复碰撞
   - 碰撞结果写入 `memory/shared/` 供复用

## 五、碰撞操作流程（jimmy 用 PinchTab 执行）

```bash
# 1. 导航到 Perplexity
~/bin/pinchtab nav https://www.perplexity.ai
sleep 3

# 2. 获取页面元素
~/bin/pinchtab snap -i -c

# 3. 选择模型（根据 snap 结果找到模型按钮的 ref）
~/bin/pinchtab click <模型按钮ref>

# 4. 确认思考模式已开启（默认开启）

# 5. 输入问题
~/bin/pinchtab type <输入框ref> "<问题>"

# 6. 提交
~/bin/pinchtab click <提交按钮ref>

# 7. 等待回复（思考模式需要 30-60s）
sleep 30

# 8. 提取回复（~800 tokens，比截图省 13 倍）
~/bin/pinchtab text
```

**关键优势**：
- 每页只需 800 tokens（之前截图 10000 tokens）
- 可以多次迭代、追问、验证，不心疼成本
- 稳定的 ref 定位，不需要坐标猜测

## 六、碰撞结果处理

1. **直接回复厂长**：碰撞结果就是最终答案 → 整理后直接给
2. **喂给子 agent**：碰撞结果是中间材料 → 作为 context 传给 deep/logic/kitt
3. **写入记忆**：重要碰撞结果 → 写入 `memory/shared/碰撞结果_YYYY-MM-DD.md`
4. **多模型交叉**：重大决策 → 至少碰撞 2 个不同模型，对比后给厂长
