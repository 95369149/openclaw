# 模型能力路由表 v3.0

> 目的：让 Kitt/Jimmy 在任何会话、任何模型切换场景下，都按"模型特质 × 擅长领域 × 当前稳定性"进行路由。
> 生效级别：P0 行为规范补充文件
> 最后更新：2026-03-13
> 依赖：排兵布阵.md v9.0（唯一编制权威源）
> 若与 openclaw.json / 排兵布阵.md 冲突，以其为准。

## 总原则
1. **先看任务性质，再选模型**。
2. **能力匹配优先于成本**。
3. **稳定性优先于便宜**；链路不稳的模型即使便宜也降级。
4. **能主动切换就主动切换**，不要让不合适的模型硬扛。
5. **最终目标是结果质量、连续性、不中断会话**。

## 路由决策顺序
1. 判断任务属于哪一类：推理 / 代码 / 多模态 / 检索整理 / 中文表达 / 外部验证
2. 判断是否有高风险：不可逆操作、架构级决策、关键配置、资金/组织类判断
3. 检查链路是否正常：provider 可用、联网正常、相关工具可用
4. 选择最合适模型/Agent
5. 若首选不稳定，立刻切换备选，不勉强坚持

## 模型/Agent 专长表

### jimmy（L0 调度中枢）
- 当前模型：mynewapi/claude-sonnet-4-6
- 定位：调度中枢、短任务直出、浏览器/外链碰撞、验收
- 适合：状态查询、短回复、路由判断、轻量汇总、调用外部工具
- 不适合：长文重写、复杂代码、大型架构推理

### deep（L1 主力牛马）
- 当前模型：mygptapi/gpt-5.4
- 特长：中文写作、代码、批量处理、脚本、结构化产出
- 适合：
  - 写代码 / 修 bug / 自动化脚本
  - 长文报告 / 方案初稿 / 内容生产
  - 批量整理 / 数据清洗 / X 摘要
- 备选触发：当任务同时需要极强推理，再升级 kitt

### main（L1 多模态）
- 当前模型：google-gemini-cli/gemini-3-pro-preview
- 特长：多模态、长文档、图片/视频/PDF、大上下文吞吐
- 适合：
  - 图片、视频、PDF、长文档理解
  - 海量资料消化
  - 免费高频资料摄取
- 备选触发：若视觉/文档链路受限，再由 jimmy + 工具链兜底

### kitt（L1 深度推理）
- 当前模型：mynewapi/claude-opus-4-6
- 特长：深度推理、架构设计、重大决策、复杂 SOP、审核
- 适合：
  - 超过 2 步推理
  - 架构设计 / 方案 PK / 不可逆决策
  - 复杂规则设计 / 风险审查 / 质量验收
- 使用原则：慎用，但关键任务必须上

## 任务类型 → 默认路由
- **架构 / 战略 / 重大决策 / SOP 设计** → kitt
- **代码 / 自动化 / 重构 / 批处理 / 中文长文** → deep
- **图片 / 视频 / PDF / 超长文档 / 视觉任务** → main
- **短答 / 状态 / 调度 / 外部碰撞组织** → jimmy
- **需要联网事实核验** → jimmy 组织 web_search / browser / Perplexity
- **需要二次审查** → deep/main 完成初稿后，kitt 审核

## 特殊规则
- **不允许因为当前模型就在手上，就让它硬做不擅长的事。**
- **不允许因为省钱，选择明显不稳定或不匹配的模型，导致会话中断。**
- **涉及核心配置、系统架构、记忆规范变更时，优先 kitt 或由 jimmy 调度更强模型参与。**
- **外部世界变化快的任务，必须允许调用联网能力或外部强模型，不闭门造车。**

## 失败降级策略
1. 首选模型失败 → 切同类备选
2. 同类备选失败 → 切 jimmy + 工具链 / 人工拆解
3. 高风险任务不得因失败而草率降级到不擅长模型硬做
4. 始终保留"稳定完成"优先级高于"理论最优"

## 一句话标准
> 不是哪个模型便宜就用哪个，也不是哪个当前在场就用哪个；而是谁最适合这件事、谁最稳定、谁最可能把结果做对，就用谁。
