> 来源：GPT-5.2 第三波建议（2026-02-22）
> 主题：数据底座 + 四条业务流水线 + 人审闸门

---

## 一、数据底座：Excel 5 表结构

加一个 DataOps 子角色（工兵-代码兼职），专门做 Excel 读写，其他 Agent 不直接改 Excel。

### Leads（线索表）
LeadID、公司名、来源、联系人、角色、产品兴趣、国家/城市、状态、负责人、最近跟进日期、下次动作、评分、证据链接集合

### Suppliers（供应商表）
SupplierID、供应商名、国家地区、关键物料、交期(天)、MOQ、付款条款、历史准交率、最近异常、风险等级、替代供应商

### Materials（物料表）
MaterialID、物料名、规格、关键供应商、可替代物料、认证周期(天)

### Inventory（库存表）
MaterialID、现库存、在途、日均消耗、可用天数(自动算)、安全库存、缺口(自动算)

### EventsLog（事件日志）
时间、任务类型、涉及对象ID、结论、证据URL、执行链路、质检分、是否人审

## 二、供应链风险公式

- 断料风险：`可用天数 < 交期 + 缓冲天数(7-14天)` → 触发预警
- 单一来源风险：某物料仅1家供应商 → 风险+1档
- 外部风险必须带 URL + 日期，写入 EventsLog

### 预警输出格式（行动单）
- 影响物料/供应商
- 最晚下单日期（或最晚转单日期）
- 建议动作（备料/加急/改替代料/临时双供/客户交期沟通）
- 负责人（采购/计划/销售）+ 截止时间

## 三、销售流水线（S1 证据驱动线索卡）

1. Kitt 从 Leads 抽取缺失字段 → 生成"需补证据清单"
2. 侦察兵补公司信息（只写证据，不写结论）
3. 工兵生成：A/B/C评分 + 跟进路径 + 可直接发的话术
4. 质检：评分理由是否指向证据URL、是否有下一步动作

## 四、营销审批流（M2 可控闸门）

必填项：目标行业、应用场景、核心参数、禁语清单、引用口径
- 工兵出3版（保守/标准/激进）+ 主张清单 + 引用链接
- 质检只做"可发布性判定 + 修改指令"，不改稿

## 七、WPS 单文件落地策略（GPT-5.2 第四波）

### 硬规则
1. 统一 `.xlsx` 格式，禁止 `.et`/`.xls`
2. 单写原则：只有 DataOps 可以写回 Excel，其他 Agent 只输出 patch
3. 每次写回必须追加 EventsLog（最轻量审计日志）
4. 每行必须有不可变主键（LeadID/SupplierID/MaterialID）
5. 任何结论句必须指向 evidence_urls，没证据只能写"假设/待确认"

### DataOps 4 个固定动作
1. `load_workbook()` — 读取 5 张表
2. `validate_schema()` — 校验列名、ID唯一、日期格式
3. `apply_patches(patches[])` — 应用 Agent 输出的 JSON patch
4. `atomic_save()` — 先写 tmp 再替换，防断电损坏

### Patch 统一结构
```json
{
  "sheet": "Leads",
  "key": "L001",
  "set": {"score": "A", "next_action": "发资料"},
  "evidence_urls": ["https://..."],
  "comment": "官网显示年采购额>500万"
}
```

### 四条业务线写回点

| 业务线 | 谁写回 | 写回哪些列 | 高风险闸门 |
|--------|--------|-----------|-----------|
| S1/S2 销售 | 工兵→DataOps | score/next_action/owner/next_followup_date | 报价/承诺交期/合同 |
| SC1/SC2 供应链 | 工兵→DataOps | risk_level/last_event/evidence_urls | 供应中断预警 |
| IM1/IM2 内部 | 工兵→Artifacts | SOP模板 | 无（low risk） |
| M1/M2 营销 | 工兵→Artifacts | 文案+主张清单 | 对外发布/PR |
