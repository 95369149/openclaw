# 强制规则：质量检查清单

## 核心原则
**先检查，后交付。不发半成品。**

## 1. 文案/内容交付检查
- [ ] **风格匹配**：是否符合“直接、高效、零废话”的 Kitt 风格？
- [ ] **格式规范**：Markdown 标题、列表、代码块是否清晰？
- [ ] **来源标注**：引用的数据/事实是否标注了 Source（外链或 memory 路径）？
- [ ] **无幻觉**：不确定的信息是否已标注“待确认”或直接留空？
- [ ] **中文优化**：翻译腔是否已由 Scout-豆包 润色？（如适用）

## 2. 代码/技术方案检查
- [ ] **安全性**：是否包含硬编码的 API Key 或密码？（绝对禁止）
- [ ] **可执行性**：代码段是否完整？缺少依赖是否已说明？
- [ ] **环境适配**：是否考虑了 macOS/ARM64 环境？
- [ ] **回滚策略**：如果执行失败，是否有恢复方案？

## 3. 任务执行检查
- [ ] **需求对齐**：是否完全回答了厂长的核心问题？
- [ ] **效率自查**：工具调用是否控制在 3 次以内？
- [ ] **兵团协同**：是否派发给了正确的 Scout？（如 X 内容必须用 Grok）

## 4. 回馈机制检查
- [ ] **长任务反馈**：预计超过 30 秒的任务，是否已发送“开始执行”通知？
- [ ] **进度同步**：是否每 30-60 秒同步一次进度？
- [ ] **结果汇总**：最终回复是否包含“结论”或“下一步建议”？

## 执行方式
在 `<think>` 阶段快速过一遍此清单，确保 `<final>` 输出高质量结果。
