# 自我进化协议 V2.0
# 外部碰撞驱动的持续进化机制

时间：2026-03-13
灵感来源：厂长建议 + 今天 Lyra V6.0 的成功实践

---

## 核心理念

**用浏览器 token（便宜）+ Perplexity 高级模型（外部碰撞）持续自我进化，而不是用自己的 token 闭门造车。**

---

## 工作流程

### 1. 侦察（Scout）
**频率**：每周日 20:00（`weekly_evolution_pipeline`）
**工具**：`web_search` + `browser` + `agent-reach`
**目标**：
- OpenClaw GitHub Discussions / Issues
- Reddit r/LocalLLaMA
- X/Twitter #OpenClaw
- OpenViking 更新
- 相关技术博客

**输出**：`memory/shared/evolution_scout_YYYY-MM-DD.json`

---

### 2. 碰撞（Collision）
**执行者**：jimmy（操作浏览器）
**平台**：Perplexity（厂长的 Pro 会员）
**模型选择**：
- 架构审查 → Claude Opus 4.6 Max
- 深度推理 → GPT-5.4 Thinking
- 反向验证 → Grok 4.1
- 中文内容 → Kimi K2.5

**输入**：
- 侦察发现的新内容
- 当前架构摘要（`大脑中枢.md` + `排兵布阵.md`）
- 具体问题："这些新东西对我们有什么启发？"

**输出**：`memory/shared/collision_result_YYYY-MM-DD.md`

---

### 3. 提案（Proposal）
**执行者**：kitt（深度推理）
**输入**：碰撞结果
**输出**：`memory/07_版本控制/进化提案_YYYY-MM-DD.md`

**格式**：
```markdown
## P0 提案（必须做）
- 标题
- 背景
- 具体改进
- 预期效果

## P1 提案（应该做）
...

## P2 提案（可以做）
...
```

---

### 4. 验收（Review）
**执行者**：厂长
**方式**：jimmy 把提案摘要发 Telegram
**决策**：
- 同意 → jimmy 执行或派 deep/kitt 落地
- 拒绝 → 归档到 `memory/90_归档/rejected_proposals/`
- 延期 → 标记 `pending`，下周再议

---

### 5. 落地（Implementation）
**执行者**：根据提案复杂度选择
- 配置变更 → jimmy
- 代码重构 → deep
- 架构升级 → kitt

**验证**：
- 改完后跑一次健康检查
- 更新相关文档
- 写入 `memory/2026-MM-DD.md`

---

## 成本对比

| 方式 | Token 消耗 | 质量 | 速度 |
|------|-----------|------|------|
| 闭门造车 | 高（用自己的 opus/sonnet） | 中（容易思维定式） | 慢 |
| 外部碰撞 | 低（浏览器几乎免费 + Perplexity Pro） | 高（吸收外部智慧） | 快 |
