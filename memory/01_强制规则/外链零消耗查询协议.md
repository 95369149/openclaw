# 外链零消耗查询协议 v1.0

## 问题
厂长问："有没有这么一个功能，我跟你聊天，你直接调用外链，不消耗 token？"

## 方案

### 核心思路
**派子 agent 去查 → 结果写文件 → jimmy 读文件回复**

这样外链的长回复不会进入主会话上下文，节省 token。

### 实现路径

#### 方式 1：脚本直接调用（最简单）
```bash
bash memory/scripts/external-query.sh "nitter 实例稳定性 2026" doubao
# 结果写入 memory/shared/external-query_YYYY-MM-DD_HH-MM-SS.md
# jimmy 读文件提取关键信息回复厂长
```

**优点**：
- 零 token 消耗（豆包免费，结果不进上下文）
- 立即可用

**缺点**：
- 需要手动触发（jimmy 判断后执行脚本）
- 豆包质量一般

#### 方式 2：子 agent + Perplexity（推荐）
```
厂长提问 → jimmy 判断需要外链 
→ sessions_spawn(main, task="用 Perplexity Sonar 查询 xxx，结果写入 memory/shared/xxx.md")
→ main 完成后 announce
→ jimmy 读文件，提取关键信息（<500 字）回复厂长
```

**优点**：
- Perplexity Sonar 免费且质量高
- 子 agent 的 token 不算在主会话
- 自动化流程

**缺点**：
- main 的 announce 消息还是会进主会话（但可以控制长度）

#### 方式 3：纯文件中转（零污染）
```
厂长提问 → jimmy 写查询请求到 memory/ops/query-queue.json
→ 独立 cron 任务每 5 分钟扫描 queue，调 Perplexity，结果写 memory/shared/
→ jimmy 心跳时检查新文件，主动推送摘要给厂长
```

**优点**：
- 完全零 token 消耗
- 主会话完全不受影响

**缺点**：
- 延迟（最多 5 分钟）
- 实现复杂

## 使用示例

**厂长问**："2026 年最稳定的 nitter 实例有哪些？"

**jimmy 判断**：需要最新信息 → 调外链

**执行**：
```bash
bash memory/scripts/external-query.sh "2026 年最稳定的 nitter 实例" doubao
```

**jimmy 回复**：
"查到了，2026 年推荐这 3 个实例：nitter.net、nitter.poast.org、nitter.privacydev.net。详细对比见 `memory/shared/external-query_2026-03-02_15-30-00.md`"

**token 消耗**：jimmy 的回复 <100 tokens，外链的 2000+ tokens 回复不进上下文。
