## 1. 守门决策表

### 风险等级定义

| 等级 | 含义 | 典型特征 |
|------|------|----------|
| CFG_LOW | 爆炸半径小，可自愈 | 不影响生产、不涉及凭据、不对外 |
| CFG_MEDIUM | 影响可控但需双重确认 | 影响外部可见面、知识体系、定时任务 |
| CFG_HIGH | 不可逆或影响全局 | 改配电盘、改供应链、改治理规则 |

### 签收人缩写

- **G** = guard 单签
- **G+K** = guard + kitt 双签
- **G+K+H** = guard + kitt + 厂长 三签

### 操作 → 风险 → 签收 映射表

| 操作类型 | 风险等级 | 签收人 | 说明 |
|----------|----------|--------|------|
| 改 cron（生产环境定时脚本） | CFG_MEDIUM | G+K | 可能导致批量错误执行或高频调用 |
| 改 cron（仅开发/测试、只读） | CFG_LOW | G | 爆炸半径小 |
| 改 agent 路由/模型（影响生产流量） | CFG_HIGH | G+K+H | 直接影响质量与成本 |
| 改 agent 路由/模型（仅新增备选 fallback，默认不启用） | CFG_MEDIUM | G+K | 先挂候选不立即生效 |
| 改 provider 配置（API key / baseUrl） | CFG_HIGH | G+K+H | 供应链与凭据高危操作 |
| 改 channel 配置（Telegram/Discord/WeChat） | CFG_MEDIUM | G+K | 影响外部可见面 |
| 删除 memory 内文件（记忆/规则类） | CFG_MEDIUM | G+K | 知识与规则丢失风险 |
| 删除 memory 外普通文件（临时输出） | CFG_LOW | G | 爆炸半径有限 |
| 发外部消息（系统级广播/批量触达） | CFG_MEDIUM | G+K | 合规/品牌风险 |
| 写/改 openclaw.json | CFG_HIGH | G+K+H | 整个系统的"配电盘" |
| 新增 agent | CFG_HIGH | G+K+H | 影响路由与风控边界 |
| 删除 agent | CFG_HIGH | G+K+H | 影响既有链路 |
| 新增/删除 skill | CFG_MEDIUM | G+K | 技能可放大行为半径 |
| 安装 MCP / 第三方工具 | CFG_HIGH | G+K+H | 供应链风险最高的操作之一 |
| 执行含 sudo/rm -rf/curl\|sh 的命令 | CFG_HIGH | G+K+H | 高危命令，必须人类知情 |
| 修改 SOUL.md/AGENTS.md/排兵布阵.md | CFG_HIGH | G+K+H | "宪法级"变更 |

## 2. scout 强制 / 豁免规则

### 2.1 强制侦察（不可豁免）

满足**任一项**即必须先跑 scout：

1. 架构设计或系统级方案（新系统、微服务拆分、数据流/权限设计）
2. 跨 3 个以上文件的代码协同修改
3. 有效代码改动 > 200 行
4. 没有明确实现路径（只给目标没给路线）
5. 涉及外链、竞品或第三方框架选型
6. 高风险 CONFIG_CHANGE（新增 provider / 替换主路由模型 / 改安全配置）
7. 厂长显式指示"先调研/对标"

### 2.2 可豁免条件

以下条件**全部满足**时，可跳过 scout 走 FAST 链：

| 条件 | 判断依据 | 示例 |
|------|----------|------|
| riskLevel=LOW 且 size=SMALL | task_meta 明确 | 改一条文案、调一个按钮 |
| 有成熟模板可直接套用 | memory 中有同类执行模板 | 标准 CI 脚本只改 repo 名 |
| 仅做润色/翻译，不改逻辑 | 任务描述仅涉及文字改写 | 优化一段错误提示文案 |
| 单文件 < 10 行显式小改 | 厂长明确给出具体改动 | 超时时间从 10s 改 15s |
| 仅在 sandbox/测试环境 | 不触及生产配置 | 本地跑 log 分析脚本 |

### 2.3 决策流程

```
收到任务 → 打 task_meta
  ├─ taskType ∈ {PLAN, CONFIG_CHANGE} → needs_scout = true
  ├─ 命中强制条件任一项 → needs_scout = true
  └─ 豁免条件全部满足 → needs_scout = false → FAST 链
      └─ 否则 → needs_scout = true → FULL 链
```

冲突处理：同时命中"强制"和"豁免"，以**强制启用 scout**为准。

## 3. 熔断参数

### 3.1 关键阈值

| 参数 | 值 | 原因 |
|------|-----|------|
| 连续失败触发熔断 | 2 次 | 一次可能偶发，连续两次是系统性问题 |
| 熔断冷却时长 | 30 分钟 | 覆盖多数 API 限流/故障恢复窗口 |
| 单日累计失败停用 | 20 次 | 超过说明当天该 agent 极不稳定 |
| RETRIABLE 最多重试 | 1 次 | LLM 重试收益递减，配合 2 次熔断更清晰 |
| RETRIABLE 重试间隔 | 15 秒 | 太短撞限流，太长用户觉得挂机 |
| RISK_ESCALATION 升级路径 | 执行 agent → jimmy → kitt → 厂长 | 逐级收敛上下文 |

### 3.2 错误分类

| 类别 | 定义 | 处理 |
|------|------|------|
| RETRIABLE | 网络超时、429 限流、临时不可用 | 等 15s 重试 1 次 |
| NON_RETRIABLE | 模型拒绝、格式错误、认证失败 | 不重试，直接走降级链 |
| RISK_ESCALATION | 输出含敏感内容、操作超权限 | 立即升级，不重试不降级 |

### 3.4 熔断后恢复

- 先从"全熔断"退到"限流运行"，观察 5 分钟
- 再从"限流"退到"正常"
- 每一步在 `ops/state.json` 记录时间戳与责任人
