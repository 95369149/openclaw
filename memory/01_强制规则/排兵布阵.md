## 设计原则

### 1. 调度、执行、审核分离

- 调度者不长期深度执行。
- 执行者不自行放行高风险结果。
- 审核者不接管普通生产任务。

### 2. 专岗优先于全能岗

- `scout` 查资料
- `deep` 干执行
- `main` 读多模态
- `sino` 管中文表达
- `guard` 守配置风险
- `kitt` 做终审

### 3. 多-agent 只用于可拆分任务

适合：调研→分析→产出→审核。
不适合：极短任务、强耦合配置手术、拆了更乱的任务。

### 4. 重要结果必须进入审核链

以下默认进入审核链：架构设计、配置变更、高风险脚本、对外正式内容、关键业务判断。

## 职责边界

### `jimmy`

**做**：接任务、判断路由、派发、汇总、对外统一回复、维护闭环。

**不做**：长期消化大资料、超长内容生产、终审裁决。

### `deep`

**做**：代码、脚本、自动化、批处理、技术文档初稿、结构化交付。

**不做**：终审、风险放行、战略拍板。

### `main`

**做**：图片/视频/PDF/长网页理解、长文本归纳、多模态证据读取。

**不做**：配置拍板、系统审计、最终业务判断。

### `kitt`

**做**：审架构、审复杂代码、审关键方案、识别漏洞和不一致、做重大决策质量门禁。

**不做**：普通流水生产、低价值批处理。

### `sino`

**做**：中文改写、润色、总结、营销文案、客服/销售语境、本地化表达。

**不做**：架构决策、高风险配置、系统级审核。

### `scout`

**做**：GitHub 对标、外链与公开资料侦察、竞品/框架/方法论收集、事实证据整理。

**不做**：最终拍板、高风险执行、配置修改。

### `guard`

**做**：配置变更前检查、schema/漂移/回滚校验、安全红线审查、供应链审计。

**不做**：普通问答、内容生产主力、业务结论拍板。

## 路由规则

### 总入口

所有需求先到 `jimmy`。`jimmy` 在 3 秒内判断：

1. 自己直做
2. 单 agent 派发（FAST 链）
3. 多 agent 协作（FULL 链）
4. 高风险待确认

> 详细 FAST / FULL 链路定义见 `路由与审核链.md` §2。
> sino / deep 分工矩阵见 `路由与审核链.md` §1。

### 单 agent 默认去向

| 任务类型                                 | 默认 agent |
| ---------------------------------------- | ---------- |
| 简单问答、轻量状态查询、轻量文件读写     | `jimmy`    |
| 代码、脚本、自动化、数据处理             | `deep`     |
| 图片、视频、PDF、长文档、网页视觉理解    | `main`     |
| 中文文案、改写、润色、总结、本地化表达   | `sino`     |
| GitHub、竞品、外链、情报收集             | `scout`    |
| 架构、战略、关键审查、复杂判断           | `kitt`     |
| 配置审计、风险检查、回滚核对、规则一致性 | `guard`    |

### 多 agent 协作

1. 调研 + 决策：`scout` → `kitt`
2. 多模态 + 执行：`main` → `deep`
3. 中文内容 + 审核：`sino` → `kitt`（对外正式稿强制）
4. 技术实现 + 审核：`deep` → `kitt`
5. 配置修改：执行方 → `guard` → 必要时 `kitt` → 人工确认
6. 技术写作 + 中文润色：`deep` → `sino`

### 禁止滥用多跳

- `scout` 不向下派发，只交事实
- `guard` 不向下派发，只交审计结论
- `sino` 不向下派发，只做中文表达
- `deep` 默认不派发
- 主要路由节点只有 `jimmy` 和 `kitt`

## 审核链

> 详细风险分级与签收矩阵见 `守门与熔断.md` §1。
> kitt 审核 SLA、抽查比例、配额见 `路由与审核链.md` §3。

- 技术审核：`deep` → `kitt`
- 方案审核：`scout` / `deep` / `main` → `kitt`
- 内容审核：`sino` → `kitt`（仅对外正式稿强制）
- 配置审核：执行方 → `guard` → 必要时 `kitt` → 人工确认

### 强制触发 `kitt`

1. 架构设计
2. 复杂代码改造
3. 对外正式长文
4. 高风险业务判断
5. 涉及 3 步以上复杂推理的关键决策

### 强制触发 `guard`

1. `openclaw.json` 变更
2. 路由规则变更
3. 密钥/凭据处理
4. 新 Skill / 新 MCP / 新依赖安装前审计
5. 回滚方案核对

---

## 供应链与安全规则（并入 `guard`）

1. 新 Skill / MCP / 第三方工具安装前必须审计。
2. 自动 `pip install` / `npm install` / 安装脚本视为高风险动作。
3. 审计范围包括：读取环境变量、写入 `~/.openclaw/`、`curl | sh`、base64 混淆、外发请求、凭据搜集行为。
4. 明文密钥不得写入配置文件，必须使用环境变量引用。
5. 配置变更必须带回滚方案。
