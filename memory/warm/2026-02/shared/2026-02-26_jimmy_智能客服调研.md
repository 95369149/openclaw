# 智能客服系统调研（Perplexity 碰撞）

**时间**: 2026-02-26 00:19
**来源**: Perplexity Sonar

## 推荐方案：Dify + FastGPT 协同

- **Dify**：对话引擎 + 工作流 + 通道整合（WhatsApp/邮件）
- **FastGPT**：知识库 + RAG + 故障诊断模块

## 五大需求实现

1. **24h 自动回复**：Dify/FastGPT 配置 7×24 客服机器人，LLM + RAG 自动回答
2. **WhatsApp + 邮件**：WhatsApp Business API（或 Mixdesk）+ 邮件网关（SMTP/IMAP）→ Webhook → Dify
3. **自动诊断故障**：报警码规则库 + 设备手册知识库 + IoT 数据（Modbus/OPC UA/MQTT）
4. **转人工**：关键词触发或连续 3 次未命中 → 自动创建工单 → 分配售后工程师
5. **成本低**：云服务 SaaS 模式，年成本数千～数万元

## 四方案对比

| 方案 | 优点 | 缺点 | 适配度 |
|------|------|------|--------|
| Coze | 低代码、拖拽式 | 不支持私有部署、故障诊断弱 | 简单客服 |
| Dify | 多语言、多LLM、工作流强 | 学习成本 | ⭐⭐⭐ 外贸多语言客服 |
| FastGPT | 开源、知识库+RAG强 | UI 不如 Dify | ⭐⭐⭐ 故障诊断 |
| 自建 | 100% 定制 | 成本高、周期长 | 大型集团 |

## 架构

```
用户入口（WhatsApp/邮件/官网）
  → 通道网关（WhatsApp Business API + 邮件网关）
    → Dify 对话引擎（意图识别：售前/售后/转人工）
      → FastGPT 知识库（设备手册 + 故障规则库 + 报价规则）
        → 设备 IoT 层（报警码/温度/电流/主轴转速）
          → 人工坐席 + 工单系统
```

## 落地节奏

- 第一阶段（1-2月）：Dify + FastGPT 云版，上线售前+常见售后（WhatsApp+邮件）
- 第二阶段（3-6月）：接入设备 IoT，完善故障诊断
- 第三阶段（6-12月）：私有化部署，接 CRM/ERP，预测性维护
