# 多Agent架构升级方案（Perplexity Claude Sonnet 4.6 Thinking）
> 来源：https://www.perplexity.ai/search/ni-shi-yi-ge-aiduo-agentxi-ton-nr1yrNX2QZaSyczjySBC6A
> 日期：2026-03-05

## 七个痛点根因
1. 工具调用次数限制 vs 外链读取需求 → 规则粒度太粗
2. logic 和 kitt 职责模糊 → 按能力而非决策权划分
3. 子 agent 写文件成功率 <30% → 原子性缺失
4. jimmy 上下文污染 → 无界上下文积累反模式
5. 记忆系统碎片化（5套机制）→ 按工具可用性而非访问模式演化
6. 心跳每55分钟消耗大量 token → 用完整 LLM 推理做连接保持
7. deep 的 Responses API 协议不匹配 → 缺少协议适配层

## 五个改进建议
A. logic+kitt 合并为 sage（按触发条件而非能力标签）
B. 子 agent 只返回 JSON，jimmy 统一写文件 ✅ 已完成
C. 记忆系统精简为三层（长期事实层/任务状态层/临时数据层）
D. 引入会话轮换机制（上下文水位监控，超55%触发压缩）
E. 心跳轻量化（脚本级检查替代完整 LLM 推理）

## 路线图
- 第1周：修复子agent写文件 ✅ 已完成
- 第2周：deep协议适配层 ✅ 已确认OpenClaw框架自动处理，无需额外操作
- 第3周：logic+kitt合并为sage，更新路由规则 ← 当前
- 第4周：jimmy上下文水位监控+压缩机制
- 第5-6周：记忆系统三层重构+心跳轻量化
