# 2026-03-05 Deep 框架升级分析

时间：2026-03-05 12:43 (GMT+8)

## 当前框架痛点
1. **权威源冲突**：`00_大脑中枢.md`写“排兵布阵 v6.0 为权威”，但实际`排兵布阵.md`已是 v7.0，且 deep/logic 模型标注与中枢不一致（metaapi vs mynewapi、thinking 开关描述不一致），存在“文档看起来都对但执行会偏”的漂移风险。
2. **规则重复与编号错误**：`SOUL.md`中“配置变更必须全量同步”出现重复（第8条重复两次），说明规则维护流程缺少去重校验，容易让执行者对“是否最新”产生不确定。
3. **路由与失败降级链不一致**：`SOUL.md`里 deep 失败降级链写“deep→main→jimmy”，而`排兵布阵.md`边界 case 里又写“deep 失败→main”，但更早版本历史常见“deep→kitt”；多处并存会导致值班时切换策略随缘。
4. **角色边界有重叠**：SOUL 中既强调“jimmy 只做调度+轻量回复”，又赋予其浏览器碰撞、模型选择与高风险审计；同时 kitt 也承担架构/决策/审核，造成“重大任务该谁拍板”偶发模糊。
5. **强制流程与实际工具约束有张力**：SOUL 对 `curl`/`wget`列为敏感命令需人工确认，但任务执行中又要求调用外链 API 做深度碰撞；缺少“子 Agent 在受控任务里可执行的白名单例外条款”。
