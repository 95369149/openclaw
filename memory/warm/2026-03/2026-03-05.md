# 2026-03-05 关键决策与系统升级记录

## 关键决策和原因
- **框架升级与缺陷修复**：确认 OpenClaw 多 Agent 框架存在子 agent 写文件失败率高（<30%）、上下文污染等痛点。决策：通过修改 `SOUL.md` 和派发模板，强制要求子 agent（如 deep、logic、main、kitt）以 JSON 格式返回结果而不自行写入文件，由主 agent (jimmy) 统一解析 JSON 并落地文件。这从根源上剥离了子 agent 的 IO 职责，大幅提高可靠性。
- **协议适配确认**：此前担心的 deep agent (gpt-5.3-codex) Responses API 协议不匹配问题，已确认由 OpenClaw 框架底层自动处理，无需在上层做额外修改。
- **模型和 API 状态**：`mynewapi` (claude-sonnet-4-6) 已恢复正常使用；`xjrouter` 仍然由于 auth 问题不可用；废弃了配置错误的 `metaapi`，将 deep agent 统一指向 `mygptapi`。

## 状态变更
- **系统配置**：更新了 `openclaw.json`，移除了失效的 `metaapi`，确保 `deep` 指向正确的 `mygptapi/gpt-5.3-codex`。重启了 gateway 使得配置生效。
- **工作流推进**：正在逐步执行 Perplexity 提供的第一优先级整改方案，即修改各子 agent 以及 jimmy 本身的 `SOUL.md`，以落实新的文件输出和回收协议。

## 经验教训
- 复杂的系统架构中，“事务性操作（如写文件）放在非事务性 LLM 调用里（token 可能耗尽）”是导致成功率低的根本原因。将“生成”与“持久化（写文件）”拆分为两个步骤由不同角色（子 agent 生成，主 agent 写入）执行是更稳健的设计模式。
- 定期通过外链模型（如 Claude Sonnet 4.6 Thinking）进行深度代码/架构 Review 是极有价值的，能快速定位如“无界上下文积累反模式”等系统级盲点。
