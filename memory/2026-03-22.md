## OpenClaw 多代理稳定性方案碰撞结论（外部碰撞摘要）

### 优先级排序（根治顺序）
1. **checkpoint 状态机**（根治层）- 断点恢复、续跑、任务接力
2. **外部 watchdog**（根治层）- 静默卡死、失联无人发现
3. **retry budget + idempotency + observability**（工程化层）
4. **真实 Chrome + CDP**（执行层增强）
5. **sessions_spawn + 审核代理**（治理层）
6. **轻量浏览器抓取层**（只读补刀层）

### 外部碰撞补充的工程关键词
- **lease / heartbeat**：worker 拿任务要续租，超时不续 = 视为死亡，任务回队列
- **job queue**：统一入队/领取/执行/完成/失败回退
- **retry budget**：每步最多重试次数 + 整体预算上限
- **idempotency**：每步加 key，防断点恢复后重复执行副作用
- **observability**：job_id/session_id/current_step/last_heartbeat_at/retry_count/lease_owner

### 核心结论
**先把 OpenClaw 当分布式任务系统修，再把它当多代理系统优化。**
