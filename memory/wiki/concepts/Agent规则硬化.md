# Agent规则硬化

> 把"写在prompt/文档里的规则"升级为"runtime中被强制执行的代码级gate"。

## 核心要点

- 现有规则（路由、触发条件、记忆协议）大多停留在SOUL/AGENTS文档层，未变成代码gate
- 硬化目标：调度/执行/审核分离 → 路由模式默认开启 → 高风险输出必须走审核链
- 强制触发kitt：架构设计、复杂代码改造、对外正式长文、高风险业务判断、3步以上复杂推理
- 强制触发guard：openclaw.json变更、密钥处理、新skill/MCP安装前审计、回滚方案核对
- 强制触发scout：跨3个以上文件协同修改、有效代码改动>200行、涉及外链/竞品/框架选型
- 最小可落地路径：先做拦截层（jimmy收到任务后的分类判断），再做审核链（kitt/guard的gate函数）

## 对红太阳的启示

- OpenClaw多Agent系统的可靠性取决于规则是否真正被执行，而非是否被写下来
- 优先级：任务完成标准 > 项目既有风格 > 用户明确指令（高于讨好用户情绪）
- 硬化改造应渐进上线，不推翻重做——先加拦截层，再逐步把文档规则转成代码断言
