## 🟡 功能缺陷

### 3. main.py 772行，所有路由挤在一个文件
所有 API 端点（accounts CRUD、触达、评分、采集、设置）全在 main.py，没有拆分 router。维护困难，容易冲突。

### 4. ImportYeti _search_apify 吞掉所有异常
`importyeti.py` 的 search() 方法在官方 API 失败时 `except Exception: pass`，静默切换到 Apify，不记录任何日志。如果两个通道都有问题，排查困难。

### 5. 触达模板只有8个触点，缺少多语言
`touch_templates.py` 只有中文模板，但目标客户是海外企业。邮件内容混合中英文（"Hi {contact_name}" + 中文正文），不专业。

### 6. 线索评分维度单一
`lead_scoring.py` 把所有信息丢给 LLM 打分，没有本地规则引擎。完全依赖 LLM 意味着：无 API Key 就没有评分能力，且每次评分都消耗 token。应该有本地规则兜底（如：有海关记录+相关行业=A2，无信号=C）。

### 7. SQLite 单文件数据库，无备份机制
`growth_system.db` 是唯一数据存储，没有定时备份。数据丢了就全没了。

### 8. 前端 API 地址硬编码 127.0.0.1:8000
`sources/page.tsx` 里 `const API = process.env.NEXT_PUBLIC_API_BASE_URL ?? "http://127.0.0.1:8000"`，其他页面用 `lib/api.ts`。不一致，部署时容易出问题。

### 9. 无去重逻辑
ImportYeti 和 Apollo 采集的线索没有跨源去重。同一家公司可能被重复入库多次。

### 10. 触达节奏无自动执行
`touch_templates.py` 只是模板定义，没有定时任务自动推进触达。需要人工在前端点击才能推进到下一个触点。

## 🟢 优化建议

### 11. 加入 Snovio 连接器
README 提到整合 Snovio，但 source_connectors/ 里没有实现。Snovio 的邮箱验证能力可以补全 Apollo 的短板。

### 12. Dashboard 缺少时间维度
dashboard 只有当前快照数据，没有趋势图（本周新增线索、回复率变化等）。

### 13. 缺少数据导出
没有 CSV/Excel 导出功能，销售团队无法离线使用数据。

### 14. 缺少 webhook/通知
新线索入库、客户回复等关键事件没有通知机制（邮件/微信/钉钉）。

### 15. settings_manager 直接读写 .env 文件
`settings_manager.py` 直接操作 `backend/.env`，没有文件锁。并发写入可能损坏文件。
