# skills.sh 吸收与替换清单 v1

时间：2026-04-09 07:08 CST
负责人：Kitt
来源：基于 `skills.sh` 对 inferen-sh / yofine 相关 skill 的一轮定向筛选，目标是找出**最值得接入当前 OpenClaw / memory / wiki / 内容 / 图形体系**的 10 个 skill，并判断本地现有 skill 中哪些应升级、替换或吸收外部结构。

---

## 一、总判断

本轮结论不是“全装”，而是分成两类：

1. **直接接入或持续保留参考**
2. **吸收其结构，用来升级本地 skill**

核心原则：
- 不把系统做成 skill 拼装市场
- 优先升级我们自己的骨架
- 外部 skill 的真正价值，往往在**结构 / 方法 / 输入输出约束**，而不是 skill 名字本身

---

## 二、Top 10 候选清单

### P0 / 第一梯队（最值得优先吸收）

#### 1. `inferen-sh/skills/ai-rag-pipeline`
**定位**：研究 / 检索 / 证据链流水线

**价值**：
- 把 search / extract / summarize / cite / contradiction check 串成标准 RAG 流
- 和我们当前 `memory-wiki + compiled knowledge + claims/evidence` 路线高度同向

**建议角色**：
- 吸收其 pipeline 结构，不建议原样照搬
- 用于升级 `learning_ingest_batch` 和 wiki 编译流

**适配本地**：
- `learning_ingest_batch`
- `memory-wiki bridge/import/compile` 周边流程
- 后续 claim/evidence 规范

---

#### 2. `inferen-sh/skills/agent-browser`
**定位**：浏览器自动化标准件

**价值**：
- 工作流非常清晰：open → interact → re-snapshot → close
- `@e` ref / session / 录像调试都很工程化
- 和我们已经确立的主刀方向一致

**建议角色**：
- 继续作为浏览器主链参考
- 用它反向升级我们的浏览器 SOP、故障恢复和提示词规则

**适配本地**：
- `agent-browser`
- 外链读取 / 登录流 / 页面操作 SOP

---

#### 3. `yofine/skills/blueprinter`
**定位**：工程图纸风格输出规范

**价值**：
- 高信息密度、克制、平面、严格对齐
- 非常适合架构图 / 流程图 / SOP / 运营闭环图

**建议角色**：
- 已吸收成本地《Kitt Blueprint Spec v1.0》
- 后续继续作为表现层规范母本

**适配本地**：
- `memory/shared/2026-04-08_中文图纸风格规范_Kitt_Blueprint_Spec_v1.0.md`
- 架构图 / 流程图 / SOP 图统一输出

---

#### 4. `inferen-sh/skills/data-visualization`
**定位**：数据图表达规范 + 图表 recipe

**价值**：
- 给出了选图逻辑、标题规则、颜色控制、KPI 卡片、折线/条形/热力图等明确规范
- 可和 blueprinter 组成“图纸风格 + 数据表达”的双规范

**建议角色**：
- 不急着原样安装
- 优先提炼为我们的“数据图子规范”

**适配本地**：
- `baoyu-infographic`
- `slides`
- `Skywork-ppt`
- 经营日报 / 线索转化 / 生产看板

---

#### 5. `inferen-sh/skills/competitor-teardown`
**定位**：竞品拆解模板

**价值**：
- 7 层结构完整：产品 / 定价 / 定位 / traction / reviews / content / team
- 很适合做行业、竞品、同行官网、渠道打法拆解

**建议角色**：
- 吸收框架，优先做成本地竞品分析 SOP
- 不建议机械原样照搬

**适配本地**：
- `biz-reporter`
- 行业分析 / 同行拆解 / 方案对标

---

### P1 / 第二梯队（值得用于升级内容 / 视频 / 分发）

#### 6. `inferen-sh/skills/technical-blog-writing`
**定位**：技术文章 / 架构说明 / benchmark / 复盘 写作框架

**价值**：
- 对教程、深度解释、事故复盘、基准测试、架构文的结构总结得比较成熟
- 适合提升我们文档、SOP、技术说明的正式度

**建议角色**：
- 吸收模板与写作规则
- 不一定需要独立安装

**适配本地**：
- `doc`
- `baoyu-format-markdown`
- 各类结构说明 / 技术说明 / 复盘文

---

#### 7. `inferen-sh/skills/remotion-render`
**定位**：React / Remotion 可控视频渲染

**价值**：
- 适合“工程图 / 数据图 / 培训步骤 / 讲解卡片”做成可控视频
- 和纯 AI 视频相比，更适合需要严格布局和稳定输出的场景

**建议角色**：
- 作为新的视频分支补链
- 不替换现有 AI 视频 skill

**适配本地**：
- `video-factory`
- `jianying-video-gen`
- 培训视频 / 架构讲解动画 / 数据汇报短视频

---

#### 8. `inferen-sh/skills/twitter-automation`
**定位**：X/Twitter 动作自动化

**价值**：
- 发帖、带媒体、点赞、转发、DM、拉用户资料这一层动作比较完整
- 适合我们后续做 X 分发 / 线程发布的动作链参考

**风险**：
- 强依赖 inference.sh / X 集成
- 当前我们环境对 X 读取与自动化仍有现实约束

**建议角色**：
- 先观察，不作为短期核心底座
- 吸收动作分层思路即可

**适配本地**：
- `x-reader`
- `x-writer`
- `baoyu-post-to-x`

---

### P2 / 第三梯队（偏底层方法或通用底座）

#### 9. `inferen-sh/skills/web-search`
**定位**：统一搜索入口 / 研究工作流模板

**价值**：
- 不是替代 OpenClaw 内置 `web_search`
- 主要价值在于“搜完之后如何组织、如何继续深挖”

**建议角色**：
- 吸收为 research SOP 的一部分

**适配本地**：
- 外部碰撞规则
- `biz-reporter`
- 研究工作流

---

#### 10. `inferen-sh/skills/python-executor`
**定位**：可执行数据 / 图表 / 清洗处理底座

**价值**：
- 很多高级 skill 实际都依赖它，说明它是通用底层能力
- 对图表生成、CSV/Excel 清洗、矩阵生成很有用

**建议角色**：
- 视为通用底座思路，不一定单独强调为前台 skill

**适配本地**：
- 图表生成
- 数据清洗
- positioning map / KPI 卡片 / 汇总图

## 三、对现有本地 skill 的升级/替换判断

### 1. `baoyu-infographic` → 应升级，不建议删除
**升级方向**：
- 吸收 `blueprinter + data-visualization`
- 拆成两种模式：
  - Blueprint 模式：架构图 / 流程图 / SOP 图
  - Viz 模式：数据图 / KPI 图 / 汇报图

---

### 2. `slides` / `Skywork-ppt` → 应升级表达体系
**问题**：容易滑向花哨 PPT 风

**升级方向**：
- 按工程图 + 数据图 + 技术写作结构收敛
- 统一白底、线框、黑灰主色、单色强调、短句表达

---

### 3. `biz-reporter` → 必须升级
**升级方向**：
- 吸收 `competitor-teardown + ai-rag-pipeline`
- 增加：
  - claim / evidence 分层
  - contradiction 标注
  - executive summary
  - 多源证据整合

---

### 4. `x-reader` / `x-writer` → 应升级，不急着替换
**升级方向**：
- 吸收 `twitter-automation` 的动作分层
- 增加权限/登录态检查
- 失败时走明确降级路线

---

### 5. `doc` / `baoyu-format-markdown` → 应升级模板层
**升级方向**：
- 吸收 `technical-blog-writing` 的固定模板
- 标准化几类输出：
  - 教程
  - 架构说明
  - 事故复盘
  - benchmark
  - 决策备忘录

---

### 6. `video-factory` / `jianying-video-gen` → 不替换，补新分支
**升级方向**：
- 保留原有 AI 视频链
- 新增 `remotion-render` 这条“工程型、可控视频”链

---

## 四、建议的三步优先动作

### 动作 1：升级 `learning_ingest_batch`
**吸收来源**：`ai-rag-pipeline`

**目标**：

**目标**：
形成统一：
- 架构图规范
- 流程图规范

---

**吸收来源**：`competitor-teardown + technical-blog-writing`

**目标**：
让竞品 / 行业 / 方案报告彻底结构化，不再松散。

---

## 五、最终原则

1. **外部 skill 先吸收结构，再决定是否安装**
2. **优先升级本地 skill 骨架，不盲目新增并列 skill**
3. **所有接入都要服务当前主线：memory-wiki / ingest / 图形表达 / 报告结构化**
4. **先做 P0，再看 P1/P2，避免体系膨胀**
