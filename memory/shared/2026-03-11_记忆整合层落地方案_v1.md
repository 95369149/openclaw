# 记忆整合层落地方案 v1

日期：2026-03-11
状态：提案
目标：在不推翻现有 OpenClaw 记忆体系的前提下，为 `MEMORY.md`、`memory/shared/`、`task-board.json`、`memory_search` 增加一层“主动整合器”，提升召回质量、降低上下文浪费、提高子 Agent 成功率。

---

## 一、现状问题

当前体系已经有：

- `MEMORY.md`：高层长期记忆
- `memory/shared/`：任务中间态与交付物
- `memory/task-board.json`：任务状态
- `memory_search`：语义检索

但仍存在 4 个问题：

1. 记忆分散：同一主题分布在多个 shared 文件里
2. 重复堆积：类似结论反复写，缺少自动合并
3. 子 Agent 喂料不稳：要么读太多，要么漏关键上下文
4. 搜索结果“能搜到”但“未整合”：缺少跨文件洞察层

---

## 二、总体思路

不重做记忆系统，只增加一层：

### 新增：记忆整合层（Memory Consolidation Layer）

作用：

- 定时扫描新增记忆
- 合并重复结论
- 发现跨文件关联
- 生成高层洞察
- 为子 Agent 提供更精准的喂料

一句话：
**从“被动存储 + 临时搜索”升级为“被动存储 + 主动整合 + 精准喂料”。**

---

## 三、落地结构

### 1. 保留现有目录

- `MEMORY.md`
- `memory/shared/`
- `memory/task-board.json`
- `memory_search`

### 2. 新增目录

```text
memory/
  insights/
    agent-reliability.md
    notebooklm-workflow.md
    memory-architecture.md
    content-sop.md
  summaries/
    2026-03-11_daily-summary.md
    2026-03_weekly-summary.md
  consolidation/
    queue.json
    runs.jsonl
```

### 3. 三类新增文件的职责

#### `memory/insights/`

存跨天、跨任务、跨文件的稳定规律：

- 反复踩坑
- 有效 SOP
- 成功模式
- 常见失败原因

#### `memory/summaries/`

存周期性压缩结果：

- 日摘要
- 周摘要
- 特定主题摘要

#### `memory/consolidation/`

存整合器运行状态：

- 哪些文件已处理
- 哪次整合产出了什么
- 是否有失败/跳过

---

## 四、整合器工作流

### Step 1：收集新增记忆

来源：

- 当天 `memory/shared/` 新文件
- 当天工作日志
- `task-board.json` 状态变化
- 指定主题文件（可选）

### Step 2：抽取结构化信息

对每个新文件提取：

- 主题
- 任务名
- 关键实体（人/项目/工具/文件）
- 结论
- 风险
- 待办
- 适用范围
- 是否可复用

### Step 3：做三件事

1. **去重**：相似结论合并，不重复堆积
2. **连接**：找跨文件关系
3. **升级**：把高频规律升级成 insight

### Step 4：产出结果

- 更新 `memory/summaries/当天摘要.md`
- 如有高价值规律，更新 `memory/insights/*.md`
- 如是长期规律，追加到 `MEMORY.md`

## 五、给子 Agent 的喂料机制（重点）

这是最直接提升稳定性的地方。

### 当前问题

子 Agent 常常：

- 读太多无关记忆
- 读不到最关键文件
- 被长上下文污染

### 新规则

以后派发子 Agent 前，不再让它自己乱读，而是由主 Agent 先挑好：

#### 默认只喂 3 类材料

1. `task-board.json`
2. 最近 1-2 份最相关 `shared/` 文件
3. 1 份相关 `insight` 或规则文件

### 子 Agent 喂料模板

```text
前置读取：
1. task-board.json
2. shared/<最近相关文件>.md
3. insights/<相关主题>.md
```

### 好处

- 上下文更短
- 任务边界更清晰
- 成功率更高
- 不容易跑偏

## 六、建议先做的 3 个 insight 文件

### 1. `memory/insights/agent-reliability.md`

记录：

- 子 Agent 失败模式
- manifest 落地问题
- 超时规律
- 最佳派发粒度

### 2. `memory/insights/notebooklm-workflow.md`

记录：

- 上传前先删旧版本
- NotebookLM source 管理规则

- 常见错误与兜底

### 3. `memory/insights/content-sop.md`

记录：

- 内容生成前先确认结构
- 输入不合格直接打回
- 输出自检
- 不合格自动重写
- 结果留痕与归档

## 七、最小可用版本（MVP）

### v1 只做 4 件事

1. 每日整合当天 shared 文件
2. 生成 daily summary
3. 生成 1-3 个 insights 文件
4. 派发子 Agent 时只喂精选记忆

### 不做的事

- 不替换 `memory_search`
- 不引入向量数据库
- 不重做现有 memory 目录
- 不上复杂 UI

## 九、成功标准

如果这套方案有效，应该看到 4 个变化：

1. 子 Agent 失败率下降
2. 单次喂料上下文变短
3. 同类问题返工减少
4. 搜索命中后更容易直接拿到结论而不是原料

---

## 十、我的建议

不要一上来重做记忆系统。

正确路线是：
**先给现有系统补“整合层”和“精准喂料层”，再看是否需要更换底层记忆架构。**

这是低风险、高收益、最适合当前 OpenClaw 实际状态的路线。
