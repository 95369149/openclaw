# 中文图纸风格规范（Kitt Blueprint Spec v1.0）

> 目的：统一我们后续所有“技术图 / 架构图 / 流程图 / 生产标准图 / 运营闭环图”的视觉表达，避免 AI 默认生成营销风、花哨 UI 风、SaaS 落地页风。

---

## 一、定位

这不是海报规范，不是宣传页规范，也不是产品官网规范。

这是**工程图纸风格规范**。

目标效果：
- 一眼看上去像“技术规格书”
- 强调结构、关系、边界、数据，而不是氛围和装饰
- 可直接用于：汇报、标准文件、SOP、架构说明、流程培训、制造现场张贴

关键词：
- **克制**
- **平面**
- **高信息密度**
- **强对齐**
- **低装饰**
- **工程感**

---

## 二、核心原则

### 1. 先信息，后美观
图先服务于“看懂”，再追求“好看”。

判断标准不是“酷不酷”，而是：
- 结构是否清楚
- 层级是否明确
- 流向是否一眼可见
- 关键数据是否突出
- 注释是否够少但够用

### 2. 工程图，不是营销图
禁止把技术图做成：
- SaaS Landing Page
- 玻璃拟态
- 大面积渐变背景
- 卡片悬浮阴影堆叠
- 大圆角按钮和“现代 UI”组件感

### 3. 用最少视觉手段表达最多信息
追求高 data-ink ratio：
- 少装饰
- 少空话
- 少图标
- 少色彩
- 多结构
- 多层级
- 多准确信息

### 4. 统一风格优先于单张炫技
后续所有图统一语言：
- 边框语言统一
- 配色统一
- 字体统一
- 标题结构统一
- 连接线规则统一

---

## 三、视觉总规范

### 1. 背景与画布
- 页面背景：浅灰色
- 主画布：纯白底
- 主画布必须有边框
- 所有内容必须放在一个清晰的“图纸画布”中，不允许散在页面里

推荐颜色：
- 页面背景：`#f8fafc`
- 画布背景：`#ffffff`
- 边框颜色：`#cbd5e1`

### 2. 配色原则
采用“**黑白灰为主，单一强调色为辅**”原则。

#### 主色
- 主文字：`#0f172a`
- 次文字：`#64748b`
- 结构边框：`#cbd5e1`

#### 强调色
默认最多只允许一个强调色：
- 红色：错误 / 风险 / 异常 / 警告
- 蓝色：信息 / 通路 / 主系统（仅在必要时）
- 绿色：已完成 / 正常 / 闭环（少量使用）

规则：
- 一张图最多一个语义强调色
- 非必要不要彩色
- 禁止五颜六色模块乱飞

### 3. 阴影 / 渐变 / 模糊
全部默认禁止：
- 禁止阴影
- 禁止渐变
- 禁止毛玻璃
- 禁止背景光斑
- 禁止拟物质感

### 4. 圆角
- 默认使用小圆角或直角
- 不允许“大圆角 UI 卡片风”
- 更偏工程图时直接使用直角

---

## 四、字体规范

### 1. 中文 / 标题 / 正文
优先使用无衬线字体：
- 中文：微软雅黑 / 思源黑体 / 苹方
- 英文：Inter / Helvetica / Arial

### 2. 技术字段 / 路径 / 数据 / 代码
必须使用等宽字体：
- JetBrains Mono
- Consolas
- Menlo

适用范围：
- 文件路径
- 模型名
- 命令行
- 变量名
- 参数名
- ID
- API 名称
- cron 表达式

### 3. 字体层级
建议层级：
- 主标题：18–24px
- 副标题：10–12px（全大写可选）
- 模块标题：13–16px
- 正文说明：12–14px
- 技术标签/路径：11–13px

---

## 五、布局规范

### 1. 所有元素必须严格对齐
不允许“差不多对齐”。

要求：
- 模块边缘对齐
- 列宽一致
- 间距统一
- 标题线统一
- 连接线从结构边缘精确出发

### 2. 优先 Grid / Flex，不要随意漂浮
布局优先级：
1. Grid
2. Flex
3. 定位仅用于连接线、特殊标注

### 3. 统一间距系统
推荐基础间距单位：8px

常用：
- 模块内边距：16px / 20px
- 模块间距：16px / 24px / 32px
- 标题与内容：8px / 12px
- 区块间距：24px / 32px

### 4. 图必须有“标题区”
所有正式图都应包含：
- 主标题
- 副标题 / 类型 / 版本 / 日期（至少一项）
- 标题区和主体内容之间要有明确分隔线

推荐结构：
- 主标题：图名
- 副标题：用途 / 版本 / 日期 / 类型

---

## 六、图形元素规范

### 1. 模块（Box）
模块是最核心元素。

要求：
- 白底
- 1px 或 2px 实线边框
- 内容左对齐或规整居中
- 不使用复杂背景纹理

适合表示：
- 系统
- 组件
- 阶段
- 部门
- 角色
- 文件夹
- 数据层

### 2. 连接线
要求：
- 细线
- 直线或直角折线
- 尽量少弯曲
- 抽象关系用虚线
- 实际流转用实线

禁止：
- 花哨箭头
- 发光连线
- 曲线过多
- 粗线抢视觉

### 3. 图标
默认少用。

使用条件：
- 能明显提升识别速度
- 不会干扰结构阅读

要求：
- 线性图标
- 简单 SVG
- 禁止彩色拟物图标
- 禁止表情包式图标体系

### 4. Badge / 标签
适合表达：
- 状态
- 类型
- 风险等级
- 环境（prod/dev）
- 模型名

规则：
- 小尺寸
- 边框清楚
- 文案短
- 不喧宾夺主

---

## 七、文字表达规范

### 1. 文案短句化
图里的文字必须短。

优先：
- 名词
- 动词短语
- 结果短语

避免：
- 大段解释
- 口号式句子
- 宣传性形容词

### 2. 模块命名要专业、统一
例如：
- 原始输入层
- 编译知识层
- 记忆巩固层
- 任务执行层
- 异常告警层

不要写成：
- 超强大脑中心
- 智能超算引擎
- 神级中枢

### 3. 注释只写必要信息
注释应该回答：
- 这是什么
- 它和谁连接
- 为什么重要

不要写成长文说明。

---

## 八、适用图类型

本规范适用于：

### 1. 架构图
如：
- OpenClaw 多 Agent 架构图
- Memory / Wiki / Dreaming 分层图
- 外贸自动化系统架构图

### 2. 流程图
如：
- 线索进入 → 分类 → 跟进 → 报价 → 成交
- 学习材料进入 → wiki 编译 → task 化 → 执行

### 3. SOP / 标准图
如：
- 装配检查图
- 扭矩标准流程图
- 复盘机制图

### 4. 汇报型信息图
如：
- 本周系统升级结构变化
- Agent 编制与职责图
- 数据闭环图

---

## 九、不适用场景

不适用于：
- 品牌宣传海报
- 活动主视觉
- 花哨营销页
- 面向 C 端用户的情绪化设计
- 追求氛围感的视觉作品

---

## 十、默认 HTML/CSS 实现要求

如果未来让 AI 直接输出 HTML/CSS 图，默认要求：

1. 所有颜色走 CSS 变量，不写死到局部
2. 主画布必须为一个有边框的 `diagram-canvas`
3. 标题区必须独立
4. 布局优先 Grid/Flex
5. 技术字段使用等宽字体
6. 连接关系优先 SVG 直线 / 折线
7. 不允许阴影 / 渐变 / blur / 发光
8. 输出优先可截图、可打印、可嵌入文档

推荐变量：

```css
:root {
  --c-bg: #f8fafc;
  --c-canvas: #ffffff;
  --c-border: #cbd5e1;
  --c-text-main: #0f172a;
  --c-text-sub: #64748b;
  --c-accent: #dc2626;
  --font-ui: 'Inter', 'Microsoft YaHei', sans-serif;
  --font-mono: 'JetBrains Mono', 'Consolas', monospace;
}
```

## 十一、我们内部的执行口令

以后做图时，默认执行以下口令：

### 口令 1：
**按中文图纸风格规范输出，不要做成营销页。**

### 口令 2：
**白底、浅灰边框、黑灰文字、单一强调色，严格对齐，高信息密度。**

### 口令 3：
**所有技术字段、路径、模型名、命令行统一使用等宽字体。**

### 口令 4：
**连接线细、直、克制；模块清楚、边界明确、说明短句化。**

---

## 十二、我们自己的风格判断标准

一张图做出来后，用这 6 条快速验收：

1. 一眼看上去像不像工程图，而不是宣传页？
2. 结构边界是否清楚？
3. 信息层级是否明确？
4. 有没有多余装饰？
5. 关键数据 / 路径 / 模型名是否够醒目？
6. 截图后放进 Word / 汇报 / 培训材料里是否显得正式？

只要有 2 条答不上来，就不算过关。
