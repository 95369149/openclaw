## 背景

我在运营一个基于 OpenClaw 的多-Agent AI 系统，当前编制 7 个 Agent：

| Agent | 模型 | 职责 |
|-------|------|------|
| jimmy | Claude Sonnet 4.6 | 总调度 + 对外出口 |

| kitt | Claude Opus 4.6 | 终审 + 架构裁判（贵，慎用） |
| sino | Kimi K2.5 | 中文专家 |
| scout | Gemini 3 Pro Preview | 外链/情报侦察（免费） |
| guard | Claude Sonnet 4.6 | 配置守门 / 风险审计 |

上一轮碰撞（Perplexity Reality Checker）给了 8.5/10，指出 3 个 blocker：
1. guard 与 kitt 的高风险决策边界模糊
2. 缺可执行路由矩阵
3. 规则停留在人话版，缺与配置的字段映射

这一轮我需要你帮我补齐 7 个具体细节，每个都要给**可直接落地的表格/数字/规则**，不要框架性描述。

我有 CFG_LOW / CFG_MEDIUM / CFG_HIGH 三档风险分级框架，但缺具体操作到风险等级的映射。

请输出一张表，格式如下：

| 操作类型 | 风险等级 | 签收人 | 说明 |
|----------|----------|--------|------|

要覆盖的操作至少包括：
- 改 cron 任务
- 改 agent 路由/模型
- 改 provider 配置（API key / baseUrl）
- 改 channel 配置（Telegram / Discord / WeChat）
- 删除文件（memory 内 / memory 外）
- 发外部消息（Telegram / Discord / 微信）
- 写/改 openclaw.json
- 新增/删除 agent
- 新增/删除 skill
- 安装 MCP / 第三方工具
- 执行含 sudo/rm -rf/curl|sh 的命令
- 修改 SOUL.md / AGENTS.md / 排兵布阵.md 等系统规则文件

每个操作给出：guard 可自行放行 / 需 guard+kitt 双签 / 需 guard+kitt+人类三签。

## 问题 2：sino（Kimi）和 deep（GPT-5.4）的任务分界线

两个都能写中文、都能写代码。我需要一个决策矩阵来判断什么时候该给 sino 而不是 deep。

| 维度 | 给 sino 的条件 | 给 deep 的条件 |
|------|---------------|---------------|

维度至少包括：
- 任务类型（写作 / 代码 / 分析 / 翻译 / 润色）
- 输出长度
- 是否需要联网搜索
- 中文质量要求（通顺即可 vs 营销级 vs 文学级）
- 是否涉及代码/技术
- 上下文长度需求

另外请给出 3-5 个典型 case 示例：同一个任务，为什么选 A 不选 B。
