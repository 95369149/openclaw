## xjrouter 接入方案（最终版）
- 问题：xjrouter 只支持 HTTP + 需要 Host header，Surge 会劫持 DNS
- 方案：本地 HTTP 反向代理（`/tmp/xjrouter-proxy/proxy_http.py`，端口 8444）
  - 监听 `http://127.0.0.1:8444`
  - 转发到 `http://47.86.25.153:80`，自动加 `Host: xjrouter.xyz`
- OpenClaw 配置：`models.providers.xjrouter.baseUrl = http://127.0.0.1:8444/v1`
- launchd 开机自启：`~/Library/LaunchAgents/ai.openclaw.xjrouter-proxy.plist`（KeepAlive=true）
- session 切换需要 `session_status(model="xjrouter/claude-opus-4-6-max")` 刷新

## 踩坑记录
1. HTTPS 自签证书 → OpenClaw Node.js 拒绝连接 → 改用 HTTP 代理
2. IP 直连 xjrouter 返回 404 → 必须带 Host header
3. SIGUSR1 热重载不会重新探测 provider → 需要 session_status 手动切模型
4. 旧 session 会缓存 provider → 新配置生效后需要手动刷新 session 模型
5. **教训：改配置后先验证再重启，不能稀里糊涂就 restart**
6. 代理 v1 用 urllib.request 不支持 SSE 流式 → 切到 xjrouter 后 session 卡死无响应
7. `agents.defaults.models`（注意是 models 不是 model）是模型白名单 map，不在里面的模型 session_status 拒绝切换
8. Gateway 重启后已有 session 不会自动切到新 primary（已知 bug #7539/#9754），需要 `/new` 或手动 session_status 切换
9. 别名配置在 `agents.defaults.models` 的 alias 字段，不是 model.fallbacks

## 修复记录（16:30-16:55）— xjrouter 代理 v4
1. **根因**：代理转发时透传了客户端原始 `Content-Length`，又追加了修改后的 `Content-Length`，nginx 收到两个不一致的值直接 400
2. **修复**：header 转发时跳过 `content-length`，只用修改后的 body 长度
3. **额外兼容**：
   - 删除 `stream_options`、`store`、`tools`、`tool_choice`、`parallel_tool_calls`（xjrouter 不支持）
   - `max_completion_tokens` → `max_tokens`（兼容旧 API）
   - `developer` role → `system`（xjrouter 不认 developer）
4. **结论**：xjrouter 不能当主模型（Gateway bug #7539 每轮回落），但 `sessions_spawn(model="max")` 派子 agent 完全可用
1. **代理脚本 v2** — 重写 `memory/scripts/xjrouter_proxy.py`，用 http.client 替代 urllib.request，支持 SSE 逐块流式转发 + ThreadingMixIn 多线程
2. **模型白名单** — 把 `xjrouter/claude-opus-4-6-max` 加入 `agents.defaults.models`，别名 `max`
3. **Primary 切换** — xjrouter 设为 primary，mynewapi 降为 fallback#1 保底
4. **HEARTBEAT 兜底** — 重启后 session 缓存旧模型时，heartbeat 检查并自动切回 xjrouter
