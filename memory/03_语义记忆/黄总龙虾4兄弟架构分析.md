# 黄总《龙虾4兄弟的AI协作实战》架构分析

> 来源：https://x.com/servasyy_ai/status/2020475413055885385
> 分析时间：2026-02-20

## 核心架构
- **Single Gateway + 5 Agent + 5 独立 Workspace**
- **双通道**：Discord + Telegram
- **5 角色分工**：
  - 总指挥：全局调度、任务拆解、纠偏收口
  - 军师：策略分析、方案评估、风险预判
  - 工程师：技术执行、代码实现、系统维护
  - 创作官：内容创作、表达优化、对外输出
  - 智库：知识审核、质量把关、合规检查

## 关键配置
- **bindings**：`channel + accountId -> agentId` 显式路由
- **dmScope**：`per-account-channel-peer`（三维隔离）
- **群聊策略**：
  - 总指挥 `requireMention=false`（全局监听）
  - 其他4角色 `requireMention=true`（@触发）
- **agentToAgent ping-pong = 0**（防止AI互相客套）

## 实战案例：Twitter 推文分析
- 创作官抓取 35 条推文数据
- 智库质疑样本量和因果关系
- 最终公式：**具体成果 + 实用价值 + 数字佐证**
- 数据：高赞推文平均 253 赞 vs 普通推文 27 赞（10倍差距）

## 对我们的启发
1. **智库角色很重要**：质疑 + 验证，防止AI瞎说
2. **ping-pong=0 是好实践**：避免AI废话循环
3. **我们的 Webhook 方案更轻量**：不需要 5 个 Gateway
4. **记忆分层值得借鉴**：短期流水 + 长期记忆 + 群聊记忆 + 冷归档
