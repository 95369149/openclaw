## Deep Agent 模式

### 中文内容生成
- ✅ **成功模式**: 给出明确的输出格式（字数、结构、语气）
- ✅ **成功模式**: 提供参考素材或案例
- ❌ **失败模式**: 只说"写一篇文章"，没有具体要求
- **示例 prompt**:
  ```
  任务：生成开工第一课安全生产演讲稿
  字数：800-1000字
  结构：开场白 + 3个安全要点 + 结尾号召
  语气：严肃但不说教，接地气
  参考：memory/02_知识库/企业文化/九大机制.md
  ```

### 代码重构
- ✅ **成功模式**: 先分析现状，再提出方案，最后执行
- ✅ **成功模式**: 明确保留什么、删除什么、合并什么
- ❌ **失败模式**: 直接说"重构这个目录"，没有具体指导
- **示例 prompt**:
  ```
  任务：重构 memory/scripts/ 代码体系
  第一步：读取所有脚本，分析功能和依赖
  第二步：识别废弃脚本（sf_key_health.py、*.bak*）
  第三步：合并重复的同步脚本，保留最优版本
  第四步：创建 README.md 说明各脚本用途
  原则：先分析后动手，保留能用的，删除废的
  ```

### 批量任务
- ✅ **成功模式**: 给出明确的处理规则和边界条件
- ✅ **成功模式**: 要求生成报告而不是直接执行（安全）
- ❌ **失败模式**: 让 agent 自己判断什么该删什么不该删

## Logic Agent 模式

### 数学计算
- ✅ **成功模式**: 提供完整的数据和公式
- ✅ **成功模式**: 要求展示计算过程
- ❌ **失败模式**: 只给部分数据，期望 agent 自己找

### 算法优化
- ✅ **成功模式**: 先给出当前实现，再说明性能瓶颈
- ✅ **成功模式**: 明确优化目标（时间复杂度？空间复杂度？）
- **示例 prompt**:
  ```
  任务：优化客户匹配算法
  当前实现：O(n²) 暴力匹配
  瓶颈：客户数量 >1000 时响应超过 5 秒
  优化目标：降到 O(n log n)，响应时间 <1 秒
  约束：不能改变匹配逻辑，只能优化数据结构
  ```

## Main Agent (Scout) 模式

### 浏览器操作
- ✅ **成功模式**: 总是先 screenshot 确认当前状态
- ✅ **成功模式**: 给出明确的 targetId（从之前的 snapshot 获取）
- ❌ **失败模式**: 盲目操作，不确认页面状态
- **示例 prompt**:
  ```
  任务：抓取 Perplexity Tab 1 搜索结果
  步骤：
  1. browser(action=open, targetId=1CBB090733D2AC67A24BD1BB9CA0CE38)
  2. browser(action=screenshot) 确认页面加载
  3. browser(action=snapshot) 提取内容
  4. 返回结果给 jimmy
  ```

### 多模态分析
- ✅ **成功模式**: 明确要分析的维度（文字？图片？视频？）
- ✅ **成功模式**: 给出输出格式（markdown？JSON？）
- **示例 prompt**:
  ```
  任务：分析产品宣传图
  分析维度：
  - 视觉风格（配色、排版、字体）
  - 信息层次（主标题、副标题、正文）
  - 目标受众（年龄、职业、痛点）
  输出格式：markdown，包含改进建议
  ```

## Kitt Agent 模式

### 架构设计
- ✅ **成功模式**: 提供完整的业务背景和约束条件
- ✅ **成功模式**: 要求给出多个方案并对比
- ❌ **失败模式**: 只说"设计一个系统"，没有上下文
- **示例 prompt**:
  ```
  任务：设计供应商评估系统
  背景：当前有 50+ 供应商，手动评估效率低
  约束：
  - 必须支持多维度评分（价格、质量、交期、服务）
  - 必须能自动预警风险供应商
  - 必须能生成对比报告
  要求：给出 3 个方案，对比优劣，推荐最优方案
  ```

### 战略决策
- ✅ **成功模式**: 提供历史数据和决策依据
- ✅ **成功模式**: 明确决策目标和风险承受度
- **示例 prompt**:
  ```
  任务：决策是否切换主力供应商
  背景：
  - 当前供应商 A：合作 3 年，价格稳定，质量偶尔有问题
  - 备选供应商 B：价格低 15%，质量未知，交期承诺更快
  历史数据：memory/10_项目/供应链管理/供应商评估.md
  决策目标：降低成本但不能牺牲质量
  风险承受度：中等（可以试单，但不能全切）
  要求：给出决策建议 + 风险预案
  ```

## 通用成功模式

### Prompt 结构
1. **任务描述**（一句话说清楚要干什么）
2. **背景上下文**（为什么要做，相关历史）
3. **具体要求**（输出格式、字数、结构）
4. **约束条件**（不能做什么，必须遵守什么）
5. **成功标准**（怎样算完成）

### 失败重试策略
- **第一次失败**: 补充上下文，缩小范围
- **第二次失败**: 换 agent（deep → kitt，logic → deep）
- **第三次失败**: 报告厂长，人工介入

### 上下文管理
- **文件路径**: 总是给绝对路径或相对于 workspace 的路径
- **引用文件**: 明确告诉 agent 去读哪个文件
- **输出位置**: 明确告诉 agent 把结果写到哪里

## 待验证模式

### 跨 Agent 协作
- 假设：大任务拆成子任务，分别派给不同 agent，最后由 jimmy 整合
- 待验证：是否比单个 agent 完成整个任务更高效？
- 测试场景：文稿生成系统（deep 写内容 + main 配图 + kitt 审核）

### 主动学习
- 假设：agent 完成任务后，自动总结成功模式并写入本文件
- 待验证：是否能形成自我进化闭环？
- 测试场景：每日 03:00 自我进化任务
