## 一、残酷的现状——金鱼记忆

- GitHub Issue #5429：用户丢失 45 小时 agent 积累上下文，静默压缩清除所有对话历史
- Issue #2624：agent 随机重置，忘记 2 条消息前的对话
- Issue #8723：memory flush 触发无限循环，锁死 agent 72 分钟

**OpenClaw 记忆架构**：Markdown 文件 + 向量搜索
- Daily Logs（短期）、MEMORY.md（长期）、SOUL.md（人格）
- 检索：向量嵌入 + BM25 混合搜索

**六个根本缺失**：扁平、无差别、被动
- 所有记忆权重相同，无遗忘机制，无自动整理
- 检索只看语义相似度，不评估重要性
- 无法表达关系，数据永远是数据不会变成认知

## 二、官方在做什么——QMD 后端与混合搜索

**版本时间线**：
- v2026.1.12：向量搜索基础设施（SQLite 索引 + 分块 + 懒同步 + 文件监听）
- v2026.1.29：L2 归一化修复（本地嵌入向量未归一化导致余弦相似度失真）
- v2026.2.2：QMD 记忆后端合并（PR #3160），BM25 + 向量 + Reranking 三路混合搜索

**QMD**：本地搜索 sidecar 进程，每个 agent/config 缓存一个 sidecar，会话数据索引前脱敏
- 已知坑：CPU-only 查询 3 分 40 秒（超 12 秒超时）、paths 配置不生效、回退静默

**PR #6060**：暴露四个默认关闭的隐藏功能
- pre-compaction memory flush、混合搜索、嵌入缓存、会话记录搜索

**核心问题**：都是"检索层"优化，六个根本缺失（遗忘、重要性、图谱、反思、时序、晋升）一个没解决

## 三、社区自救——土法炼钢五种方案

1. **Mem0**（46.6K Stars）：Auto-Recall + Auto-Capture，Session + User 双层，声称 91% 低延迟提升
2. **Hindsight**（1.3K Stars）：本地长期记忆，Auto-Recall 自动注入，PostgreSQL 后端
3. **MoltBrain**（365 Stars）：SQLite + ChromaDB，生命周期钩子，Web UI 时间线
4. **NOVA Memory System**：PostgreSQL 结构化，8 张表（实体/关系/地点/项目/事件/教训/偏好）
5. **Penfield Skill**：BM25 + 向量 + 图 三路混合搜索

**社区验证的方向**：
- Daily Log → MEMORY.md 晋升模式
- Heartbeat 复用为记忆整合触发器
- 70/30 混合搜索权重（向量 70% + 关键词 30%）
- Session Transcript 索引

**社区六个盲区**：遗忘/衰减、重要性评分、知识图谱、自动反思、时序推理、记忆晋升

| 论文 | 核心贡献 |

| xMemory [1] ICML 2026 | 记忆解耦为语义组件 + 层次结构，主题聚类层 |

**59 位作者综述 [3] 三维分类法**：
- 记忆基底（Substrate）：向量/图谱/文档
- 认知机制（Mechanism）：被动记录/主动推理
- 记忆主体（Subject）：用户/Agent/共享

**两个工业界警告**：
1. Serial Collapse [9]（Kimi K2.5）：Agent 退化为不使用记忆
2. Memory Misevolution [5]（TAME）：正常迭代中积累有毒捷径

## 五、开源记忆生态——6 个项目全景（77K+ Stars）

**三种记忆哲学**：
1. 状态层优先（mem0、Memori）：记忆 = 状态管理
2. 知识层优先（cognee、MemOS）：记忆 = 结构化知识
3. 学习层优先（Hindsight）：记忆 = 学习过程（retain/recall/reflect）

没有任何一个项目同时覆盖三层。

## 六、200+ Issues 五大共性问题

1. **静默失败**（6/6 项目）：功能不行但不告诉你
   - mem0 #2443：有效信息未存储，AI 过滤太激进无提示
   - Memori #238：日志显示成功但数据库为空
2. **记忆去重**：重复触发 DELETE 而非 NOOP，LLM 把重复判为"矛盾"导致错误删除
3. **LLM 判断不可靠**：第一人称丢失、JSON 格式不稳定、prompt 偏向
4. **数据库连接/迁移**：SQLite 锁、Docker 迁移失败、遥测泄漏
5. **搜索排序失真**：跨集合归一化导致排序错误、缺少时间维度

## 七、游戏 AI 启发

### 矮人要塞三层记忆
- **STM**：8 槽位循环缓冲，按情感强度竞争（目睹死亡 0.9 挤掉饥饿 0.1）
- **LTM**：停留足够久 + 未被挤出 → 1:3 概率晋升
- **Core Memory**：永久修改性格参数，数据→逻辑的质变

### 斯坦福 Generative Agents 三维检索
- 检索分数 = Recency × Importance × Relevance
- **反思机制**：100 条琐碎记忆 → 3 条高层洞察，召回率 41% → 87%

### 模拟人生 4 情感固化
- 短期情感反复出现 → 永久特质（经历塑造人格）

### Nemesis System 事件驱动
- 事件标签 → 参数突变 → 社会关系网络传播

## 八、User Memory vs Agent Memory

**OpenViking（字节跳动）分类体系**：
- 6 类记忆：档案、偏好、实体、事件、案例、模式
- L0 摘要 ~100 tokens（索引去重）→ L1 概览 ~500 tokens（结构化）→ L2 全文
- 合并策略：档案总是合并，偏好/实体/模式支持合并，事件/案例不可合并

## 九、记忆是核心基础设施

"谁先解决记忆问题，谁就赢得 24/7 Agent 的战争。"
- Context window = 短期记忆：溢出则截断，重启则归零
- 这不是 OpenClaw 的 bug，是整个技术栈的结构性限制

## 对 Kitt 的直接启示

### 已落地 ✅
1. .abstract = L0，大脑中枢 = L1，具体文件 = L2（OpenViking 三级模型）
2. softThresholdTokens: 4000 → 40000（提前触发 flush）
3. experimental.sessionMemory = true（历史会话可搜索）
4. memorySearch.fallback = none（强制本地）
5. SOUL.md 第零号铁律（压缩后先读记忆）
6. sync.sh v2.0 Git 自动同步
7. Heartbeat 心跳机制

### 可落地的进阶 ⚠️
1. **反思 cron**：每日取当天记忆 → 提炼高层洞察写入 MEMORY.md（斯坦福方案）
2. **记忆晋升**：反复出现的模式 → 写入 SOUL.md（矮人要塞 Core Memory）
3. **静默失败检测**：子 agent 完成后检查 shared/ 是否有新文件
4. **重要性评分**：关键决策/教训标记高权重
5. **Serial Collapse 防护**：监控 memory_search 调用频率，退化时告警

### 当前架构盲区 ❌
1. 无遗忘/衰减机制（所有记忆权重相同）
2. 无知识图谱（无法表达实体关系）
3. 无时序推理（检索缺少时间维度）
4. 无自动去重（可能产生重复记忆）
