# 智囊团 · Advisor Board v2

> 不是来给你信心的，是来提前暴露盲区，然后替你收敛成方案的。

## 统一入口（slash 风格）

- `/board <问题>`：标准入口，等同于「开个董事会」
- `/decision <问题>`：决策型别名
- `/office-hours <问题>`：对标 gstack，用于产品/方案反证

上述三个 slash 命令与自然语言触发词**等价**，命中任一即进入 Advisor Board 流程。

主持人：`jimmy`；涉及架构/系统路线判断时自动托 `kitt` 终审。

## 目标升级

v1 的问题：会分析，但容易停在“列观点”。

v2 的目标：

1. **自动判断要不要开董事会**
2. **自动挑人，不让厂长手动点将**
3. **自动并行碰撞，不只单线程思考**
4. **必要时自动二轮追问分歧**
5. **最后必须收敛成一个明确方案 + 下一步动作**

---

## 适用场景

命中以下任一类，优先走 advisor-board：

- 战略判断：这个方向值不值得做？
- 系统路线：先做 A 还是先做 B？
- 产品取舍：要不要封装成独立入口/agent/skill？
- 组织效率：这套机制能不能复制给团队？
- 风险决策：最大坑在哪，怎么规避？
- 复杂方案评估：不是缺信息，而是缺多视角碰撞与最终拍板

不适用：

- 单纯执行任务（直接派 deep/main/scout）
- 单纯事实查询（先查再说）
- 已经明确到只差动手的事情

## 可用智囊层

Advisor Board 不再局限于“名人观点”。分两层：

### A. 认知型智囊（框架层）

| 智囊           | Skill                      | 擅长领域                             |
| -------------- | -------------------------- | ------------------------------------ |
| Charlie Munger | `munger-perspective`       | 逆向思考、认知偏误、风险识别         |
| Naval Ravikant | `naval-perspective`        | 杠杆、长期主义、机会成本、路线选择   |
| 张一鸣         | `zhang-yiming-perspective` | 组织效率、信息流、战略判断、管理韧性 |

### B. 执行型智囊（系统层）

| 智囊  | 模型                          | 擅长领域                         |
| ----- | ----------------------------- | -------------------------------- |
| kitt  | `opus`（claude-opus-4-6）     | 终审、架构裁判、方向正确性       |
| deep  | `gpt54`（gpt-5.4）            | 执行落地、工程可维护性、可复用性 |
| sino  | `kimi`（kimi-k2.6）           | 中文表达、业务转译、组织落地     |
| scout | `sonnet`（claude-sonnet-4-6） | 外部情报、竞品、资料碰撞         |
| guard | `sonnet`（claude-sonnet-4-6） | 风险审计、配置安全、守门         |
| main  | `opus`（claude-opus-4-6）     | 长文档/多模态/复杂材料综合       |

⚠️ **碰撞会执行铁律（2026-05-12 定稿）**：

- 碰撞会**必须 spawn 真实子 agent**，不同模型才有真实碰撞价值
- **每路子 agent 必须指定高级模型**，禁止用免费/低级模型做碰撞
- **每路 runTimeoutSeconds=300**，超时视为失败，jimmy 主进程接管该路视角
- **每路 task 开头必须引用 conventions 目录**（见 spawn-template.md）
- **context 必须用 isolated**，不用 fork（跨 agent spawn 不支持 fork）
- 碰撞结束后 jimmy 负责收敛，不让子 agent 自己收敛

原则：

- **抽象决策 / 框架判断** → 认知型智囊优先
- **系统方案 / 多 agent / 工作流设计** → 执行型智囊优先
- **外部方案碰撞** → scout 必上
- **高风险变更** → guard 必上

## 自动选人规则

### 默认组合

| 问题类型          | 默认智囊                |
| ----------------- | ----------------------- |
| AI/系统路线       | `kitt + deep + sino`    |
| 外部情报/竞品判断 | `scout + deep + kitt`   |
| 配置/风险/守门    | `guard + deep + kitt`   |
| 中文内容/组织机制 | `sino + kitt + deep`    |
| 纯框架/人生/投资  | Munger + Naval + 张一鸣 |

### 升级规则

满足任一条件可升级为 4 人局：

- 方案涉及外部产品/竞品/链接 → 加 `scout`
- 涉及配置、安全、回滚 → 加 `guard`
- 涉及长文档/复杂材料 → 加 `main`
- 三方意见分歧明显 → 自动加 1 位裁判或信息补位者

### 禁止事项

- ❌ 不要为了热闹而拉太多人
- ❌ 不要把“多 agent”误当成“质量更高”
- ❌ 一轮默认 3 人，必要时才扩到 4 人

## 执行流程

### Phase 0: 先判断值不值得开董事会

先问自己 3 个问题：

1. 这是**判断题**还是**执行题**？
2. 这件事的难点是**信息不足**还是**路线分歧**？
3. 多视角碰撞后，是否真的能提高正确率？

只有当答案偏向“路线判断/优先级取舍/系统设计/风险权衡”时，才开董事会。

---

### Phase 1: 问题定性

提取四件事：

- **问题本质**：战略/系统/产品/风险/组织/内容
- **决策对象**：到底在判断什么
- **约束条件**：时间、资源、风险承受度、现有资产
- **输出目标**：要结论、要路线、要最小可行方案，还是要否决

如果用户表达含混，不要先追问；先根据上下文做最合理假设，再碰撞。
只有继续下去会明显跑偏，才补 1 个关键问题。

---

### Phase 2: 选人

按“最小够用”原则自动选 3 人：

- 1 个方向裁判
- 1 个执行落地者
- 1 个业务/风险/外部视角补位者

优先使用系统内现成 agent；不要每次都拟人化成名人视角。

---

### Phase 3: 并行碰撞

对每位智囊统一要求输出：

1. **核心判断**：成立 / 部分成立 / 不成立
2. **3 个关键证据**
3. **3 个最大担忧**
4. **如果只做 1-2 个最小改造，补什么**
5. **最终动作建议**

要求短、硬、可比较，禁止散文式长篇。

---

### Phase 4: 自动二轮追问（必要时触发）

满足以下任一条件，自动追加第二轮：

- 三方结论冲突明显
- 对“先做什么”没有共识
- 证据太虚、建议太空
- 关键分歧落在同一个点（例如：先做 skill 还是先做 agent）

二轮只追一个问题：

> 请围绕最大分歧点，重新给出你的最终判断，不要重复第一轮内容。

注意：

- 二轮是为了**收敛**，不是为了继续发散
- 最多一轮，不要无限开会

---

### Phase 5: 强制收敛

这一步最关键。Advisor Board 的职责不是“展示讨论过程”，而是**给厂长拍板建议**。

必须输出：

1. **共识**：2 人以上同意的部分
2. **分歧**：真正冲突点是什么
3. **倾向判断**：站在厂长当前系统阶段，更该选哪边
4. **最小可行方案**：今天就能推进的 1 个动作 / 1 个小里程碑
5. **不建议做什么**：明确砍掉一个次优路线

## 路由建议（给后续系统封装）

如果未来做更高阶封装，正确分层应是：

- `advisor-board` = 智囊碰撞引擎
- `ceo agent` = 面向厂长的统一入口

顺序：

1. 先把 advisor-board 做成稳定引擎
2. 再考虑包一层 `ceo` 或 `/board` `/decision` 命令

不要倒过来。

---

## Anti-Patterns

- ❌ 只列观点，不收敛
- ❌ 每次都要用户手动点名智囊
- ❌ 把“多 agent”当成“多一些废话”
- ❌ 明明是执行题，硬开董事会
- ❌ 开完会不给明确建议
- ❌ 用名人视角硬套系统问题
- ❌ 把二轮追问用成无限研讨会

---

## 诚实边界

Advisor Board 做不到：

- 替代真实领域专家
- 替代实时市场验证
- 直接证明一个方向一定成功

它能做到：

- 让复杂判断少走弯路
- 用多视角提前发现盲区
- 给出比“单 agent 单结论”更稳的拍板建议
- 让厂长少说一句“再帮我换个角度看看”
