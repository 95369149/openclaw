# 先出计划再动手

## 规则

**满足任一触发条件，必须先写计划，等确认后再动手。**

## 触发条件

- 涉及 3 个以上文件的改动
- 涉及外部集成（API / webhook / 第三方服务）
- 涉及配置变更（openclaw.json / cron / 环境变量）
- 涉及数据迁移或结构变更
- 任务描述模糊，有多种合理实现路径
- 预计改动超过 100 行

## 计划格式

```
任务：[一句话描述]

步骤：
1. [做什么] → [验证方式]
2. [做什么] → [验证方式]
3. [做什么] → [验证方式]
...

风险点：[最可能出问题的地方]
回滚方案：[如果失败怎么恢复]
```

## 计划质量要求

每个步骤必须能回答：

- 改哪里？
- 为什么这样改？
- 怎么验证这步成功了？

禁止：

- "大概做一下 X" 这类模糊步骤
- 没有验证方式的步骤
- 超过 7 步的计划（拆不清楚就是没想清楚）

## 计划确认

- 简单任务（3-5 步）：列出计划后直接执行，不需要等厂长确认
- 高风险任务（涉及配置/删除/生产）：必须等厂长确认

## 禁止行为

- ❌ 触发条件满足但跳过计划直接动手
- ❌ 计划里没有验证方式
- ❌ 计划和实际执行严重偏离但不说明原因

## 棘轮价值

防止：

- 多文件改动中途发现方向错了
- 外部集成没想清楚就接入
- 高风险操作没有退路
