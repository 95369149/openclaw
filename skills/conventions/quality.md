# 质量公约

## 1. 写入 memory 的事实必须带来源

所有写入 memory 的事实都必须附带来源标注，格式固定为：

`[Source: 用户/会议/网页/X推文, YYYY-MM-DD]`

要求：

- 来源类型必须明确，不要省略。
- 日期必须可定位到具体日历日。
- 同一段中存在多个事实且来源不同，分别标注。
- 无法确认来源时，不要写入为事实。

## 2. 提到已有 memory 页面的实体必须建立反向链接

当内容中提到已经存在于 memory 的实体、主题或页面时，必须建立反向链接，保证后续可追溯、可导航。

要求：

- 优先链接到现有 memory 页面，而不是重复创建近似页面。
- 若从 A 页提到 B 页实体，应在合适时补充 B 页到 A 页的反向链接或关联关系。
- 链接应服务于检索与上下文恢复，不做装饰性堆砌。

## 3. 新建 memory 页面前先过必要性检查（notability gate）

不要因为一次提及就新建页面。新建前先判断是否值得长期保留。

通过 notability gate 时，至少满足以下之一：

- 该实体会被反复提及或持续影响后续工作。
- 该主题具有长期参考价值。
- 该事项涉及明确决策、承诺、依赖或风险。
- 不单独建页会明显增加未来检索成本。

不通过时：

- 记录到当天日志或现有相关页面。
- 保持信息可找回，但避免页面泛滥。

## 4. 保留原话，不要改写别人的表述

记录用户、会议参与者、网页作者或发帖人的表达时，优先保留原话，不要擅自美化、压缩立场或改变语气。

要求：

- 引述时尽量使用原始措辞。
- 如需节选，不能改变原意。
- 解释与原话要分开写，避免混成“事实”。
- 带观点、判断、情绪色彩的内容，尤其不能无标记改写。

## 5. 反证优先：高风险结论先写可能错在哪

涉及研究引用、技术方案、实时信息、配置安全、法律/医疗/合规、外部教程时，不能只记结论，必须同时记录“为什么它可能是错的”或“边界在哪”。

要求：

- 先写结论，再补一段 `可能失效/待验证点`，或直接内联说明不确定边界。
- 遇到“看起来很像对，但证据链不完整”的内容，默认按未完成处理。
- 警惕“静默替换”——原问题被偷偷换成更容易回答的问题。
- 若发现静默替换风险，必须原样写出：`原问题`、`被替换后的问题`、`为什么不等价`。

## 6. 实操检查清单

写入前确认：

- 这条内容是事实、观点，还是原话？
- 事实是否带了 `[Source: ..., YYYY-MM-DD]`？
- 是否提到了已有 memory 实体但尚未建立链接？
- 这件事真的值得新建页面吗？
- 我有没有把别人的原话改写成自己的总结？
- 这条记录有没有遗漏关键边界、反证或失效条件？
