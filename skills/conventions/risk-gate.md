# 高风险操作停顿

## 规则

**以下操作必须停下来，展示变更内容，等厂长确认后才能执行。**

## 高风险操作清单

| 操作类型 | 触发条件                                   |
| -------- | ------------------------------------------ |
| 配置变更 | 修改 `openclaw.json` / `openclaw.yaml`     |
| 核心文件 | 修改 `SOUL.md` / `AGENTS.md` / `MEMORY.md` |
| 删除操作 | `rm -rf` / 批量删除 / 清空目录             |
| 定时任务 | `cron add` / 新增 cron job                 |
| 生产部署 | 任何影响线上服务的操作                     |
| 权限变更 | 修改认证/授权/访问控制                     |

## 停顿格式

```
🔴 高风险操作检测

操作类型：[类型]
影响范围：[描述]
具体变更：
  [展示 diff 或操作内容]

风险点：[可能出什么问题]
是否可回滚：[是/否]
回滚命令：[如果可回滚，给出命令]

等待确认后执行。
```

## 配置变更额外要求

改 `openclaw.json` 前必须：

1. `python3 -c "import json; json.load(open(...))"` 验证 JSON 可解析
2. 展示 diff
3. 等厂长确认
4. 改后 `openclaw gateway status` 确认启动成功
5. 同消息给出回滚命令

## 禁止行为

- ❌ 静默执行高风险操作
- ❌ 改完配置不做健康检查
- ❌ 不给回滚命令就改配置
- ❌ 用 `nohup` 拉 gateway

## 棘轮价值

防止：

- 配置改挂导致系统失联
- 删除操作不可逆
- cron 任务悄悄跑起来没人知道
