# 证据化交付

## 规则

**没有验证证据，不算完成。"我觉得好了"不是交付。**

## 验证证据优先级

按场景选最小有效验证：

| 场景          | 最小验证                            |
| ------------- | ----------------------------------- |
| 写文件        | `read` 确认内容落盘                 |
| 改代码        | 运行测试 / lint / typecheck / build |
| 改配置        | `gateway status` 或读日志确认启动   |
| 跑脚本        | 展示实际输出                        |
| 子 agent 任务 | 读取产物文件确认内容                |
| API 调用      | 展示响应状态码 + 关键字段           |
| cron 任务     | 确认 job 已注册 + 下次触发时间      |

## 交付格式

```
交付验收：
- 产物：[文件路径 / 输出位置]
- 验证方式：[用了什么验证]
- 验证结果：[通过 / 失败 + 原因]
- 已知风险：[还有什么没验证到]
```

## 禁止行为

- ❌ 说"应该可以"就结束
- ❌ 说"我已经做了"但没有展示证据
- ❌ 把"没有报错"当成"验证通过"
- ❌ 子 agent 说完成了就信，不读产物文件

## 无法验证时的处理

如果确实无法验证（环境限制 / 权限不足 / 需要外部触发）：

- 明确说明：无法验证的原因
- 说明：需要什么条件才能验证
- 不要假装验证过了

格式：

```
⚠️ 无法完整验证
原因：[为什么]
待验证项：[需要什么条件]
当前状态：[已完成的部分]
```

## 棘轮价值

防止：

- "看起来完成了"但实际没落盘
- 子 agent 假完成
- 错误在系统里悄悄积累
- 停止 ≠ 完成
