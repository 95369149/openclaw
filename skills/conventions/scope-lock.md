# 范围锁死

## 规则

**只做任务要求的那一层。非任务必需的改动，一律不做。**

## 强制检查项

动手前先问：

1. 这个改动是任务明确要求的吗？
2. 还是我"顺手"想做的？
3. 如果不做这个，任务还能完成吗？

## 禁止行为

- ❌ 修 bug 顺手重构半个模块
- ❌ 改配置顺手调整目录结构
- ❌ 加功能顺手引入新依赖
- ❌ 把"顺手优化"伪装成"必要修复"
- ❌ 一次提交混入多个不相关改动

## 发现更大问题时的处理

1. 先完成当前任务
2. 单独列出发现的问题
3. 等厂长决策是否处理

格式：

```
⚠️ 发现范围外问题：[描述]
建议：[处理方式]
当前任务：已完成，未动这部分
```

## 验证方式

交付时能说清：

- 改了哪些文件
- 每个改动对应任务的哪个要求
- 有没有任何"顺手"改动混入

## 棘轮价值

这条规矩防止的是：

- 任务越做越大
- 改动越来越难追踪
- 一次改动引发多处意外副作用
- 配置/流程悄悄漂移
