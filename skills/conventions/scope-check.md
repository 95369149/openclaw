# 范围越界检查

## 规则

**交付时必须列出所有改动文件，并对照任务要求标注是否在范围内。**

## 强制要求

交付时必须包含：

```
changed_files:
  - path: <文件路径>
    in_scope: true/false
    reason: <为什么改这个文件>
```

## 越界改动处理

- `in_scope: false` 的改动 → 不自动合并
- 必须单独列出，等厂长确认
- 格式：
  ```
  ⚠️ 范围外改动：[文件路径]
  原因：[为什么动了它]
  建议：[合并 / 回滚 / 单独处理]
  ```

## 禁止行为

- ❌ 不列改动文件列表直接交付
- ❌ 把范围外改动混入主交付不标注
- ❌ 用"顺手优化"掩盖越界改动

## 验证方式

apply_manifest.py 检查 `changed_files` 字段：

- 所有文件都有 `in_scope` 标注 → 通过
- 有 `in_scope: false` → 提示厂长确认
- 字段缺失 → 打回重做

## 棘轮价值

防止：

- 任务越做越大
- 改动越来越难追踪
- 一次改动引发多处意外副作用
